# Chapter 6. 동기화 도구(Synchronization Tools)

## 6.1 배경

프로세스와 스레드는 동시에 실행되거나 여러 CPU 코어에서 병렬로 실행될 수 있다. 한 프로세스의 명령어 실행 중간에 다른 프로세스가 실행될 수 있고, 여러 프로세스가 공유 데이터를 동시에 읽고 수정할 수도 있다.

### 경쟁 조건(race condition)

- 유한 버퍼의 생산자-소비자 문제에서 `count++`와 `count--`가 동시에 실행되는 경우를 생각할 수 있다. 각각의 연산은 기계어 수준에서 다음처럼 여러 단계로 나뉜다.

```text
register = count
register = register + 1   // 또는 - 1
count = register
```

- 두 연산의 명령어가 임의로 교차 실행되면 최종 `count`가 실제 상태와 다른 값이 될 수 있다. 이처럼 여러 프로세스가 같은 데이터를 동시에 조작하고, 결과가 실행 순서에 따라 달라지는 상황을 경쟁 조건이라고 한다.
- 따라서 공유 데이터를 다루는 코드에는 실행 순서를 제어하는 동기화가 필요하다. 멀티코어 시스템과 다중 스레드 애플리케이션이 일반화되면서 이 문제의 중요성이 더 커졌다.

## 6.2 임계구역 문제

- 임계구역(critical section)은 공유 데이터를 읽거나 수정하는 코드 영역이다. 한 프로세스가 임계구역을 실행하는 동안 다른 프로세스가 자신의 임계구역을 실행하지 못하게 하는 프로토콜을 설계하는 것이 임계구역 문제다.

\* 일반적인 프로세스 구조는 다음과 같다.

```text
while (true) {
    entry section       // 임계구역 진입 요청
    critical section    // 공유 데이터 접근
    exit section        // 임계구역에서 나옴
    remainder section   // 나머지 작업
}
```

- 올바른 해결 방법은 다음 세 조건을 만족해야 한다.

1. **상호 배제(mutual exclusion)**: 한 프로세스가 임계구역에 있으면 다른 프로세스는 임계구역에 들어갈 수 없다.
2. **진행(progress)**: 임계구역이 비어 있고 진입하려는 프로세스가 있으면, 선택이 무기한 미뤄지지 않아야 한다.
3. **한정 대기(bounded waiting)**: 어떤 프로세스가 진입을 요청한 뒤 허가받기 전까지 다른 프로세스가 임계구역에 들어갈 수 있는 횟수에 상한이 있어야 한다.

\* 한정 대기는 특정한 프로세스만 계속 임계 구역에 접근해서, 사실상 독점하는 현상을 방지하기 위한 개념이다.

- 운영체제 커널에서도 열린 파일 목록, 프로세스 목록, 메모리 할당 정보, 다음 PID 등의 자료구조가 동시에 갱신되면 경쟁 조건이 발생할 수 있다.
- 단일 코어에서는 공유 변수 수정 중 인터럽트를 막는 방법을 생각할 수 있지만, 멀티프로세서에서는 모든 코어의 인터럽트를 제어해야 하므로 비효율적이다. 비선점형 커널은 커널 모드에서 실행 중인 프로세스를 선점하지 않아 경쟁 조건이 상대적으로 적지만, 선점형 커널은 응답성이 좋고 실시간 시스템에 적합한 대신 커널 자료구조를 세심하게 동기화해야 한다.

## 6.3 Peterson의 해결 방법

- Peterson의 해결 방법은 두 프로세스가 임계구역 문제를 해결하도록 만든 고전적인 소프트웨어 알고리즘이다. 두 프로세스 `P0`, `P1`이 다음 공유 변수를 사용한다.

```text
int turn;
boolean flag[2];
```

- `flag[i] == true`: 프로세스 `Pi`가 임계구역에 들어가기를 원한다.
- `turn`: 두 프로세스가 동시에 원할 때 먼저 양보할 프로세스를 나타낸다.

\* 핵심 구조는 다음과 같다.

```text
flag[i] = true;
turn = j;
while (flag[j] && turn == j)
    ;

// critical section

flag[i] = false;
```

- 어떤 프로세스가 접근을 원하는 상황에서 해당 프로세스가 (다른 경합하는 프로세스보다) 우선 순위가 있는 경우 critical section 접근 권한을 얻는 방식 같다.

- 두 프로세스가 동시에 진입을 시도해도 `turn`은 한 값만 가질 수 있으므로 상호 배제가 성립한다. 상대 프로세스가 진입을 원하지 않으면 즉시 진행할 수 있고, 상대가 먼저 들어가더라도 한 번 나간 뒤에는 진입할 수 있으므로 진행과 한정 대기도 만족한다.
- 다만 현대 프로세서와 컴파일러는 성능을 위해 서로 의존하지 않는 메모리 읽기·쓰기의 순서를 바꿀 수 있다. 이 명령어 재배치 때문에 Peterson 알고리즘이 현대 하드웨어에서 항상 올바르게 동작한다고 보장할 수 없다. 공유 메모리 동기화에는 하드웨어가 제공하는 메모리 순서 보장과 원자 명령어가 필요하다.

## 6.4 동기화를 위한 하드웨어 지원

- 현대 시스템은 소프트웨어 알고리즘의 한계를 보완하기 위해 원자적으로 실행되는 하드웨어 기능을 제공한다. 이러한 기능은 직접 동기화 도구로 사용하거나, 뮤텍스·세마포어 같은 고수준 도구의 기반으로 사용할 수 있다.

### 6.4.1 메모리 장벽

- 메모리 모델은 한 프로세서의 메모리 변경이 다른 프로세서에 보이는 방식이다.

- **강한 순서(strongly ordered)**: 메모리 변경이 다른 프로세서에 즉시 보인다.
- **약한 순서(weakly ordered)**: 변경 사항이 다른 프로세서에 즉시 보인다는 보장이 없다.

- 메모리 장벽(memory barrier 또는 memory fence)은 장벽 이전의 모든 메모리 읽기·쓰기가 완료되고 다른 프로세서에 보인 뒤에 다음 메모리 연산이 수행되도록 한다. 이를 통해 명령어 재배치로 인해 플래그는 먼저 보이지만 실제 데이터는 아직 갱신되지 않은 문제를 방지할 수 있다.
- 메모리 장벽은 매우 낮은 수준의 기능이므로 일반 애플리케이션보다는 커널 개발이나 특수한 동기화 코드에서 주로 사용된다.

### 6.4.2 하드웨어 명령어

#### Test-and-set

`test_and_set()`은 대상 값을 읽고 `true`로 설정하는 작업을 하나의 원자적 연산으로 수행한다.

```text
while (test_and_set(&lock))
    ;                   // 바쁜 대기

// critical section

lock = false;
```

\* 원자적 연산: 각자의 객체 시점에서 연산하는 작업(프로세스에서 연산을 한 경우, 메모리에서 원본 값을 가져오고 결과를 다시 쓰는 일련의 과정에 다른 객체가 접근하지 못하게 막는 기능이다.)
- 여러 코어가 동시에 실행해도 원자적 연산은 순차적으로 처리되므로 한 프로세스만 락을 획득한다. 그러나 이 방식만으로는 한 프로세스가 무한정 기다리지 않는다는 한정 대기를 보장하지 않는다.

#### Compare-and-swap(CAS)

- CAS는 현재 값이 예상 값과 같을 때만 새 값으로 바꾸고, 교체 전의 원래 값을 반환하는 원자적 명령어다.

```text
while (compare_and_swap(&lock, 0, 1) != 0)
    ;                   // 바쁜 대기

// critical section

lock = 0;
```

- 락이 `0`일 때 첫 프로세스가 `1`로 바꾸어 진입하고, 다른 프로세스는 락이 다시 `0`이 될 때까지 기다린다. 기본 형태는 상호 배제를 만족하지만 한정 대기는 보장하지 않는다. 대기 배열을 두고 락 해제 시 다음 대기 프로세스를 순환적으로 선택하면 상호 배제·진행·한정 대기를 모두 만족시킬 수 있다.

- Intel x86에서는 `cmpxchg` 명령과 `lock` 접두사를 사용해 CAS의 원자성을 구현할 수 있다.

### 6.4.3 원자 변수

- 원자 변수는 정수나 boolean 같은 기본 자료형에 대해 읽기·수정 작업을 끊김 없이 수행하도록 제공되는 자료형이다. 일반적으로 CAS를 이용해 카운터 증가나 순번 생성기 같은 단일 갱신을 안전하게 처리한다.
- 그러나 원자 변수 하나만으로 복합적인 경쟁 조건이 모두 해결되지는 않는다. 예를 들어 버퍼의 `count` 갱신은 원자적이어도, 여러 소비자(사용자)가 같은 `count` 값을 보고 동시에 버퍼에서 데이터를 꺼내는 문제는 남을 수 있다. 따라서 원자 변수는 단일 공유 값의 갱신에 적합하고, 더 복잡한 조건에는 별도의 동기화 도구가 필요하다.

## 6.5 뮤텍스 락

- 뮤텍스(mutex, mutual exclusion)는 임계구역을 보호하는 가장 단순한 고수준 동기화 도구다. 프로세스는 임계구역에 들어가기 전에 `acquire()`를 호출하고, 나올 때 `release()`를 호출한다.

```text
while (true) {
    acquire(lock)
    // critical section
    release(lock)
    // remainder section
}
```

- 락이 사용 가능하면 획득하고, 이미 다른 프로세스가 보유 중이면 대기한다. `acquire()`와 `release()` 자체는 원자적이어야 하며, CAS 같은 하드웨어 명령어로 구현할 수 있다.
- 락을 기다리는 방식에 따라 다음과 같은 특성이 있다.

- **스핀락**: 락을 얻을 때까지 반복해서 확인하는 바쁜 대기 방식이다. 컨텍스트 전환이 필요 없으므로 멀티코어에서 락 보유 시간이 매우 짧을 때 유리하다.
- **블로킹 방식**: 기다리는 프로세스를 잠들게 하여 CPU를 다른 작업에 사용한다. 긴 대기에는 적합하지만 컨텍스트 전환 비용이 발생한다.

- 락 경쟁이 심할수록 전체 병행 프로그램의 성능이 떨어진다. 특히 단일 코어에서 긴 시간 스핀락을 사용하면 CPU 시간을 낭비할 수 있다.

## 6.6 세마포어

세마포어 `S`는 초기화 이후 원자적 `wait()`와 `signal()` 연산으로만 접근하는 정수 변수다.

```text
wait(S) {
    while (S <= 0)
        ;
    S--;
}

signal(S) {
    S++;
}
```

- `wait()`는 자원을 요청하고 세마포어 값을 감소시키며, `signal()`은 자원을 반납하고 값을 증가시킨다. `wait()`에서 값 검사와 감소는 중간에 끊기지 않는 하나의 원자적 작업이어야 한다.

### 6.6.1 세마포어 사용

- **이진 세마포어**: 값이 0 또는 1이며 뮤텍스와 비슷하게 상호 배제에 사용된다.
- **카운팅 세마포어**: 값에 더 넓은 범위를 허용하며, 여러 개의 동일한 자원을 관리하는 데 사용된다. 초기값은 사용 가능한 자원 개수다.

\* 카운팅 세마포어는 critical section에 동시에 접근 가능한 프로세스 수를 n개까지 제한할 때 사용한다.
\* 세마포어의 경우 다른 프로세스가 signal() 콜을 호출해서 배타적 권한을 해제할 수 있다. 권한을 보유한 프로세스만이 스스로 해제할 수 있는 mutex lock과의 차이점이다.

- 세마포어는 실행 순서 제어에도 사용할 수 있다. `P1`의 문장 `S1`이 끝난 뒤에만 `P2`의 문장 `S2`가 실행되어야 한다면, `synch`를 0으로 초기화하고 다음처럼 작성한다.

```text
P1: S1; signal(synch);
P2: wait(synch); S2;
```

`P2`는 `P1`이 `signal()`을 호출하기 전까지 진행할 수 없다.

### 6.6.2 세마포어 구현

- 바쁜 대기를 줄이기 위해 세마포어가 0 이하일 때 기다리는 프로세스를 대기 큐에 넣고 잠들게 할 수 있다.

```text
semaphore {
    int value;
    process_list list;
}
```

- `wait()`: 값을 감소시키고, 값이 음수가 되면 현재 프로세스를 큐에 넣어 `sleep()`한다.
- `signal()`: 값을 증가시키고, 대기 프로세스가 있으면 하나를 꺼내 `wakeup()`한다.

- 이 구현에서는 세마포어 값이 음수가 될 수 있으며, 그 절댓값은 대기 중인 프로세스 수를 나타낸다. 대기 큐를 FIFO로 구성하면 한정 대기 성질을 구현하기 쉽지만, 올바른 세마포어 사용 자체가 특정 큐 방식에 의존하는 것은 아니다.

- 세마포어 연산도 임계구역 문제이므로 원자적으로 구현해야 한다. 단일 프로세서에서는 인터럽트 비활성화가 가능하지만, 멀티코어에서는 모든 코어의 인터럽트를 막아야 하므로 CAS나 스핀락 같은 방법이 필요하다. 즉, 바쁜 대기를 완전히 없앤 것이 아니라 짧은 세마포어 내부 임계구역으로 제한한 것이다.

## 핵심 정리

1. 공유 데이터에 대한 동시 접근은 실행 순서에 따라 결과가 달라지는 경쟁 조건을 만든다.
2. 임계구역 해결 방법은 상호 배제, 진행, 한정 대기를 만족해야 한다.
3. Peterson 알고리즘은 개념적으로 중요하지만 현대 하드웨어의 명령어 재배치 때문에 단독 사용이 안전하지 않다.
4. 메모리 장벽과 원자적 하드웨어 명령어는 저수준 동기화의 기반이다.
5. 원자 변수는 단일 값의 갱신에는 유용하지만 복합적인 동기화 문제 전체를 해결하지는 못한다.
6. 뮤텍스는 상호 배제에 적합하고, 세마포어는 상호 배제와 자원 개수·실행 순서 제어까지 지원한다.
7. 동기화 도구는 강력하지만 사용 순서를 잘못 설계하면 교착이나 타이밍 오류가 발생할 수 있다.
