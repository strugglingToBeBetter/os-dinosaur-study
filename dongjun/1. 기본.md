# 1. 서론
## 1.1. OS 기본
### 1. OS 개요
- OS(Operating System: 운영체제)란 **컴퓨터의 하드웨어를 제어하는 소프트웨어**다.
- OS는 컴퓨터(HW)와 사용자 간의 상호작용을 연결하는 매개 시스템 역할을 한다.

### 2. OS의 역할
- OS는 시스템 자원을 사용자나 앱에 할당하는 역할을 한다.
- OS는 시스템 커널에 접근해서 시스템 자원(메모리, 디스크, CPU 등)을 관리한다.
- 모바일 디바이스에서는 OS는 미들웨어를 포함하기도 한다(iOS, Android)
- OS는 사용자가 시스템을 편리하게 사용할 수 있도록 도와주는 역할도 한다. 
(*미들웨어: 운영체제와 앱 사이, 혹은 서로 다른 분산된 시스템(또는 소프트웨어) 사이에서 연결 및 데이터 교환을 돕는 '중간 소프트웨어'로, 소프트웨어 간 원활한 상호작용을 위해 사용된다. 예를 들면 DBMS)
- 사용자 입장에서는 컴퓨터/OS와 다양한 방식으로 상호작용한다(마우스/키보드 입력, 터치스크린, 음성인식 등).
- 임베디드 디바이스의 경우 사용자의 개입 없어도 (알아서) 프로그램이 작동할 수 있도록 디자인된 경우가 많다.

### 3. OS 지식의 필요성
- 모든 응용 프로그램들은 OS를 기반으로 생성/동작하므로, OS에 대해 알아야 프로그램을 적절하고, 효율적이고, 효과적이고, 보안적으로 취약하지 않게 만들 수 있다.
- 또한 프로그램을 변경하거나(write) 사용할 때에도 유용하다.

## 1.2. 컴퓨터-시스템 구성
### 1. 개요
- 현대의 일반적인 컴퓨터 시스템은 CPU와 디바이스 컨트롤러가 버스(bus) 형태로 연결되어 구성 요소(component)와 공유 메모리의 접근을 허용하는 방식으로 구성되어 있다.
- 운영체제는 각 디바이스 컨트롤러마다 디바이스 드라이버를 가지고 있어서, 디바이스 드라이버를 통해 장치를 인식하고 운영체제의 잔여 영역에 장치에 대한 균일한 인터페이스를 제공한다.
- 각 디바이스 컨트롤러는 특정 타입의 디바이스를 담당한다.(예: 디스크 드라이브, 오디오 장치, 그래픽 표시 장치 등)
- 컨트롤러에 따라서 여러 개의 디바이스가 연결될 수 있다(예: USB 컨트롤러에 여러 대의 디바이스 연결하기).
- 운영체제는 '디바이스 드라이버'를 통해 디바이스 컨트롤러를 식별하고 디바이스가 시스템에서 공유된 메모리에 접근할 수 있도록 한다.

### 2. 인터럽트
- 인터럽트는 시스템이 처리 중인 작업을 일시적으로 중단하게 하는 기능이다.
- 디바이스(컨트롤러)가 드라이버(디바이스 드라이버)에게 디바이스의 상태(작업 완료, 처리 중 등)를 알려주는 용도로 사용한다.
- CPU가 인터럽트 신호를 받으면 즉시 고정된 위치(*인터럽트 프로세서 주소를 뜻하는 것 같다)로 작업을 전환한다.
- 인터럽트에 해당하는 작업이 완료되면, CPU는 인터럽트 신호를 받기 전에 수행하던 작업을 재개한다.
- 인터럽트는 수시로 발생하므로, 빠르게 처리(handle)되어야 한다.
- 인터럽트 아키텍처는 인터럽트에 대한 상태 정보를 저장하고 있다.

### 3. 인터럽트의 실행
- 인터럽트의 기본 매커니즘은...
```
1. CPU가 인터럽트-요청 라인(interrupt-request line)에서 컨트롤러의 신호를 감지한다.
2. CPU는 인터럽트 번호를 읽고 인터럽트 핸들러 루틴으로 건너뛴다(jump).
3. 인덱스와 연관되어 있는 메모리 주소에서 인터럽트 작업을 시작한다.
4. 인터럽트 핸들러는 (인터럽트 동작 중) 변경되는 상태를 저장하고, 인터럽트 발생 원인을 설정하고, 인터럽트 이전 상태로 돌아가기 위한 필수 프로세스 실행을 담당한다.
5. 인터럽트 핸들러가 'return_from_interrupt'를 실행하여, CPU를 인터럽트 이전에 다른 작업을 실행하던 상태로 되돌린다.
```
의 방식으로 진행된다.
- 인터럽트의 기본 매커니즘은 CPU가 비동기적인 이벤트에 대응할 수 있도록 설계되었지만, 현대의 OS는 인터럽트 처리 기능이 더 복잡해졌다.
- 현대의 인터럽트는...
```
1. 주요 작업 중에는 인터럽트 동작 처리를 뒤로 미루거나
2. 디바이스에 적절한 인터럽트를 보내기 위한 적절한 방법이 필요하거나
3. OS가 인터럽트 간 우선순위를 판단하여 반응 순서를 조절할 수 있는 다중 레벨(multilevel) 인터럽트가 필요하다.
```
*인터럽트 핸들러에는 인터럽트 처리 과정에서 발생하는 모든 정보(인터럽트 발생 이유, 상태 변화, 실행 동작 등)들이 저장된다.

### 4. 인터럽트 작동 예시 및 요약
1) CPU가 디바이스의 입출력 초기화를 명령
2) 디바이스 입출력 초기화
3) 입력 준비 완료, 출력 완료, 오류 발생 등의 인터럽트 신호를 생성하여 CPU에 전달
4) CPU는 인터럽트 신호를 수신하여, 인터럽트 핸들러에 통제 권한 이전
5) 인터럽트 핸들러가 데이터를 처리하고, CPU를 인터럽트 이전 상태로 되돌림
6) CPU는 인터럽트 이전에 수행하던 작업을 재개함

### 5. 인터럽트 요청 라인
- CPU는 NonMaskable Interrupt와 Maskable Interrupt 라인을 갖고 있다.
- Maskable Interrupt 라인은 방해받으면 안 되는 중요한 동작이 있는 경우 꺼질(turned off) 수 있다.
- Maskable Interrupt는 디바이스 컨트롤러가 서비스를 요청할 때 사용된다.
```
Maskable Interrupt와 NonMaskable Interrupt의 용도
대부분의 인터럽트(키보드 입력, CPU 작업 일시 정지, 문서 작성, 게임 플레이)는 '매우 중요한 작업'으로 간주되어, Maskable Interrupt로 구현된다.
NonMaskable Interrupt는 메모리 하드웨어 오류, 와치독 타임아웃, 시스템 장애 보고, 디버깅 환경 등 치명적 오류나 긴급한 상황에서 주로 사용한다.
Maskable Interrupt는 치명적인 오류가 발생하는 등의 특수한 상황에서 인터럽트 처리가 지연되거나 사실상 처리되지 못할 수 있다.
```

### 6. 다중 인터럽트 처리
- CPU는 다양한 디바이스(와 이에 비례하는 인터럽트 핸들러)를 보유하고 있으므로, 인터럽트 핸들러를 매칭하는 시간/자원을 최적화할 필요가 있다.
ㄴ 인터럽트 벡터 주소보다 컴퓨터가 제공 가능한 인터럽트 처리기가 더 많으므로, 고유 값을 할당할 수 있는 방법이 필요한 것도 있다.
- 인터럽트 체인(chaining): 인터럽트 벡터 안의 각 요소가 인터럽트 헨들러 리스트의 헤드를 가리킨다. 인터럽트 발생 시 요청을 처리할 수 있는 인터럽트가 발견될 때까지 리스트의 핸들러가 하나씩 호출된다.
- 인터럽트 체인은 인터럽트 우선 순위를 판단할 때도 사용한다.
- 인터럽트는 반응에 민감한 프로세스에서 중요하게(heavily) 사용되므로, 효율적인 인터럽트 처리는 시스템 성능 향상에 필수적이다.

### 7. 저장소 구성
- CPU는 메모리에만 명령을 적재(load)할 수 있으므로, 모든 프로그램은 실행 전에 반드시 메모리에 적재되어야 한다.
- 프로그램이 실행되기 전 적재되는 메모리는 메인 메모리(RAM)이라고 한다.
- RAM은 휘발성이 있어서 컴퓨터 전원이 꺼지면 저장된 정보를 상실한다.
- RAM의 단점을 보완하기 위해 컴퓨터는 전자적으로만 삭제 가능한 형태로 프로그램된 읽기 전용 메모리(EEPROM)와 기타 형태의 펌웨어를 사용한다.
  *이 때 사용하는 '기타 펌웨어'는 비휘발적이고 자주 write되지 않은 저장소이다.
- EEPROM은 자주 변경될 수 없고, 쓰기 속도도 느리다. 그래서 자주 변경되지 않는 정보(고유 정보 등)를 저장할 때 사용하기도 한다.

### 8. 메모리 구성
- 모든 형태의 메모리는 바이트 배열을 제공한다.
- 각 바이트에는 고유한 주소가 있다.
- 적재(load)는 메인 메모리의 바이트나 단어를 CPU 내 레지스터에 옮기는 작업이다.
- 저장(save)은 레지스터의 내용물을 메인 메모리로 옮기는 작업이다.
- CPU는 프로그램 카운터에 저장된 위치부터 실행하기 위해 메인 메모리에서 자동으로 명령을 적재한다.

### 9. 폰 노이만 사이클(vonNeumann architecture)
- 폰 노이만 사이클에서는...
```
1. 명령을 메모리에서 페치(fetch)하고, 페치한 명령을 명령 레지스터에 저장(store)한다.
2. 명령이 해독되면 메모리에서 피연산자가 페치되어 내부 레지스터에 저장될 수 있다.
3. 피연산자에 대한 명령이 실행되면, 실행 결과는 메모리에 다시 저장될 수 있다.
```
- 우리는 실행 중인 프로그램이 생성하는 메모리 주소의 시퀀스에만 관심이 있으므로, 메모리 주소가 생성되는 과정은 무시할 수 있다.
- 이상적으로 우리는 프로그램 데이터가 메인 메모리에 영구적으로 존재해 있기를 원하지만, 메인 메모리는 용량이 작고 휘발적이어서 현실적으로 불가능하다.
- 그러므로, 모든 컴퓨터 시스템은 메인 메모리의 확장 역할로서 보조 기억 장치(secondary storage)를 제공한다.

### 7.  보조 기억 장치
- 보조 기억 장치는 많은 양의 데이터를 영구적으로 저장할 수 있어야 한다.
- 주로 쓰이는 보조 기억 장치는 HDD(*요즘은 대신 SSD를 많이 씀), 비휘발성 메모리(NonVolatile Memory) 장치가 있다.
- 보조 기억 장치는 메인 메모리보다 처리 속도가 느리므로, 적절한 관리는 컴퓨터 시스템의 핵심 요소이다.

### 8.  기타 저장장치 구조
- 넓은 의미에서 (레지스터, 메인 메모리, 보조 기억 장치로 구성된) 저장소 구조는 수많은 가능한 저장소 시스템 디자인 중의 일부에 불과하다.
- 캐시 메모리, CD ROM(*요즘으로 치면 USB 메모리), 마그네틱 테이프 등도 저장 장치의 일종이다. 이것들을 **삼차 저장소(tertiary storage)**로 부른다.
- 각 저장소 시스템은 데이터를 오랫동안 보관할 수 있는(나중에 데이터를 불러와도 검색할 수 있도록) 기능을 제공한다.
- 삼차 저장소 시스템은 구성이 다양하지만, 주요 차이점은 처리 속도, 크기, 휘발성 여부이다.
- 일반적으로 속도와 크기는 반비례하는 관계이며, 작고 빠른 메모리는 CPU에 가깝다.

### 9.  저장 장치 계층
- 저장 장치 계층은 *레지스터-캐시-메인 메모리-NV 메모리-HDD-광학 디스크-마그네틱 테이프* 순서로 형성되어 있다.(*뒤로 갈 수록 저장 공간이 커지는 대신 처리 속도가 느려짐)
- 상위 4개 계층(*레지스터, 캐시, 메인 메모리, NV 메모리*)은 반도체로 구성되어 있다.
- NVM의 경우 일반적으로 하드 디스크보다 접근 속도가 빠르다. NVM은 주로 플래시 메모리를 사용하는데, 모바일/임베디드 영역에서 많이 쓰인다. 최근에는 컴퓨터나 서버의 장기 데이터 저장에도 사용한다.
```
기억 장치 구성은 경제적으로 최적화된 형태여야 한다*(*용도와 필요에 맞게 사용). 두 구성요소(휘발성-비휘발성 저장소) 간 성능 차이가 큰 경우 캐시를 설치해 이를 보완할 수 있다.
```
## 1.3. 입출력 구조
- 운영체제 코드의 주요 부분은 입출력(I/O) 제어에 할애되어 있다.
- 입출력 제어는 시스템의 신뢰성과 성능에 주요한 영향을 주고, 장치의 속성이 다양하기 때문에 제대로 관리하는 것이 중요하다.
- 인터럽트 구동 I/O 형태는 소량의 데이터 제어에는 유용하지만, NVS I/O처럼 대량의 데이터를 이동할 때는 시스템에 높은 오버헤드를 유발할 수 있다.
```
오버헤드: 
어떤 작업을 처리하기 위해 드는 자원(시간, 메모리, 제어 신호 등)
```

### 1. NVS: 비휘발성 저장소(Non-Volatile Storage)
- 위 문제를 해결하기 위해, 직접 메모리 접근(Direct Memory Access: DAM)을 사용한다.
- 장치에 대한 버퍼 및 포인터, 입출력 카운트를 세팅한 후, 장치 제어기는 CPU의 개입 없이 메모리로부터 자신의 버퍼 장치 또는 버퍼로부터 메모리로 데이터 블록 전체를 전송한다.
- 블록 당 하나의 인터럽트만 생성되며, 디바이스 드라이버에게 '동작 완료' 이벤트를 알린다.
- 디바이스 컨트롤러가 작업들을 수행하는 동안, CPU는 다른 작업을 할 수 있다.

### 2. 멀티프로세서 시스템
- 멀티프로세서 시스템은 PC/모바일 구분없이 주로 채택되는 시스템이다.
- 멀티프로세서 시스템은 2개 이상의 프로세서를 보유하며, 각 프로세서는 한 개의(싱글코어) CPU를 갖고 있다.
- 프로세서는 컴퓨터 버스(Bus)를 공유하며, 클럭(clock), 메모리, 개별 디바이스를 공유하기도 한다.
- 멀티프로세서 시스템의 주 이점은 처리량 향상이다.
- 여러 프로세서가 협업하는 경우 시스템의 모든 영역이 원활히 동작하도록 조율하는 과정에서 일정 오버헤드가 발생하는데, 이 오버헤드는 추가 프로세서로 얻을 수 있는 효용을 낮춘다. 
(*한계효용이 낮아지니까 프로세서를 무작정 많이 붙인다고 좋은 건 아니라는 뜻임)
```
오버헤드가 발생하는 이유
여러 CPU가 하나의 버스에 연결되어 있는 경우, 작업 처리 과정에서 병목 현상이 발생하기 때문
```
- 가장 일반적인 멀티프로세서 시스템은 대칭형 멀티프로세싱(SMP)이다. 
- 멀티프로세서 시스템의 모든 프로세서는 시스템 버스를 통해 물리 메모리를 공유한다.
- 대칭형 멀티프로세싱은 시스템 자원을 프로세서 간 동적으로 공유할 수 있으며, 프로세서 간 작업 부하 분산을 낮출 수 있다는 장점이 있다.
- 멀티프로세서의 정의는 진화해 왔고, 최근에는 멀티코어 시스템 개념도 포함한다.
- 칩 내에서의 통신은 칩 간 통신보다 빠르므로, 멀티코어 시스템은 싱글코어에 여러 개의 칩이 붙어 있는 것보다 효율적이다.
- 멀티코어 시스템은 전력 소모도 적으므로, 모바일 디바이스(노트북, 스마트폰 등)에서 중요한 개념이다.
- 여러 칩으로 이루어진 멀티프로세서의 경우 각 프로세서마다 고유의 레지스터를 갖고 있지만, 멀티코어 시스템의 경우 여러 칩들이 하나의 레지스터를 공유한다.

### 3. 불균일 기억장치 접근(NUMA)
*NUMA(Non-Uniformed Memory Access): 각 CPU가 메모리의 일부를 자신의 로컬 메모리로 가지게 해서, 메모리 접근 속도를 향상시키는 방법
- NUMA는 멀티프로세서 시스템에서 발생하는 병목 현상을 완화하기 위해 등장한 개념이다.
- NUMA 시스템은 메모리에 더 빠르게 접근할 수 있고, 한 번에 더 많은 프로세서들을 수용할 수 있도록 확장하기에 용이하다.
- NUMA 시스템의 잠재적인 약점으로 CPU가 상호 연결된 시스템의 원격 메모리에 접근할 때 성능 저하가 발생할 수 있다는 점이 있다.

예) CPU0은 CPU3이 점유한 로컬 메모리에 직접 접근할 수 없다.
- 운영체제는 NUMA의 단점을 세심한 CPU 스케쥴링과 메모리 관리로 최소화(보완)한다.
- NUMA 시스템은 서버나 고성능 컴퓨팅 시스템에 주로 적용되고 있다.

### 4. 블레이드 서버(blade server)
- 블레이드 서버는 여러 개의 프로세서 보드, 여러 개의 입출력 보드와 네트워크 보드가 동일한 차대 내에 위치한 시스템이다.
- 블레이드 서버가 멀티프로세서 시스템과 차별화되는 점은 각 블레이드 프로세서 보드가 독립적으로 켜지고, 고유한 운영체제에서 동작한다는 것이다.
- 일부 블레이드 서버는 멀티프로세서처럼 컴퓨터 간 유형 구분을 모호하게 만들기도 한다.
- 본질적으로 블레이드 서버는 여러 독립적인 멀티프로세서 시스템들로 구성되어 있다.

### 5. 클러스터화된 시스템(clustered systems)
- 클러스터화된 시스템은 여러 CPU들을 함께 모은다.
- 클러스터화된 시스템이 멀티프로세서 시스템과 다른 점은, 클러스터화된 시스템은 여러 개의 독립적인 시스템들로 구성되어 있다는 점이다.
- 클러스터화된 시스템의 각 노드는 느슨하게 결합되어 있다.
*'clustered'라는 개념은 명확하게 정의할 수 있는 것은 아니다.
- 클러스터링(clustering)은 주로 고가용 서비스에서 사용된다.
- 고가용성 시스템은 클러스터 내의 다른 시스템이 실패(fail)해도 지속/제공될 수 있어야 한다.(*높은 신뢰성을 요구할 때 사용)
- 클러스터 소프트웨어 계층은 클러스터 노드 위에서 동작한다.
- 각 노드는 네트워크 위에서 다른 시스템들을 감시할 수 있다.
- 감시 대상 머신(machine)이 실패하는 경우, 감시 중인 머신은 저장 장치의 소유권을 갖고 실패한 머신에서 구동하던 응용 프로그램을 재시작한다.(*daemon 스레드랑 비슷한 개념인 듯)
- 응용 프로그램 사용자와 클라이언트에게는 일시적인 서비스 인터럽트가 표시된다.(*복구 중... 등)
- 고가용성은 많은 응용 프로그램에서 중요한 요소인 신뢰성을 향상시킨다.
- 우아한 저하(graceful degradation): 하드웨어가 지원 가능한 한도에서 서비스를 제공할 수 있는 능력
- 내결함성(fault tolerant): 우아한 저하에서 발전한 개념으로, 일부 컴포넌트에 문제가 생겨도(fail 해도) 전체 서비스를 제공할 수 있는 속성
- 내결함성은 실패가 감지되고, 진단되고, 가능하다면 수정될 수 있는 메커니즘을 요구한다.
- 클러스터링은 대칭적 혹은 비대칭적으로 구성될 수 있다.
- 비대칭적 클러스터링에서 다른 머신이 응용 프로그램을 실행 중일 때 한 머신은 핫스탠바이 모드(hot-standby mode) 상태를 유지한다.
- 핫스탠바이 호스트 머신은 활성화된 서버를 감시하는 작업만 수행한다. 만약 감시 대상 서버에 문제가 생기면, 핫스탠바이 호스트가 활성 서버가 된다.
- 대칭적 클러스터링에서는 두 개 이상의 호스트가 응용 프로그램을 실행하고 각자를 모니터링한다.
- 대칭적 클러스터링 구조는 가용 가능한 모든 하드웨어를 사용하므로 보다 효율적이지만, 실행 가능한 응용 프로그램이 적어도 한 개 이상 있어야 한다.
- 클러스터는 네트워크로 연결된 여러 컴퓨터 시스템으로 구성되어 있어서, 클러스터는 고사양 컴퓨팅 환경을 제공할 때에도 사용될 수 있다.
- 응용 프로그램은 클러스터를 사용하도록 구체적으로 작성되어(written) 있다.
- 하지만 이는 병렬화(parallelization)에 연루시켜서, 한 프로그램이 컴퓨터(또는 클러스터의 컴퓨터들 내)의 여러 코어 내부에서 독립적으로 실행되도록 나눈다.
- 전통적으로 이러한 응용 프로그램은 클러스터의 각 컴퓨팅 노드가 문제의 일부를 해결해서, 각 노드들의 결과를 취합한 다음 최종 결과물로 반환한다.
- 병렬화된 클러스터는 다수의 호스트들이 공유된 저장소에서 동일한 데이터에 접근할 수 있도록 한다.
- 대부분의 운영 체제들이 다수의 호스트들이 동시에 데이터에 접근하도록 허용하는 것에 취약하다 보니, 병렬화된 클러스터는 특별한 버전의 소프트웨어와 특정 릴리즈 버전의 응용 프로그램을 요구한다.

예) 클러스터 내의 컴퓨터들이 동일 DB에 접근하는 경우, 컴퓨터들의 DB 시스템 버전이 동일해야 한다.

예) Oracle의 MySQL을 사용할 때는 DB와 이에 접근하는 각 컴퓨터의 SW 버전이 호환되어야 한다.
- (다수의 호스트들이 동시에 데이터에 접근하는 과정에서) 시스템은 접근 권한을 주고, 이것이 충돌(conflict)하지 않도록 조율하는 기능이 필요한데, 이를 DLM(Distributed Lock Manager)이라고 한다.
*DLM을 사용하면 엑세스 권한을 조율하고, 리소스에 대한 접근 과정을 직렬화해서 충돌 상황을 방지한다.
- 클러스터 기술을 빠르게 변해서, 어떤 클러스터는 수천 개의 시스템을 클러스터에서 관리한다.
- SAM(Storage-Area Networks): 많은 시스템들이 저장소 풀에 접근할 수 있도록 허용한다. SAM 시스템에서 만약 호스트에 문제가 생기는 경우, 다른 호스트가 이를 넘겨받을 수 있다. 클러스터의 성능과 신뢰성을 대폭 높일 수 있는 방법이다.

## 1.4. 운영체제 구조
- 운영체제는 프로그램이 실행할 수 있는 환경을 제공한다.
- 운영체제는 수많은 종류가 있지만, 대부분 공통적인 특징을 갖고 있다.

예) 컴퓨터가 최초로 구동될 때, 최초로 실행하는 프로그램(또는 bootstrap 프로그램)이 필요하다.
- 전통적으로 '최초로 구동될 때' 실행되는 프로그램은 펌웨어 내의 컴퓨터 하드웨어에 저장되어 있다.
- bootstrap 프로그램은 어떻게 운영체제 시스템을 불러와서 시스템 내에서 시작할 수 있는지에 대한 정보가 필요하다. 이를 위해 bootstrap 프로그램은 운영체제 커널 내에 위치하여 메모리에 적재된다.
- 커널이 적재/실행되면, 커널은 서비스를 시스템/사용자에게 제공한다.
```
커널
RAM에 상시 적재되어 있는 운영 체제 시스템
```
- 일부 서비스는 커널 외부에 위치해서 시스템 프로그램에 의해 제공되며, 부팅 시 메모리에 적재가 된다. 이 시스템은 daemon 시스템이 된다.
- daemon 시스템은 커널이 동작하는 한 종료되지 않는다.
- 리눅스에서는 최초 프로그램이 'systemd'인데, 이는 daemon 시스템의 일종이다. 그리고 systemd는 다른 많은 daemon 시스템들을 작동시킨다.
- daemon 시스템들을 가동하는 절차가 완료되면, 시스템은 완전히 부팅되어 다른 이벤트를 기다릴 수 있는 상태가 된다.
- 만약 다른 제약 사항(실행 중인 프로세서, 입출력 장치, 응답을 기다리는 사용자 등)이 없다면, 운영체제는 조용히 대기 상태에 돌입한다.
- 이벤트는 거의 항상 인터럽트 발생 시 이벤트 신호가 발생한다.
- 인터럽트는 (이전에 다뤘던 것처럼) HW에 의한 인터럽트가 있지만, 소프트웨어 예외 상황에 대한 인터럽트도 있다.

예) 소프트웨어에 대한 인터럽트 예시: 0으로 나누기, 유효하지 않은 메모리 접근
- 소프트웨어는 예외 상황이 아니더라도 운영체제 시스템에 특별한 동작 실행을 요청하기도 한다(시스템 콜).

### 1. 멀티프로그래밍과 멀티태스킹
- 운영체제의 중요한 측면 중 하나는 다수의 프로그램을 구동시키는 능력이다.
- 시스템은 기본적으로 입출력 장치나 CPU가 수행 중(busy) 상태에서도 다른 프로그램을 동작할 수 있어야 한다.

예) 프린터 출력 중에도 다른 동작을 할 수 있어야 함
- 멀티프로그래밍은 항상 최소 하나의 프로그램이 항시 가동되게 만들어서, CPU 활용성을 높이고 사용자를 만족시킬 수 있다.
- 멀티프로그램 시스템에서 실행 중인 프로그램을 '프로세스(process)'라고 한다.

### 2. 듀얼 모드와 멀티 모드 작동(operation)
- 운영체제와 사용자는 컴퓨터의 HW/SW 자원을 공유하므로, 적절히 디자인된 운영체제는 잘못된(또는 악의적인) 프로그램이 다른 프로그램(운영체제 자신 포함)을 부정확하게 실행하지 않도록 해야 한다.
- 이를 위해서는 사용자가 정의한 코드와 운영체제 시스템 코드의 실행을 구분해야 한다. 이를 사용자 모드와 커널 모드로 구분한다.
```
커널 모드
커널 모드는 관리자 모드, 시스템 모드라고도 한다.
```
- 커널 모드로 실행되는 경우 모드 비트가 컴퓨터의 하드웨어에 추가되어, 현재 모드가 커널(0)인지 사용자(1)인지 구분한다.
- 일반적으로 사용자가 프로그램을 실행하는 경우 '사용자 모드' 체제에서 동작하지만, 사용자가 운영체제에 서비스(시스템 콜)를 요구하는 경우 운영체제는 일시적으로 '커널 모드'로 전환해야 한다.
- 듀얼 모드는 잘못된 사용자로부터 운영체제를 보호하는 기능을 제공한다.
- 하드웨어는 '특별한 기능'을 커널 모드 상에서만 동작하도록 제한한다. 만약 이 기능을 사용자 모드에서 실행하려 하면, 하드웨어는 유효하지 않은 접근으로 간주하고 운영체제에 격리시킨다(trap).
- I/O, 타이머, 인터럽트 관리 등의 다른 기능들도 듀얼 모드와 모드 간 스위치 기능을 사용하는 예시이다.
- '듀얼 모드' 컨셉은 인텔의 protection rings, ARMv8의 VMM등에도 적용되어 있다. (*커널 모드와는 상이한 점이 있음)
- Windows, UNIX, Linux 등 자주 사용되는 운영체제들은 듀얼 모드를 통해 운영체제 자체에 향상된 보호 체계를 갖추고 있다.

### 3. 시스템 콜
- 시스템 콜은 사용자 프로그램이 OS에게 (사용자 프로그램) 자신의 이익을 위한 동작을 요청하는 동작이다.
- 시스템 콜은 기반 프로세서에 따라 다양한 방식으로 호출(Invoke)된다.
- 시스템 콜이 실행되면, 하드웨어에서는 이를 소프트웨어 인터럽트로 간주하고, 모드 비트가 '커널 모드'로 전환된다.
- 시스템 콜 서비스 루틴은 운영 체제의 일부다.
- 커널은 인터럽트 신호를 분석하여, 어떤 시스템 콜이 발생했는지 확인한다. (*어떤 종류인지는 콜에 포함된 파라미터를 통해 확인)
- 커널은 파라미터를 통해 시스템 콜의 유효성을 판단하고, 요청을 실행한 다음, 명령어로 제어 권한을 반환한다.
- 하드웨어 보호 기능이 정상 동작하는 경우, 모드 위반(violate)으로 인한 에러를 감지한다.
- 모드 위반으로 인한 에러는 보통 운영체제에 의해 관리된다.
- 만약 사용자 프로그램이 어떠한 이유로 실패하는 경우(예: 사용자에게 할당되지 않은 메모리 접근), 하드웨어는 (이 프로그램을) 운영체제에 가둔다. 가두는(trap) 신호는 인터럽트 벡터를 통해 운영체제로 전송된다. (*이 과정은 일반적인 인터럽트와 동일)
- 프로그램 에러가 발생한 경우, 운영체제는 이 프로그램을 '비정상적으로' 종료해야 한다. 이 때 적절한 에러 메시지가 주어지고, 프로그램에 할당되었던 메모리는 버려질(dump) 수 있다. 메모리 dump는 파일(로그)에 write되어, 사용자나 프로그래머가 어떤 문제였는지 판단하고 프로그램을 재시작할 수 있도록 한다.

### 4. 타이머
- 운영체제는 CPU 상에서 관리된다.
- 운영체제는 사용자 프로그램에게 무한 루프나 시스템 콜에 실패한 경우 영원히 제어권을 반환받지 못하는 경우가 발생해서는 안 된다. 이를 방지하기 위해 '타이머'를 사용한다.
- 타이머는 컴퓨터에 일정한 주기마다 인터럽트가 발생하도록 설정되어 있다.
- 가변 타이머(variable timer)는 일반적으로 고정율 시계(fixed-rate clock)과 카운터(counter)에 의해 실행된다.
- 운영체제가 카운터를 설정하고, 매시간 클럭 tick이 발생할 때마다 카운터 값이 감소한다.
- 카운터가 0이 되면 인터럽트가 발생한다.

예) 10비트 카운터와 1ms 클럭은 인터럽트 간격을 1ms~1024(2^10)ms 사이의 값으로 맞출 수 있다.
- 운영체제는 사용자에게 시스템 권한을 넘겨주기 전에, 타이머가 인터럽트 상태로 설정되어 있는지 확인한다. 만약 타이머 인터럽트가 발생한 경우, 제어 권한은 자동으로 운영 체제에 넘어가며 프로그램에 치명적인 오류가 발생한 것으로 간주된다.
- 타이머 설정은 운영체제의 '특별한' 권한이라고 할 수 있다.

## 1.5. 자원 관리

### 1. 프로세스 관리
- 프로그램은 CPU로부터 명령을 받지 않는 한 아무것도 할 수 없다.
- 프로그램이 메모리에 적재되어 실행되면 프로세스(process)가 된다.
- 프로세스는 작업을 완료하기 위해 일정한 자원을 요구한다(CPU 시간, 메모리, 파일, 입출력 장치 등).
- 프로세스가 생성될 때 얻는 다양한 물리적/논리적 자원에 더해, 다양한 초기 데이터(입력값)도 지나갈 수 있다.

예) 웹 사이트를 열 때 URL을 입력받으면 프로세서는 화면에 (해당 사이트의) 화면을 표시해 준다.
- CPU는 한 프로세서에 (그 프로세서가 작업이 완료될 때까지) 계속해서 명령을 내린다.
- 게다가, 한 명령은 프로세서의 이익(목표)를 위해 실행된다.
- 그래서 두 프로세스가 동일한 프로그램에 연관되어 있어도, 두 개의 별개의 시퀀스로 분류된다.
- 멀티스레드 프로세스는 다중 프로그램 카운터를 보유하고 있어서, 각각은 주어진 스레드에 대해 실행할 다음 명령어를 가리킨다(point).
- 프로세스는 시스템의 개별 개체로서 동작하고, 시스템은 프로세서들의 모임으로 구성되어 있다.
- 운영체제와 다른 사용자 프로세스들은 하나의 CPU 코어 내에서도 다중화를 통해 동시에 동작할 가능성이 있다.
- 운영체제는 다음과 같은 활동들을 관장한다:
```
1. 사용자와 시스템 프로세스의 생성과 삭제
2. CPU의 프로세스와 스레드 스케쥴링
3. 프로세스의 일시정지(suspend)와 재개(resume)
4. 프로세스 동기화 매커니즘 제공
5. 프로세스 간 통신 매커니즘 제공
```

### 2. 메모리 관리 
- 메인 메모리는 현대 컴퓨터 시스템의 동작의 핵심이다.
- 각 바이트는 자신의 주소를 가진다.
- 메인 메모리는 CPU와 입출력 장치에 의해 공유된 접근 가능한 데이터에 빠르게 접근 가능한 저장소이다.
- CPU는 (폰노이만 사이클 상의) 명령 페치 사이클에서 메인 메모리의 데이터를 읽는다.
- 메인 메모리는 CPU가 직접 정의하고 접근할 수 있는 유일한 대용량 데이터이다.

예) CPU가 디스크에서 데이터를 처리하는 상황에서 데이터는 먼저 CPU의 입출력 콜에 의해 메인 메모리로 이동한다.
- 실행되어야 하는 프로그램은 절대 주소로 맵핑되어 메모리에 적재되어야 한다.
- 프로그램이 실행되면, 프로그램은 절대 주소를 생성하여 프로그램 지침과 메모리의 데이터에 접근한다.
- 메모리 용량이 사용 가능하면, 다음 프로그램이 적재되어 실행할 수 있다.
- CPU 사용성과 응답 속도를 높이기 위해 일반적인 컴퓨터들은 몇몇 프로그램을 메모리에 보존(keep)하여, 메모리 관리를 요구한다.
- 이 체계는 다양한 접근들과 상황에 따른 주어진 알고리즘의 유효성을 반영한다.
- 특정 시스템의 메모리 관리 체계에서 우리는 많은 기능을 담당해야 한다.(특히 시스템의 하드웨어 디자인)
- 각 알고리즘은 고유한 하드웨어 지원을 필요로 한다.
- 운영체제는 메모리 관리에서 이하 활동들을 담당한다:
```
1. 메모리의 어떤 영역이 현재 사용중이고 어떤 프로세스가 그것을 점유하는지에 대한 추적 유지
2. 필요한 메모리 공간의 할당/해제
3. 어떤 프로세스(프로세스의 부분 포함)와 데이터가 메모리 안/밖으로 움직이는지에 대한 결정
```

### 3. 파일시스템 관리
- 컴퓨터 시스템을 사용자에게 편리하게 만들기 위해, 운영체제는 정보 저장소에 대한 규격화되고 논리적인 정보를 제공한다.
- 운영체제는 논리적 저장소 유닛을 정의하기 위해 저장소의 물리적 속성을 추상화한다.
- 운영체제는 물리적 미디어로 파일을 맵핑하고 이들을 저장소 디바이스를 통해 접근한다.
- 파일 관리는 운영체제의 눈에 띄는 요소 중 하다이다.
- 컴퓨터는 몇몇 다양한 형태의 미디어로 정보 저장이 가능하다.
- 미디어들을 각자의 특징과 물리적 구조를 갖고 있다.
- 대부분은 디바이스에 의해 제어된다(디스크 드라이브처럼). 이들은 고유한 *특징*을 보유한다.
- *특징*으로 접근 속도, 용량, 전송 속도, 접근 방법(순차적/무작위) 등이 있다.
- 파일은 생성자에 의해 정의된 관련된 정보들의 모음이다.
- 일반적으로 파일은 프로그램과 데이터를 대표한다.(*프로그램은 소스와 오브젝트 형태를 모두 포함)
- 데이터 파일은 숫자/알파벳/영숫자/이진(바이너리) 형태일 수 있다.
- 파일은 자유로운 형식(예: 텍스트 파일)일 수 있고, 엄격한 포맷일 수도 있다(예: MPC 음악 파일의 고정 필드).
- 분명히, 파일의 컨셉은 극히 일반적인 것이다.
- 운영체제는 대용량 미디어 저장소와 그것들을 제어하는 컨트롤을 제어함으로서 파일의 추상적인 개념을 실행한다.
- 운영체제는 파일 관리에서 아래 활동들을 담당한다:
```
1. 파일의 생성/삭제
2. (파일을 관리하는)폴더의 생성/삭제
3. 파일 및 디렉토리 관리를 위한 기본 요소 지원
4. 대용량 저장소에 파일 맵핑
5. 파일을 고정된(비휘발성) 저장소 미디어에 백업
```
### 4. 대용량 관리
- 컴퓨터 시스템은 메인 메모리를 백업하기 위한 이차적인 저장소를 제공해야 한다.
- 현대의 대부분의 시스템들은 HDD(*SSD)와 NVM 장치들을 사용한다.
- 많은 프로그램들(컴파일러, 웹 브라우저, 워드 프로세서, 게임 등)은 메모리에 적재되기 전까지 저장소에 저장되어 있다.
- 이 프로그램들은 (일단 적재가 되면) 그들의 소스와 목적을 위해 장치를 사용한다.
- 그러므로, 이차 저장소의 적절한 관리는 컴퓨터 시스템의 핵심이 된다.
- 운영체제는 이차 저장소 관리에 다음과 같은 작업들을 담당한다:
```
1. 마운팅/언마운팅
2. 여유 공간 간리
3. 저장소 할당
4. 디스크 스케쥴링
5. 파티션
6. 보호
```
- 이차 저장소는 자주 그리고 널리 사용되므로, 효율적으로 사용되어야 한다.
- 컴퓨터의 모든 동작은 이차 저장소 서브시스템 속도와 그것의 알고리즘에 의해 달라질 수 있다.
- 동시에 보조저장장치보다 더 느리고 비용은 적게 들고 때로는 용량이 더 큰 장치를 필요로 하는 경우도 많다.(*디스크 데이터 백업, CD/DVD 등의 3차 저장 장치)

### 5. 캐시 관리
- 캐싱(cacheing)은 컴퓨터 시스템의 중요 원리이다.
- 캐시는 향상된 속도의 임시 저장소이다.
- 우리가 정보의 특정한 조건을 읽을 때, 그것이 캐시에 있는지를 먼저 확인한다. 만약 캐시 메모리에 저장된 것이라면 우리는 그것을 캐시에서 바로 가져와서 사용한다.
- 만약 캐시에 없는 정보라면, 우리는 소스에서 정보를 사용해서, 나중에 사용할 수 있다는 가정 하에 캐시에 복사해 둔다.
- 추가로, 내부의 프로그램 가능한 레지스터는 메인 메모리에 고속 캐시를 제공한다.
- 프로그래머(컴파일러)는 레지스터 할당을 구현하고 어떤 정보를 레지스터에 저장하고, 레지스터 교체 알고리즘은 어떤 정보를 메인 메모리에 저장할지를 결정한다.
- 다른 캐시들은 전적으로 하드웨어에서 구현된다.

예) 대부분의 시스템들은 나중에 실행될 것으로 예상되는 명령들을 명령 캐시에 저장해서, 명령이 메인 메모리로부터 페치되는 데 걸리는 시간을 절약한다.

### 6. 입출력 관리
- 운영체제의 목적 중 하나는 특정 하드웨어 장치의 특징을 사용자로부터 숨기는 것이다.
- 디바이스 드라이버만이 (배정된) 디바이스의 특징을 알 수 있다.
- 입출력 서브시스템은 몇 가지 요소로 구성되어 있다:
```
1. 버퍼링, 캐싱, 스풀링을 포함한 메모리 관리 요소
2. 일반적인 디바이스 드라이버 인터페이스
3. 특정 하드웨어 장치의 드라이버
```

## 1.6. 보안 및 보호
- 컴퓨터 시스템이 다수의 사용자가 있고, 다수의 프로세스에 동시 실행을 서용하면, 데이터에 대한 접근이 제한될 것이다.
- 이를 위해 파일, 메모리 세그먼트, CPU 및 다른 자원들에 대해 운영체제로부터 적절한 허가를 획득한 프로세스만이 작업할 수 있도록 보장하는 구조가 필요하다.

예) 메모리 주소 지정 하드웨어는 프로세스가 자신의 주소 영역에서만 실행될 수 있도록 보장한다.
- 타이머는 프로세스가 제어 권한을 포기하지 않는 한 CPU 제어 권한을 얻을 수 없도록 제한한다.
- 장치 제어 레지스터는 일반 사용자들이 접근할 수 없게 막혀 있어서, 다양한 주변 장치들을 보호한다.
- 보호(protection)는 프로세스나 유저가 (컴퓨터에 의해 정의된) 리소스에 접근하는 행위를 제어하는 동작이다.
- 보호는 시행될 제어에 대한 명세와 이들을 강제 시행하는 방법을 규정하는 수단을 반드시 제공해야 한다.
- 보호는 컴포넌트와 서브시스템 사이의 인터페이스에 숨어 있는 에러를 감지하여 신뢰성을 높일 수 있다.
- 인터페이스 에러의 조기 감지는 한 서브시스템이 다른 서브시스템의 오작동으로 인한 오염(contamination)을 방지할 수 있다.
- 보호받지 못한 리소스는 권한이 없거나 무능한 사용자로부터 대응할 수 없다.
- 보호 기반의 시스템은 권한 유무에 따라 기능을 차등적으로 제공한다.
- 적합한 보호 체계가 있는 시스템도 실패하여 부적절한 접근을 허용하는 경우가 있다.(예: 인증 수단이 도난당한 경우)
- 이 경우 파일과 메모리 보호 체계가 정상 동작하더라도, 데이터는 유출 또는 유실될 수 있다.
- 시스템을 내/외부 공격으로부터 보호하는 기능을 *보안(security)*이라 한다.
- 시스템에 대한 공격은 (바이러스, 웜 등을 포함해서) 광범위하며, 서비스 거부 공격(*시스템의 모든 자원을 사용해서 유효한 사용자를 시스템에 접근하지 못하도록 하는 행위), 신원 도용, 서비스 도용(권한 없는 시스템 사용) 등이 있다.
- 보안 이슈에 대한 경각심이 증가하면서 운영체제의 보안성은 빠르게 성장하며 적용되고 있다.
- 보안과 보호는 시스템이 사용자를 구분하는 체계를 요구한다.
- 대부분의 운영체제는 사용자를 고유한 ID값으로 구분한다.
- 사용자가 로그인을 시도하면, 인증 스테이지에서는 사용자 ID가 적합한지 판단한다.
- 사용자 ID는 그 사용자의 프로세스와 스레드에 연관이 되어 있어서, ID를 사용자가 읽어야 할 필요가 있을 때 사용자 이름 리스트를 통하여 원래의 사용자 이름으로 보여준다.
- 어떤 상황에서는 각 사용자가 아니라 사용자의 집합을 구분하기를 원한다.

예) UNIX 시스템에는 일부 사용자에게는 모든 작업을 허용하되, 일부 사용자들에게는 읽기 전용으로 설정할 수도 있다.
- 이를 위해서 우리는 그룹 이름을 정의하고 해당 그룹에 속하는 사용자들을 설정할 필요가 있다.
- 그룹 기능은 시스템 전체에 존재하는 그룹 이름과 그룹 식별자의 리스트로 구현될 수 있다
- 운영체제의 설계에 따라 사용자는 하나 이상의 그룹에 속할 수 있다.
- 사용자의 그룹 ID 또한 관련 프로세스나 스레드에 포함된다.
- 일반적인 시스템 사용에서 사용자 ID와 그룹 ID만 있어도 충분하다.
- 다만, 사용자는 때때로 자신의 권한을 상승시켜야 할 필요가 있다.(예: 제한된 영역에 접근이 필요한 경우)
- 운영체제는 권한 상승을 허용하는 다양한 매커니즘을 제공한다.

예) UNIX 시스템에서는 'setuid' 동작은 현재 사용자의 ID가 아닌 파일 소유자의 ID로 프로그램 실행이 가능하게 한다.

## 1.7. 가상화
- 가상화는 단일 컴퓨터에서 동시에 작동 가능하며 서로 상호작용 가능한 하드웨어를 추상화하는 기술이다.(*컴퓨터에는 CPU, 메모리, 디스크, 드라이버, 네트워크 인터페이스 등이 포함)
- 가상 머신(virtual machine) 사용자는 단일 운영체제에서 동시에 실행되는 다양한 프로세스 간에 전환할 수 있는 것과 동일한 방식으로 다양한 운영체제 간에 전환할 수 있다.
(*버추얼 머신 프로그램에서 서로 다른 운영체제 간 스위칭이 자유로운 걸 생각하면 될 것 같다.)
- 가상화는 운영체제로 하여금 다른 운영체제를 응용 프로그램처럼 실행할 수 있게 한다.
- 가상화는 큰 쓸모가 없어 보일 수 있어도, 관련 산업이 빠르게 성장하고 있다.
- 넓은 의미에서 가상화 소프트웨어는 에뮬레이션(emulation)이 가능한 소프트웨어의 일종이다.
- 에뮬레이션은 컴퓨터 하드웨어를 소프트웨어적으로 시뮬레이션하여, 소스 CPU 타입이 대상 CPU 타입과 다른 경우에 사용된다.

예) 컴퓨터의 CPU를 IBM에서 인텔 x86으로 변경한 경우, 'Rosetta'라는 에뮬레이터를 사용하여 IBM CPU 체제에서 컴파일된 프로그램을 x86에서 원활히 실행될 수 있게 할 수 있다.
- 에뮬레이션은 비용이 많이 든다(heavy price).
- 소스 시스템에서 수행되는 기계어 수준의 모든 명령은 목표 시스템에서 동등한 기능으로 번역되어야 하고, 종종 이는 여러 개의 목표 명령어가 되기도 한다.
- 만일 소스와 목표 CPU가 비슷한 성능 수준일 경우 에뮬레이트된 코드는 원래 코드보다 훨씬 느리게 실행된다.
- 반면 가상화의 경우 특정 CPU를 위해 컴파일된 운영체제가 동일 CPU용의 다른 운영체제 내에서 수행된다.
- 가상화는 IBM 메인프레임에서 다수의 사용자들이 작업을 동시에 할 수 있도록 하는 방법으로서 등장했다.
- 다수의 가상 머신 동작은 많은 사용자들로 하여금 단일 사용자를 위해 설계된 작업을 할 수 있게 해 주었다.
- 이후에는 VMWare가 등장해서 Windows 응용 프로그램을 x86 CPU에서 실행했을 때 발생하는 문제점을 보완했다.
- VMWare는 게스트(guest)라 불리는 하나 이상의 Windows나 다른 x86용 운영체제 복사본들을 실행하며, 각 게스트는 자신의 응용 프로그램을 실행한다.
- Windows는 운영체제의 호스트고, VMWare는 가상 머신 관리자(Virtual Machine Manager)이다.
- VMM은 게스트 운영 체제를 실행하고, (게스트의) 자원 사용을 관리하고, 다른 게스트들로부터 서로를 보호한다.
- 현대 운영체제는 다수의 응용 프로그램을 안정적으로 실행할 수 있지만, 가상화의 사용성은 계속 발전하고 있다.

## 1.8. 분산 시스템(Distributed Systems)
- 분산 시스템은 물리적으로 분리된, 이질적인 컴퓨터 시스템들의 집합이다.
- 분산 시스템의 컴퓨터들은 사용자가 시스템 내의 다양한 자원들에 접근할 수 있도록 네트워크로 연결되어 있다.
- 공유 자원에 대한 접근은 컴퓨팅 속도, 기능성, 데이터 신뢰성을 향상시킨다.
- 일부 운영 체제는 네트워크의 자세한 사항을 네트워크 인터페이스의 장치 드라이버에 포함시킴으로써 파일 접근 형식으로 네트워크 접근을 일반화했다.
- 한편, 다른 운영체제들은 사용자가 특정 네트워크 기능을 명시적으로 호출하게 한다.
- 일반적으로 시스템 상에서는 두 모드가 혼재되어 있으며 그 예로 FTP와 NFS를 들 수 있다.
- 분산 시스템을 만드는 프로토콜은 시스템의 활용성과 대중성에 큰 영향을 준다.
- 네트워크는 두 개 이상의 시스템이 소통하는 경로이다.
- 분산 시스템은 그들의 기능을 위한 네트워킹에 의존한다.
- 네트워크는 프로토콜, 노드 간 거리, 전송 매체에 따라 다양하다.
- TCP/IP는 가장 일반적인 네트워크 프로토콜이고, 인터넷의 기본적인 아키텍처를 제공한다. 많은 운영체제들이 TCP/IP를 지원한다.
- 네트워크는 노드 간 거리에 따라 성격이 구분된다.
- LAN은 단거리, WAN은 지역(건물, 도시, 국가) 간 네트워크이다.
- 개인형 제품(스마트폰 등)은 PAN을 사용하기도 한다.
- 일부 운영체제는 네트워크 연결 제공 개념을 넘어서서 네트워크 및 분산 시스템을 적용했다.
- 네트워크 운영체제(network operating system)는 다른 컴퓨터의 다른 프로세스가 메시지를 교환할 수 있도록 하는 통신 체계와 함께 네트워크를 통한 파일 공유와 같은 기능을 제공하는 운영체제이다.
- 네트워크 운영체제를 실행 중인 컴퓨터는 네트워크를 인식하고 다른 네트워크 컴퓨터와 통신할 수 있지만, 네트워크의 다른 모든 컴퓨터와는 자율적으로 작동한다.
- 분산 운영체제는 네트워크 운영체제에 비해 덜 자율적인 환경을 제공한다
- 하나의 운영체제가 네트워크를 제어하는 것 처럼 보이기 위해 여러 컴퓨터가 밀접하게 통신한다.

## 1.9. 커널 데이터 구조

### 1. 리스트, 스택, 큐
- 배열은 각 원소가 직접 접근될 수 있는 단순한 자료구조이다
예) 메인 메모리는 하나의 배열로 구성된다.
- 저장된 데이터가 한 바이트보다 크면, 다수의 바이트들이 아이템에 할당되고, 아이템은 '아이템 번호 * 아이템 크기'로 지정된다.
- 다만 크기가 다양하거나, 특정 아이템을 삭제해도 다른 아이템의 상대적인 위치가 유지되어야 하는 경우, 다른 자료구조를 사용해야 한다.
- 배열 이후로 리스트는 아마 컴퓨터 과학에서 가장 기본적인 자료구조일 것이다.
- 배열의 각 항은 (순서에 관계없이) 직접 접근할 수 있으나 리스트의 항은 일정한 순서대로 접근해야 한다.
- 즉, 리스트는 데이터 값들의 집단을 하나의 시퀀스로 표시한다.
- 이 구조를 구현하는 가장 일반적인 방법이 연결 리스트(linked list)이다.
- 연결 리스트에서는 각 항이 다른 하나에 연결되어 있다.
- 큐는 반대로 순차 순서의 자료구조로, 선입선출(first in first out, FIFO) 개념을 사용한다.

### 2. 트리
- 트리는 데이터의 서열을 표시하는 데 사용할 수 있는 자료구조이다.
- 트리 구조에서 데이터 값들은 부모-자식 관계로 연결된다.
- 일반 트리(general tree)에서 부모가 가질 수 있는 자식 수는 제한이 없지만, 이진 트리에서 부모는 최대 두 개의 자식을 가질 수 있다.
- 이진 투리의 두 자식의 값은 (왼쪽 자식 <= 오른쪽 자식) 형태로 배치되어야 한다.

### 3. 해시 함수와 맵
- 해시 함수는 데이터를 입력으로 받고 이 데이터에 산술 연산을 수행한 뒤, 산술값을 반환한다.
- 산술값은 데이터를 인출하기 위해 테이블(전형적으로 하나의 배열)의 인덱스로 사용할 수 있다.
- 해시 함수는 시간복잡도가 낮아서, 운영체제에서 광범위하게 사용된다.
- 해시 함수의 한 어려운 점은 두 개의 서로 다른 입력이 하나의 출력 값을 가질 수 있다는 것이다.
- 즉, 서로 다른 노드들이 테이블의 동일 위치를 가리킬(link) 수 있다.
- 이를 우리는 해시 충돌(hash collision)이라 하며 테이블의 각 항에 연결 리스트를 두어 동일한 해시 값을 갖는 모든 항을 수록하게 한다.
- 물론 충돌이 많을 수록 해시 함수의 효율이 떨어지게 된다.
- 해시 함수는 해시 맵(hash map)을 구현할 때 사용한다.
- 해시 맵은 해시 함수를 사용하여 [키, 값]을 연관(또는 맵핑) 시킨다.
- 일단 매핑이 성립되면 키에 해시 함수를 사용하여 해시맵으로부터 그 값을 얻을 수 있다.

예) 사용자가 비밀번호를 입력하면, 사용자 이름에 해시 함수가 적용되어 이에 연결된 비밀번호를 알아낸 다음, 사용자의 입력값과 비교한다.

### 4. 비트맵
- 비트맵은 n개의 항의 상태를 나타내는 데 사용 가능한 n개의 이진 비트의 문자열이다.

예) 다수의 자원이 있을 때, 자원의 사용 가능 여부를 0/1로 표시할 수 있다.
- 비트맵에서 i번째 위치의 값은 i번째 자원과 연관되어 있다.

## 1.10. 컴퓨팅 환경

### 1. 전통적 계산
- 오늘날 컴퓨팅이 성숙하면서, 전통적인 계산의 영역 간 경계가 모호해지고 있다.
- 업체들은 '포털'을 설립해서, 전체 서버에 대한 웹 접근성을 제공한다.(*구글, 네이버 같은 거 얘기하는 듯)
ㄴ 요즘으로 치면 챗지피티, 코파일럿, iCloud + Siri 같은 것도 포함될 수 있겠다.
- 네트워크 컴퓨터(또는 thin client)는 실질적으로 웹 기반 컴퓨팅을 이해하는 터미널을 말하며, 이들은 향상된 보안성과 유지보수 편의성이 필요한 경우 전통적인 워크스테이션을 대체하고 있다.
- 모바일 컴퓨터(노트북, 스마트폰)는 PC와 동기화되고, 무선 네트워크와 셀룰러 데이터(네트워크)로 연결된다.
*시분할 시스템: CPU에서 자원의 일정량을 각 사용자(사용자의 프로세스)마다 하나씩 돌아가면서 실행시키기 위하여 타이머와 스케줄링 알고리즘을 이용하는 체계

### 2. 모바일 컴퓨팅
- 모바일 컴퓨팅은 휴대용 스마트폰과 태블릿 컴퓨터와 연관되어 있다.
- 스마트폰+태블릿은 물리적으로 가볍고 휴대하기 좋다.
- 역사적으로 데스크롭/노트북과 비교하면 모바일 장비는 화면 크기, 메모리 용량, 전반적인 기능을 포기한 대신 휴대성을 확보했다.
- 하지만 최근은 모바일 디바이스의 성능도 풍족해져서, 전통적인 PC와의 구분이 어려워졌다.
- 모바일 디바이스에는 GPS 센서, 가속계, 자이로스코프가 있다 보니 프로그램 개발자들은 이를 고려해서 개발을 하기 시작했다.

예) 내비게이션 서비스는 모바일 디바이스에서 구현하기에 적합하다.
- 모바일 디바이스가 온라인 서비스를 제공/접근하려면 IEEE 표준 802.11(Wi-Fi) 또는 셀룰러 데이터를 사용해야 한다.
- 모바일 디바이스의 운영체제로 애플 iOS와 구글 안드로이드가 주로 사용된다.

### 3. 클라이언트-서버 컴퓨팅
- 현대 네트워크 구조는 서버 시스템에서 클라이언트 시스템이 생성한 요청을 만족시키는 배치를 특징으로 한다.
- 서버 시스템은 일반적으로 계산 서버와 파일 서버로 분류될 수 있다.
- 계산-서버(compute-server) 시스템은 클라이언트가 어떤 작업을(예를 들어, 데이터 읽기) 요청할 수 있는 인터페이스를 제공한다. 요청에 대해서 서버는 그 작업을 수행하고, 결과를 클라이언트에게 반환한다.
- 파일-서버(file-serve) 시스템은 클라이언트가 파일을 생성, 갱신, 읽기 및 제거할 수 있는 파일 시스템 인터페이스를 제공한다. (*클라우드 저장소 서비스를 생각하면 될 것 같다.)


### 4. 동료(peer) 간 계산
- 분산 시스템의 다른 구조로 P2P(Peer 2 Peer)가 있다.

예) 토렌트
- P2P 모델에서는 클라이언트와 서버사 명확하게 구분되지 않는다.
- 대신, 시스템을 구성하는 모든 노드들이 '동료(peer)'로 간주되고, 각자가 클라이언트 또는 서버의 역할을 한다.
- P2P가 클라이언트 대시 우위를 점하는 요소로 서버 쪽에서 발생하는 병목현상이 최소화된다는 것이 있다.
- P2P는 일반적으로 두 가지 방식 중 하나로 구현된다:
```
1. 노드가 네트워크에 추가(join)되면, 중앙화된 조회(lookup) 서비스에 등록된다. 특정 서비스를 요청하는 어떤 노드가 중앙 조회 서비스에 요청을 보내면, 중앙 조회 서비스에서는 어떤 노드가 서비스를 제공할지 결정한다. 통신의 나머지(중개 이후 서버-클라이언트 상호작용)는 클라이언트와 서비스 제공자 사이에서 발생한다.
2. (1번에 대한 대안으로) 중앙 조회 서비스를 사용하지 않는 방식이 있다. 클라이언트 역할을 하는 peer는 어떤 노드가 서비스 요청을 브로드캐스팅하는지(서버 역할을 하는지) 발견해야 한다. 서비스를 제공하는 노드는 (클라이언트) 피어에 대해 응답한다. 이러한 접근법을 구현하려면 발견 프로토콜(discovery protocol)이 peer들이 서로 찾을 수 있도록 서비스를 제공해 주어야 한다.
```

### 5. 클라우드 컴퓨팅
- 클라우드 컴퓨팅은 계산, 저장장치는 물론 응용 프로그램조차도 네트워크를 통한 서비스로 제공하는 계산 유형이다.
*최근에는 클라우드 컴퓨팅의 영역이 넓어져서, 서버나 AI 모델도 클라우드 형태로 제공할 수 있다.
- 논리적으로, 클라우드 컴퓨팅은 가상화 기술의 연장선이라 할 수 있다.
- 클라우드 컴퓨팅의 예시로 아마존의 EC2(Elastic Compute Cloud)가 있다.
- 클라우드 컴퓨팅은 사용자가 (서비스에 대한) 사용료만 내면 자유롭게 사용할 수 있다는 장점이 있다.
- 클라우드/클라우드 컴퓨팅은 여러 가지 종류가 있다:
```
1. 공용 클라우드: 인터넷 접속만 가능하면 모든 사용자가 사용료를 내고 자유롭게 사용할 수 있는 클라우드(*iCloud, AWS, 구글 드라이브 등)
2. 사설 클라우드: 회사에서 회사 내부적으로 운영하는 클라우드(*사내에서만 사용하고, 외부에서 함부로 접근할 수 없는 형태)
3. 하이브리드 클라우드: 공용 클라우드와 사설 클라우드의 특징을 모두 갖고 있는 클라우드
4. SaaS: 응용 프로그램을 인터넷을 통해 클라우드 형태로 제공하는 서비스
5. PaaS: 소프트웨어 스택(DB 등)을 클라우드 형태로 제공하는 서비스
6. IaaS: 서버나 저장소를 클라우드 형태로 제공하는 서비스(*예: 공장 시설관리 서버를 클라우드로 구현하면 IaaS가 될 수 있음)
```
- 클라우드 컴퓨팅 유형은 여러 가지가 조합될 수 있다(단순히 한 가지에 해당한다고 정의할 수는 없다).

### 6. 실시간 임베디드 시스템
- 일반적인 임베디드 시스템은 외부로부터 격리되어 있다.
- 임베디드 시스템은 특정한 작업에 특화되어 있다.
- 임베디드 시스템은 원시적인 형태로 동작하므로, 임베디드 OS의 기능도 제한적이다.
- 임베디드 OS는 인터페이스가 적거나 없는 경우가 많고, 하드웨어 장치의 상태를 관리하는 데 대부분의 시간을 할애한다.

### 7. 실시간 OS(RTOS)
- 임베디드 시스템은 거의 대부분 실시간 OS(Real-Time OS) 상에서 동작한다.
- 실시간 시스템은 처리기의 작동이나 데이터의 흐름에 엄격한 시간 제약이 있을 때 사용된다.
- 만약 시스템이 정해진 제약 조건 내에 작업을 완료하지 못하면, 시스템은 강제로 실패 처리된다.

## 1.11. 무료 및 오픈소스 운영체제
- 무료 운영체제와 오픈소스 운영체제는 컴파일된 이진 코드가 아닌 소스 코드 형식으로 제공된다.
- 무료 소프트웨어와 오픈소스 소프트웨어는 서로 다른 그룹에서 유래한 아이디어이다.
- 무료 소프트웨어는 소스 코드를 공개할 뿐만 아니라 무료로 사용할 수 있도록 라이센스되고, 재배포와 수정도 자유롭다.
- 그래서 무료 소프트웨어는 오픈소스의 일종이지만, 모든 오픈 소스가 무료 소프트웨어인 것은 아니다.
ㄴ 오픈 소스는 위와 같은 정책 및 라이센스를 반드시 준수해야 할 필요는 없다.

### 1. 무료 운영체제
- 무료/공개 운영체제 중 자주 사용되는 것으로 GNU/Linux가 있다.
*UNIX는 무료 운영체제는 아니고, UNIX의 대체재로서 호환 가능한 형태로 만들어진 것이 GNU이다.
