# 3.1. 프로세스 컨셉
- 프로세스는 CPU가 한 번에 여러 동작을 할 수 있도록(여러 프로그램들을 동시에 실행할 수 있도록) 하기 위해 고안된 개념이다.
- 과거에는 process 대신 'job'이라는 표현을 썼는데, 운영 체제의 동작도 job processing을 담당했다.
- 운영체제의 이론과 술어(terminology)는 운영 체제의 주 활동이 'job processing'인 시절에 발전했다.
- 컴퓨터 기술이 발전하면서 메모리 관리 같은 프로그램 간 상호작용(활동)을 보조하는 기능이 필요해졌는데, 이 때 등장한 개념이 프로세스다.

## 3.1.1. 프로세스
- 프로세스는 프로그램이 실행 중인 상태이다.
- 프로세스의 현재 상태는 프로그램 카운터의 값과 프로세서 레지스터의 내용에 따라 구분된다.
- 프로그램이 실행 중인 상태여도 text 영역과 data 영역의 크기는 변경되지 않는다.
- 다만 heap과 stack 영역은 프로그램 실행 중에 유동적으로 바뀔 수 있다.
- 함수가 호출될 때마다, 활동 기록(activation record)는 함수 파라미터, 지역 변수를 포함해서 스택에 반환값의 주소를 푸시한다.
- 컨트롤이 함수에서 반환되면 활동 기록은 스택에서 pop된다.
- 프로그램은 실행 가능한 파일이 메모리에 적재될 때 프로세스가 된다.
- 두 프로세스가 동일한 프로그램과 연관되어 있다 해도, 각자는 별개의 실행 절차로 간주된다.

\* 예를 들어 동일한 프로그램을 여러 개 실행한 경우, 각 프로세스는 별개로 간주된다.

- 프로세스 그 자체가 다른 코드의 실행 환경이 될 수 있다. Java의 경우 JVM이 적재된 Java 코드를 해석하고 동작하는 역할을 하는데, 이 때 JVM이 프로세서로서 실행된 다음 JVM이 Java 코드를 실행한다.

## 3.1.2. 프로세스 상태
- 프로세스가 실행되면, '상태(state)'가 변경된다. 프로세스의 상태는 프로세스의 현재 활동에 따라 정의된다.
- 프로세스의 상태는 New, Running, Waiting, Ready, Terminated로 분류될 수 있다.
- 다만 프로세스 상태 이름은 운영 체제마다 다를 수 있다. (\*각자 정의하기 나름이다.)

## 3.1.3. 프로세스 제어 블록(PCB)
- 각 프로세스는 Process Control Block(PCB)에 의해 대표된다.
- PCB는 task control block이라고도 한다.
- PCB의 상태 정보로 프로세스 상태, 프로그램 카운터, CPU 레지스터, CPU 스케쥴링 정보, 메모리 관리 정보, 할당 정보, 입출력 상태 정보가 있다.
- PCB는 시작/재시작이 필요한 데이터, 프로세스, 중요 데이터에 대한 저장소를 담당한다.

## 3.1.4. 스레드
- 프로세스가 실행 중일 때, 한 개의 스레드가 같이 실행된다.
- 단일 스레드는 프로세스가 한 번에 하나의 작업만 실행하도록 한다.
- 기본적으로 한 프로그램 내에서는 동시에 하나의 동작만 할 수 있지만, 최근의 운영체제는 하나의 프로세스가 동시에 여러 작업을 할 수 있도록 멀티스레드를 지원하는 경우가 많다.
- 멀티스레드의 경우, 한 프로세스 내에서 여러 동작을 할 수 있게 한다.
- 멀티스레드는 서로 영향을 주지 않고(parallel) 각자 역할을 한다.
- 멀티스레드는 멀티프로세스 환경에서 특히 유용하다.

# 3.2. 프로세스 스케쥴링
- 멀티프로그래밍의 목적은 CPU의 사용성을 극대화하는 것에 있다.
- 이를 충족하기 위해 프로세스 스케쥴러는 사용 가능한 프로세스들을 선택하고, 코어 내에서 하나의 프로그램을 실행한다. 각 CPU 코어는 동시에 하나의 프로세스만 실행할 수 있다.
- 만약 CPU 코어 개수보다 실행 중인 프로세스 수가 더 많은 경우, 일부 프로세스는 코어 자원이 유휴 상태(free)가 될 때까지 기다린 다음 다시 스케쥴링되어야 한다.

## 3.2.1. 스케쥴링 큐
- 프로세스가 시스템에 접근할 때, ready queue에 삽입된다.
- 프로세스 스케쥴링은 보통 큐(queue)로 구현된다.
- 프로세스가 준비되고 CPU 코어의 실행을 기다리는 상태가 되면 queue는 일반적으로 연결 리스트(linked list)에 저장된다.
- 프로세스 스케쥴링을 나타내는 일반적인 방식은 큐 다이어그램이다.

## 3.2.2. CPU 스케쥴링
- CPU 스케쥴러의 역할은 ready queue에 있는 프로세스 중 하나를 선택하고 CPU core에 할당하는 것이다.
- 일부 운영체제는 'swapping'이라는 스케쥴링의 중간 형태를 갖고 있다.
  
## 3.2.3. Context Switch
- 일반적인 시스템에서 인터럽트는 자주 발생한다.
- 인터럽트가 발생할 때, 인터럽트 발생 전 시스템의 상태를 저장했다가 다른 프로세스에 복원할 수 있는데, 이를 context switch라고 한다.
- Context switch 횟수는 하드웨어 성능에 영향을 많이 받는다.
- 만약 (프로세서가 제공하는) 레지스터 수보다 실행 중인 프로세스가 더 많은 경우, 시스템은 레지스터 데이터를 메모리에서 관리한다.

# 3.3. 프로세스의 동작

## 3.3.1. 프로세스 생성
- 프로세스는 실행 과정에서 몇몇 새로운 프로세스를 만들 수 있다.
- 많은 운영체제들은 프로세스를 PID(프로세스 식별자)의 형태로 관리한다.
- 한 프로세스가 자식 프로세스를 생성할 때, 자식 프로세스는 작업을 수행하기 위해 일정한 시스템 자원을 필요로 한다. 이 때 부모 프로세스는 자식 프로세스에게 자신의 자원을 일정량 배분(partition)할 수 있다.
- 자식 프로세스는 부모 프로세스의 자원 사용에 제약이 있다. (\*그렇지 않으면 자식 프로세스가 무제한적으로 생성돼서 시스템에 과부하를 줄 수 있으므로..)
- 부모 프로세스가 자식 프로세스를 생성한 다음 유휴 상태에 빠지면, 자식 프로세스의 작업을 회수(wait)할 수 있다.

## 3.3.2. 프로세스 종료
- 프로세스는 프로그램의 마지막 코드를 실행하고 운영체제에 'exit' 시스템 콜을 호출해서 삭제를 요청할 때 종료된다.
- 프로세스는 상태값을 반환할 수 있고, 프로세스가 사용하던 자원(메모리, 버퍼, 입출력 장치 등)들은 회수된다.
- 일부 시스템은 부모 프로세스가 종료된 경우 자식 프로세스도 같이 종료되도록 한다. 이를 연쇄적 종료(cascading termination)이라고 한다.
- 일반적으로 프로세스가 종료될 때, (프로세스가 점유하던) 시스템 자원은 할당 해제되어 운영체제에 반환된다.
- 하지만 자식 프로세스가 종료될 때 부모 프로세스가 (자식 프로세스의) 자원을 '회수'하지 않으면, 자식 프로세스는 좀비 프로세스로 남게 된다.
- 만약 자식 프로세스가 종료된 다음 '회수' 절차 없이 부모 프로세스가 종료되는 경우, '고아' 프로세스(orphans)가 된다.
- 전통적인 UNIX 시스템은 초기화될 때 'wait' 시스템 콜을 호출해서, 기존에 남아 있던 좀비 프로세스들의 의존관계를 재설정할 수 있다(inherit).
- Linux의 경우에는 'systemd' 명령어(시스템 콜)를 사용해서 'wait'과 동일한 효과를 낼 수 있다.

### 3.3.2.1. 안드로이드 프로세스 계층
- 안드로이드는 프로세스에 '우선 순위(importance hierarchy)'를 설정해서, 프로세스 강제 종료가 필요한 경우 중요하지 않은 프로세스부터 종료시킨다.
- 시스템이 재구성(reclaim)되어야하는 경우, 안드로이드는 먼저 빈 프로세스를 제거하고, 그 다음으로 백그라운드 프로세스를 제거한다.
- 안드로이드 개발 시에는 프로세스 라이프 사이클 가이드라인을 준수해야 한다. 라이프사이클을 적절히 따르는 경우 프로세스가 불필요하게 죽는 현상을 방지하고, 사용자가 앱 화면을 잠깐 다른 곳으로 돌렸을 때도 기존에 저장되었던 데이터를 기반으로 프로세스가 복구될 수 있다.

# 3.4. 프로세스 간 통신(IPC)
- IPC를 사용하는 이유는 정보 공유, 컴퓨팅 속도 향상, 모듈화를 추구하기 위함이다.
- IPC는 일반적으로 공유 메모리와 메시지 통신(message passing) 방식으로 구현된다.
- 공유 메모리를 사용한 IPC의 경우 공유된 메모리 영역을 사용한 통신 절차가 필요하다.
- 다른 프로세스도 공유 메모리를 통해 통신하고 싶다면, 공유된 메모리 영역에 먼저 접근해야 한다.
- 한편 운영체제는 한 프로세스가 점유한 메모리에 다른 프로세스가 함부로 점유하지 못하도록 막는다.
- 공유된 메모리는 운영체제의 제어 영역 밖에서 이루어지며, 동시에 같은 메모리 영역에 write를 시도하지 않도록 해야 한다.
