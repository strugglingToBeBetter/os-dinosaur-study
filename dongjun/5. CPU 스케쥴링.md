## 5.1 Basic Concepts (기본 개념)
- 목적: 단일 코어 시스템에서는 한 번에 하나의 프로세스만 실행될 수 있습니다. 다중 프로그래밍(Multiprogramming)의 목적은 CPU 이용률(Utilization)을 극대화하기 위해 항상 어떤 프로세스든 실행되도록 유지하는 것입니다.  

### 5.1.1 CPU-I/O Burst Cycle (CPU-I/O 버스트 사이클)
- 프로세스 실행은 CPU 실행(CPU burst)과 I/O 대기(I/O burst)의 교대 상태(Cycle)로 구성됩니다.  
- 짧은 CPU 버스트가 많이 발생하는 I/O-bound 프로그램과 긴 CPU 버스트가 적게 발생하는 CPU-bound 프로그램으로 나뉩니다.  

\* 버스트: 정해진 시간/구간 동안 집중적으로 작업을 처리한다는 의미 같다.

### 5.1.2 CPU Scheduler (CPU 스케줄러)
- CPU가 유휴(Idle) 상태가 될 때마다 운영체제는 준비 큐(Ready queue)에 있는 프로세스 중 하나를 선택하여 CPU를 할당합니다.  

### 5.1.3 Preemptive and Nonpreemptive Scheduling (선점 및 비선점 스케줄링)
- 스케줄링 발생 조건 4가지:
1) 실행(Running) -> 대기(Waiting) 상태 전환 (예: I/O 요청)  
2) 실행(Running) -> 준비(Ready) 상태 전환 (예: 인터럽트 발생)  
3) 대기(Waiting) -> 준비(Ready) 상태 전환 (예: I/O 완료)  
4) 프로세스 종료(Termination)

- 비선점형 (Nonpreemptive / Cooperative): 조건 1, 4에서만 스케줄링이 발생합니다. 한 프로세스가 CPU를 할당받으면 스스로 종료하거나 대기 상태가 될 때까지 CPU를 독점합니다. 
- 선점형 (Preemptive): 조건 2, 3에서도 스케줄링이 발생합니다. OS가 실행 중인 프로세스로부터 CPU를 강제로 회수할 수 있으며, 데이터 경쟁(Race condition)이나 커널 설계 시 유의해야 합니다. (현대 대부분 OS는 선점형 사용)  

### 5.1.4 Dispatcher (디스패처)
- CPU 스케줄러가 선택한 프로세스에게 CPU 제어권을 실제로 넘겨주는 모듈입니다.  
- 문맥 교환(Context switch), 사용자 모드 전환, 프로그램 적절한 위치로 이동 등의 작업을 수행합니다.  
- Dispatch Latency: 한 프로세스를 중지하고 다른 프로세스를 실행 개시할 때까지 걸리는 시간입니다.  

\* 프로세스가 자발적(voluntary)으로 CPU 제어권을 반납하는 경우가 있고, 비자발적으로 회수당하기도 한다(nonvoluntary). 비자발적으로 CPU 자원을 회수당하는 예시로 인터럽트가 있다.

## 5.2 Scheduling Criteria (스케줄링 기준)
- 스케줄링 알고리즘의 성능을 비교하기 위해 사용하는 5가지 주요 기준입니다.  
1) CPU Utilization (CPU 이용률): CPU가 실제로 작동하는 시간의 비율 (최대화 권장).  
2) Throughput (처리량): 단위 시간당 완료되는 프로세스의 수 (최대화 권장).  
3) Turnaround Time (반환 시간): 프로세스가 제출된 시점부터 실행, 대기, I/O를 포함해 최종 완료될 때까지 걸린 전체 시간 (최소화 권장).  
4) Waiting Time (대기 시간): 프로세스가 준비 큐(Ready queue)에서 대기하며 보낸 시간의 총합 (최소화 권장).  
5) Response Time (응답 시간): 대화형 시스템에서 요청 제출 후 첫 번째 응답이 나올 때까지 걸리는 시간 (최소화 권장).  

## 5.3 Scheduling Algorithms (스케줄링 알고리즘)

### 5.3.1 First-Come, First-Served (FCFS) Scheduling
- 가장 단순한 방식으로, CPU를 먼저 요청한 프로세스에게 먼저 할당합니다 (FIFO 큐 사용).  
- 비선점형(Nonpreemptive) 방식입니다.  
- 단점 - 호위 효과 (Convoy Effect): 소요 시간이 긴 CPU-bound 프로세스가 앞에 오면, 뒤따르는 짧은 I/O-bound 프로세스들이 오랜 시간 대기하게 되어 전체 평균 대기 시간이 길어지는 현상이 발생합니다.  

### 5.3.2 Shortest-Job-First (SJF) Scheduling
- 다음 CPU 버스트 길이가 가장 짧은 프로세스에게 CPU를 먼저 할당합니다.  
- 최적성(Optimal): 주어진 프로세스 집합에 대해 최소 평균 대기 시간을 보장함이 증명되어 있습니다.  
- 한계: 다음 CPU 버스트의 정확한 길이를 사전에 알 수 없습니다. (이전 CPU 버스트들을 바탕으로 지수 평균(Exponential average)을 통해 예측하는 방식을 사용).  
- 선점 및 비선점 방식 존재: 선점형 SJF는 Shortest-Remaining-Time-First (SRTF)라고도 불리며, 실행 중인 프로세스의 남아있는 시간보다 더 짧은 버스트 시간을 가진 프로세스가 도착하면 CPU를 빼앗습니다.  

### 5.3.3 Round-Robin (RR) Scheduling
- FCFS 방식에 선점(Preemption)을 추가한 알고리즘으로, 대화형 시분할 시스템에 적합합니다. 
- Time Quantum (시간 할당량 / Time Slice)이라는 작은 시간 단위를 정해두고, 준비 큐를 원형 큐(Circular queue)로 다루며 순환 할당합니다.  
- 성능 변수: Time Quantum 크기에 의존합니다.  
- Quantum이 매우 크면 FCFS와 동일해집니다.  Quantum이 매우 작으면 잦은 문맥 교환(Context switch) 오버헤드가 발생하여 성능이 저하됩니다.  

### 5.3.4 Priority Scheduling (우선순위 스케줄링)
- 각 프로세스에 우선순위 숫자를 부여하고, 가장 높은 우선순위를 가진 프로세스에 CPU를 할당합니다. (SJF는 '예측 버스트 길이의 역수'를 우선순위로 두는 특수한 형태).  
- 단점 - 기아 상태 (Starvation / Indefinite Blocking): 우선순위가 낮은 프로세스가 높은 프로세스들에 밀려 영원히 실행되지 못할 수 있습니다.  
- 해결책 - 에이징 (Aging): 시스템에서 오랫동안 대기하는 프로세스의 우선순위를 시간에 따라 단계적으로 높여주는 방식입니다.  
- RR 결합: 우선순위가 같은 프로세스들끼리는 Round-Robin 방식으로 실행할 수 있습니다.  

### 5.3.5 Multilevel Queue Scheduling (다단계 큐 스케줄링)
- 프로세스 종류(예: 대화형/Foreground vs 배치/Background, 실시간, 시스템 등)에 따라 준비 큐를 여러 개로 분할하여 분리 관리합니다.  
- 각 큐는 고유한 스케줄링 알고리즘(예: Foreground는 RR, Background는 FCFS)을 가집니다.  
- 큐 사이의 스케줄링도 필요하며, 주로 고정 우선순위 선점 방식이나 타임 슬라이스 배분 방식(예: CPU 시간의 80%는 Foreground, 20%는 Background)을 사용합니다.  
- 프로세스가 들어간 큐는 고정되어 옮겨가지 않습니다.  

### 5.3.6 Multilevel Feedback Queue Scheduling (다단계 피드백 큐 스케줄링)
- 프로세스가 큐와 큐 사이를 이동할 수 있도록 유연성을 더한 방식입니다.  
- 동작 원리: CPU 시간을 많이 사용하는 프로세스는 낮을 우선순위 큐로 단계를 떨어뜨리고(Demote), 낮은 우선순위 큐에서 오래 대기한 프로세스는 높은 우선순위 큐로 에이징(Aging / Upgrade)시킵니다.  
- I/O 바운드 및 대화형 프로세스를 높은 우선순위 큐에 유지시킬 수 있는 가장 일반적이면서도 유연하지만, 설정 매개변수가 많아 복잡합니다.  

## 5.4 Thread Scheduling (스레드 스케줄링)
- 현대 운영체제에서는 프로세스가 아닌 커널 수준 스레드(Kernel-level thread)가 OS 스케줄링의 기본 단위입니다.  

\* 커널이 커널 스레드를 스케쥴링하고, 커널 스레드는 중간 관리 시스템을 스케쥴링하고, 중간 관리자는 사용자 프로세스를 스케쥴링하는 방식 같다.

### 5.4.1 Contention Scope (경쟁 범위)
- PCS (Process-Contention Scope): 다대일(Many-to-One) 및 다대다(Many-to-Many) 모델에서 스레드 라이브러리가 사용자 수준 스레드를 가용한 LWP(Lightweight Process) 상에 스케줄링할 때 사용됩니다 (동일 프로세스 내 스레드 간 CPU 경쟁).  
- SCS (System-Contention Scope): OS 커널이 커널 스레드를 물리적 CPU 코어 상에 스케줄링할 때 사용됩니다 (시스템 전체 모든 스레드 간 CPU 경쟁). (일대일 모델인 Windows, Linux 등은 SCS만 사용).  

### 5.4.2 Pthread Scheduling
- POSIX Pthreads API는 스레드 생성 시 경쟁 범위를 설정할 수 있는 API를 제공합니다.  

```
PTHREAD_SCOPE_PROCESS: PCS 스케줄링 
PTHREAD_SCOPE_SYSTEM: SCS 스케줄링 
```

- pthread_attr_setscope() 및 pthread_attr_getscope() 함수를 통해 설정 및 조회가 가능합니다. 

\* (참고: Linux 및 macOS 등의 시스템은 PTHREAD_SCOPE_SYSTEM만 지원합니다).  

## 5.5. 다중 처리기 스케쥴링
- 단일 코어와 달리 다중 CPU 환경에서는 로드 공유(Load sharing)가 가능해지지만 스케줄링 구조가 훨씬 복잡해집니다.  

### 5.5.1 Approaches to Multiple-Processor Scheduling (다중 처리기 스케줄링 접근 방식)
- 비대칭 다중 처리 (Asymmetrical Multiprocessing): 하나의 주 처리기(Master server)가 모든 스케줄링, I/O, 시스템 활동을 처리하고 나머지는 사용자 코드만 실행합니다. 데이터 공유 필요성이 적어 구조가 단순하지만, 마스터 서버가 병목 지점이 될 수 있습니다.  
- 대칭 다중 처리 (Symmetric Multiprocessing, SMP): 각 프로세서가 스스로 스케줄링을 수행합니다.  
- 공통 준비 큐 (Common Ready Queue): 모든 스레드가 하나의 큐에 존재합니다. 동시 접근 시 경쟁 상태(Race condition)가 발생하므로 락(Locking)이 필요하며 병목이 생길 수 있습니다.  
- 프로세서별 전용 큐 (Per-core Run Queues): 각 프로세서가 자신만의 큐를 가집니다. 경합이 줄어들고 캐시 효율이 높아져 현대 OS(Linux, Windows, macOS 등)에서 주로 사용됩니다.  

### 5.5.2 Multicore Processors (다중 코어 프로세서)
- 하나의 물리적 칩에 여러 계산 코어를 배치하여 논리적 CPU처럼 동작하게 합니다.  
- 메모리 스톨 (Memory Stall): 프로세서가 메모리 데이터 접근이나 캐시 미스(Cache miss)로 인해 대기하며 시간을 허비하는 현상입니다.  
- 칩 다중 스레딩 (Chip Multithreading, CMT): 메모리 스톨 시 다른 하드웨어 스레드로 전환하여 효율을 높입니다. (Intel의 하이퍼스레딩/SMT).  
- Coarse-grained: 메모리 스톨 같은 긴 지연 이벤트 발생 시 스레드 전환 (파이프라인 플러시 오버헤드 존재).  
- Fine-grained: 명령어 경계 단위로 촘촘하게 전환하는 방식.  

#### 2단계 스케줄링 (Two Levels of Scheduling):
- 1단계 (OS 레벨): 소프트웨어 스레드를 하드웨어 스레드(논리 CPU)에 할당.  
- 2단계 (하드웨어 레벨): 각 코어가 어떤 하드웨어 스레드를 실행할지 결정 (Round-Robin 또는 우선순위 이벤트 기반).  

### 5.5.3 Load Balancing (부하 균등화, 로드 밸런싱)
- 프로세서별 전용 큐를 사용할 때 특정 코어만 과부하가 걸리는 것을 방지하기 위해 작업량을 균등하게 배분합니다.  
- Push Migration: 별도의 작업이 주기적으로 부하를 체크하여 과부하된 코어에서 한가한 코어로 스레드를 이동시킵니다.  
- Pull Migration: 유휴 상태가 된 프로세서가 바쁜 프로세서의 대기 스레드를 가져옵니다.  

\* 웹 서버의 로드 밸런싱 개념처럼 작업이나 스레드를 여유가 있는 CPU에 적절히 할당하는 알고리즘이 있는 것 같다.

### 5.5.4 Processor Affinity (프로세서 친화성)
- 프로세스는 자신이 실행되던 프로세서의 캐시에 데이터가 남아있어(Warm cache) 계속 동일한 프로세서에서 실행되는 것을 선호합니다.  
- Soft Affinity: OS가 동일 프로세서 할당을 노력하지만 부하 균등화를 위해 다른 코어로 이동을 허용합니다.  
- Hard Affinity: 시스템 콜(예: sched_setaffinity())을 통해 프로세스가 실행될 프로세서 집합을 명시적으로 지정합니다.  
- NUMA 영향: NUMA(비균일 메모리 접근) 구조에서는 CPU가 자신의 로컬 메모리에 접근하는 것이 빠르므로, 메모리 배치와 CPU 스케줄링이 함께 고려되어야 합니다. (부하 균등화와 프로세서 친화성은 서로 상충하는 관계임).  

### 5.5.5 Heterogeneous Multiprocessing (이종 다중 처리, HMP)
- 명령어 집합은 동일하지만 클록 속도와 전력 소비가 다른 코어를 혼용하는 구조입니다 (예: ARM의 big.LITTLE).  
- 백그라운드/긴 실행 작업은 전력 효율이 높은 LITTLE 코어에, 대화형/고성능 작업은 big 코어에 할당하여 전력 관리를 최적화합니다. 

## 5.6 Real-Time CPU Scheduling (실시간 CPU 스케줄링)
- Soft Real-Time: 중요한 실시간 프로세스에 높은 우선순위를 주지만, 언제 스케줄링될지 엄격한 시간 보장은 없습니다.  
- Hard Real-Time: 반드시 마감시간(Deadline) 내에 서비스를 완료해야 하며, 실패 시 작업 자체가 무의미해집니다.  

\* 하드 리얼 타임의 경우 타임아웃이 발생하면 시스템 실패로 간주되어, 강제 리셋 등의 절차를 거칠 수 있다.

### 5.6.1 Minimizing Latency (지연 시간 최소화)
- Interrupt Latency: 인터럽트 발생부터 ISR(인터럽트 서비스 루틴) 시작까지 걸리는 시간.  
- Dispatch Latency: 스케줄러가 기존 프로세스를 멈추고 새 프로세스를 시작할 때까지 걸리는 시간. (선점형 커널을 사용하여 낮춤). 

### 5.6.2 Priority-Based Scheduling (우선순위 기반 스케줄링)
- 실시간 OS의 핵심이며, 선점형 우선순위 알고리즘을 사용합니다.  주기적 프로세스(Periodic task)의 특성: 주기 $p$, 실행 시간 $t$, 마감시간 $d$ ($0 \le t \le d \le p$).  수락 제어 (Admission-Control): 마감시간 내 완수를 보장할 수 있는 요청만 승인하고 나머지는 거절합니다.  

### 5.6.3 Rate-Monotonic Scheduling (RMS)
- 정적 우선순위 선점형 알고리즘으로, 주기($p$)가 짧을수록 높은 우선순위를 부여합니다.  
- 정적 우선순위 알고리즘 중 최적(Optimal)이지만, CPU 이용률 한계가 존재합니다.

\* ($N$개 프로세스 시 최악의 CPU 이용률 상한: $N(2^{1/N}-1)$, $N\rightarrow\infty$일 때 약 69%). 

### 5.6.4 Earliest-Deadline-First (EDF) Scheduling
- 마감시간이 가장 가까운 프로세스에 가장 높은 우선순위를 동적으로 부여합니다.  
- 프로세스가 주기적이지 않아도 적용 가능하며, 이론적으로 CPU 이용률 100%까지 스케줄링할 수 있는 최적 알고리즘입니다.  

### 5.6.5 Proportional Share Scheduling (비율 배분 스케줄링)
- 전체 $T$개의 지분(Share) 중 각 애플리케이션에 $N$개 지분을 할당하여 전체 CPU 시간의 $N/T$를 보장합니다. 수락 제어 정책과 함께 작동합니다.  

### 5.6.6 POSIX Real-Time Scheduling
- POSIX.1b 표준에서 정의하는 실시간 스레드 클래스:

```
SCHED_FIFO: 동일 우선순위 간 타임 슬라이싱이 없는 FCFS.  
SCHED_RR: 동일 우선순위 간 타임 슬라이싱을 제공하는 Round-Robin.  
```

## 5.7 Operating-System Examples (운영체제 사례)

### 5.7.1 Example: Linux Scheduling
- 과거 $O(1)$ 스케줄러를 거쳐 Version 2.6.23부터 CFS (Completely Fair Scheduler)가 기본 알고리즘으로 채택되었습니다.  
- CFS (Completely Fair Scheduler):
```
고정 타임 슬라이스 대신 nice 값(-20 ~ +19)을 기반으로 CPU 처리 시간의 비율을 할당합니다.  
vruntime(가상 실행 시간)을 기록하여 vruntime이 가장 작은 작업을 다음에 실행할 프로세스로 선택합니다.  
실행 가능한 프로세스들은 레드-블랙 트리(Red-Black Tree) 구조로 관리되어 $O(\log N)$ 시간에 탐색 및 삽입됩니다.  
```

- 실시간 스케줄링: POSIX 기반으로 0~99 범위의 정적 우선순위를 사용하며, 일반 프로세스(100~139)보다 높은 우선순위를 가집니다.  
- 스케줄링 도메인 (Scheduling Domains): 계층적 도메인 구조(L1/L2/L3 캐시 공유 단위 및 NUMA 노드)를 파악하여 캐시 오버헤드를 줄이면서 NUMA 인식 부하 균등화를 수행합니다.  

### 5.7.2 Example: Windows Scheduling
- 32단계 우선순위 기반 선점형 스케줄러 (Dispatcher):
- 1~15는 가변 클래스 (Variable class - I/O 대기 해제 시 우선순위 승격/Boost 적용)이며,  16~31은 실시간 클래스 (Real-time class).  
- User-Mode Scheduling (UMS): 커널 개입 없이 사용자 모드에서 다수의 스레드를 생성/관리하여 효율성을 높입니다 (C++ ConcRT 라이브러리 등에서 활용).  
- SMT 세트 및 이상적 프로세서 (Ideal Processor): 로드 분산을 위해 프로세스별 Seed 값을 기반으로 스레드의 이상적 프로세서를 주기적으로 배분합니다.  

### 5.7.3 Example: Solaris Scheduling
- 6개의 스케줄링 클래스(TS, IA, RT, SYS, FSS, FP)를 운영하며 클래스별 우선순위를 전역 우선순위(Global priority 0~169)로 변환하여 스케줄링합니다.  
- TS (Time-Sharing) / IA (Interactive): 다단계 피드백 큐를 사용하며, 우선순위가 높을수록 타임 퀀텀이 짧고, I/O 대기에서 복귀 시 우선순위를 대폭 올립니다.  
- 인터럽트 스레드(Interrupt threads)가 가장 높은 전역 우선순위(160~169)를 가집니다.  

## 5.8 Algorithm Evaluation (알고리즘 평가)
- 스케줄링 알고리즘을 선택하기 위한 평가 방법들입니다.  

### 5.8.1 Deterministic Modeling (결정론적 모델링)
- 사전 정의된 특정 워크로드를 입력으로 두고 각 알고리즘의 대기 시간, 반환 시간 등을 정확히 계산하여 비교하는 분석적 평가 방식입니다. 
- 단순하고 빠르지만 입력값에 의존적입니다.  

### 5.8.2 Queueing Models (큐잉 모델)
- CPU 및 I/O 버스트의 확률 분포와 프로세스 도착 비율을 수학적 수학식(큐잉 네트워크 분석)으로 모델링합니다.  
- 리틀의 공식 (Little's Formula): $n = \lambda \times W$ (평균 큐 길이 $n$, 평균 도착률 $\lambda$, 평균 대기시간 $W$).  

### 5.8.3 Simulations (시뮬레이션)
- 컴퓨터 시스템의 모델 프로그램을 작성하여 난수 생성기나 추적 파일(Trace file, 실제 시스템의 이벤트 기록)을 입력으로 주어 통계 데이터를 수집·평가합니다.  

### 5.8.4 Implementation (구현)
- 실제 운영체제 코드에 알고리즘을 직접 구현하고 가상 머신이나 실제 환경에서 측정하는 가장 정확한 방법입니다. 
- 구현 비용이 비싸고 환경 변화 및 사용자 행동 변형 위험이 있습니다.  

\* 직접 만드는 것보다 이미 만들어진/구현된 것을 가져와서 쓰는 게 더 효율적이라는 의미 같다.

## 5.9 Summary (요약)
- CPU 스케줄링: 준비 큐에서 대기 중인 프로세스를 선택하고 디스패처를 통해 CPU를 할당하는 작업입니다.  
- 선점 및 비선점: 현대 대부분 OS는 강제로 CPU를 회수할 수 있는 선점형(Preemptive) 스케줄링을 사용합니다.  
- 평가 기준: CPU 이용률, 처리량, 반환 시간, 대기 시간, 응답 시간 등 5가지 기준을 바탕으로 평가합니다.  
- 알고리즘 요약: FCFS, SJF(최적 대기시간), Round-Robin, 우선순위, 다단계 큐, 다단계 피드백 큐 등이 존재합니다.  
- 다중 코어 & 실시간 스케줄링: 부하 균등화와 프로세서 친화성 간의 절충이 중요하며, 실시간 환경에서는 RMS 및 EDF 같은 마감시간 보장 알고리즘이 쓰입니다.  
- 현대 OS 스케줄러: Linux는 CFS(Red-Black Tree 기반 vruntime 관리), Windows는 32단계 우선순위 기반 디스패처, Solaris는 전역 우선순위 변환 매핑 체계를 사용합니다.
