## 2.1. 운영체제 서비스

#### 사용자 편의 및 프로그램 실행을 돕는 서비스

* **사용자 인터페이스 (User Interface, UI):** 거의 모든 운영체제는 어떤 형태로든 UI를 제공합니다.
  * **GUI (Graphical User Interface):** 마우스(포인팅 장치), 윈도우 시스템, 메뉴, 키보드를 활용한 인터페이스.
  * **터치스크린 인터페이스 (Touch-Screen Interface):** 스마트폰, 태블릿 등 모바일 기기에서 손가락 제스처(슬라이드, 터치) 및 가상 키보드를 사용하는 인터페이스.
  * **CLI (Command-Line Interface):** 특정 형식과 옵션을 가진 텍스트 명령어를 직접 입력하는 인터페이스.
* **프로그램 실행 (Program Execution):** 시스템은 프로그램을 메모리에 로드(Load)하고 실행(Run)할 수 있어야 합니다. 프로그램은 정상적이든 비정상적이든(오류 표시) 실행을 끝마칠 수 있어야 합니다.
* **I/O 연산 (I/O Operations):** 실행 중인 프로그램은 파일이나 입출력 장치(Network, Disk 등)를 필요로 합니다. 효율성과 보안(보호)을 위해 사용자는 I/O 장치를 직접 제어할 수 없으므로, 반드시 운영체제를 거쳐 I/O를 수행해야 합니다.
* **파일 시스템 조작 (File-System Manipulation):** 프로그램은 파일과 디렉터리를 읽고 써야 하며, 이름으로 파일을 생성/삭제하고, 검색하고, 파일 정보를 나열할 수 있어야 합니다. 권한 관리(Permissions Management)를 통해 접근을 허용하거나 거부하는 기능도 포함됩니다.
* **통신 (Communications):** 한 프로세스가 다른 프로세스와 정보를 교환해야 하는 상황에서 사용됩니다.
  * **공유 메모리 (Shared Memory):** 둘 이상의 프로세스가 메모리의 동일한 영역을 읽고 쓰는 방식.
  * **메시지 전달 (Message Passing):** 운영체제에 의해 미리 정의된 형태의 정보 패킷(Packet)이 프로세스 간에 이동하는 방식.
* **오류 탐지 (Error Detection):** 운영체제는 항상 오류를 탐지하고 수정해야 합니다. 오류는 CPU/메모리 하드웨어(메모리 에러, 정전), I/O 장치(디스크 패리티 에러, 네트워크 연결 실패, 프린터 용지 부족), 사용자 프로그램(산술 오버플로우, 잘못된 메모리 주소 접근 시도) 등 어디서나 발생할 수 있으며, 시스템의 일관성을 위해 적절한 조치(오류 코드 반환, 프로세스 강제 종료, 시스템 멈춤 등)를 취합니다.

#### 시스템 자체의 효율적 운영을 위한 서비스

* **자원 할당 (Resource Allocation):** 다중 프로세스가 동시에 실행될 때, 각각에 자원을 할당해야 합니다. CPU 사이클, 메인 메모리, 파일 저장소 등에는 특수한 할당 코드가 사용되며, 일반 I/O 장치 관리를 위한 요청 및 해제 코드도 존재합니다. (예: CPU 스케줄링 라우틴).
* **로깅 (Logging):** 어떤 사용자가 어떤 종류의 컴퓨터 자원을 얼마나 사용했는지 추적하고 기록합니다. 과금 목적이나 시스템 관리자의 시스템 성능 개선을 위한 통계 자료로 활용됩니다.
* **보호 및 보안 (Protection and Security):** 다중 사용자 또는 네트워크 컴퓨터 시스템에서 정보 자원을 통제합니다.
  * **보호 (Protection):** 시스템 자원에 대한 모든 접근이 통제되도록 보장하는 것 (프로세스 간 간섭 차단).
  * **보안 (Security):** 외부의 잘못된 접근 시도로부터 시스템을 방어하는 것 (사용자 인증, 비밀번호, 네트워크 어댑터 방어, 침입 탐지 로그 기록 등).
  * *"사슬은 가장 약한 고리만큼만 강하다(A chain is only as strong as its weakest link)."*

## 2.2. 사용자 및 운영체제 인터페이스 (User and OS Interface)

### 2.2.1. 명령 인터프리터 (Command Interpreters / Shells)
* 운영체제(Linux, UNIX, Windows 등)에서 사용자가 직접 텍스트 명령을 입력하여 실행할 수 있도록 지원하는 특수한 프로그램입니다.
* 여러 개의 명령 인터프리터를 선택할 수 있는 시스템에서 이를 **쉘(Shell)**이라고 부릅니다. (예: UNIX/Linux의 `bash`, `csh`, `ksh` 등).
* **명령어 구현의 두 가지 접근 방식:**
  1. **내부 코드 방식:** 명령 인터프리터 프로그램 자체 내에 명령어를 실행하는 코드가 포함된 방식. 명령어가 많아질수록 인터프리터 파일의 크기가 커집니다.
  2. **시스템 프로그램 방식 (UNIX/Linux 방식):** 명령 인터프리터는 명령의 의미를 자체적으로 이해하지 못합니다. 단지 사용자가 입력한 명령 단어와 일치하는 이름의 파일(시스템 프로그램)을 메모리로 로드하여 실행할 뿐입니다.
     * 예: `rm file.txt` 입력 시, 인터프리터는 `rm`이라는 파일을 찾아 메모리에 올리고 `file.txt`를 매개변수로 넘깁니다. 이 방식은 인터프리터의 크기를 작게 유지할 수 있으며, 새로운 명령어를 파일 형태로 쉽게 추가할 수 있다는 강력한 장점이 있습니다.

### 2.2.2. 그래픽 사용자 인터페이스 (Graphical User Interface, GUI)
* 데스크톱 메타포(Desktop Metaphor)를 기반으로 창, 메뉴, 아이콘을 활용하여 마우스 등으로 조작하는 직관적인 인터페이스입니다.
* 1970년대 Xerox PARC에서 최초 연구 및 개발(`Xerox Alto`, 1973년)되었고, 1980년대 `Apple Macintosh`를 통해 대중화되었습니다.
* Windows 1.0은 초기 MS-DOS 위에 GUI 레이어를 추가하는 방식으로 시작되었습니다. UNIX/Linux 진영에서도 오픈소스 프로젝트인 `KDE`, `GNOME` 등을 통해 발전해왔습니다.

### 2.2.3. 터치스크린 인터페이스 (Touch-Screen Interface)
* 모바일 기기(스마트폰, 태블릿 등)에 최적화된 인터페이스로, 마우스와 키보드 대신 손가락 제스처(누르기, 스와이프 등)를 사용합니다. (예: Apple iOS의 `Springboard` 인터페이스). 가상 키보드를 화면에 시뮬레이션하여 텍스트 입력을 지원합니다.

### 2.2.4. 인터페이스의 선택 (Choice of Interface)
* **CLI:** 시스템 관리자 및 파워 유저들이 선호합니다. 효율적이고 전 기능에 빠른 접근이 가능하며, 쉘 스크립트(Shell Script, 명령어들을 파일에 기록하여 프로그램처럼 해석·실행하는 방식)를 통해 반복적인 작업을 쉽게 자동화할 수 있습니다.
* **GUI:** 일반 사용자들이 주로 선호합니다. Windows 사용자들은 거의 대부분 GUI 환경을 사용합니다.
* **하이브리드:** macOS의 경우 사용자 친화적인 데스크톱 GUI(Aqua)를 제공하는 동시에, 하부 커널이 UNIX 기반이기 때문에 강력한 command-line 쉘 인터페이스도 함께 제공합니다.

## 2.3. 시스템 콜 (System Calls)

**시스템 콜(System Call)은 운영체제가 제공하는 커널 서비스에 접근할 수 있도록 하는 프로그램적 인터페이스입니다. 주로 C/C++ 언어로 작성되어 제공되며, 하드웨어 직접 제어와 같은 저수준 작업에는 일부 어셈블리 명령어가 결합됩니다.

### 2.3.1 시스템 콜 실행 흐름 예시 (파일 복사 프로그램)
단순히 소스 파일에서 데스틴이션 파일로 데이터를 복사하는 단순한 프로그램조차도 내부적으로는 수많은 시스템 콜을 연속적으로 수행합니다.

1. **사용자 입력 획득:** 화면에 프롬프트 출력(시스템 콜), 키보드로부터 입력 파일명 및 출력 파일명 획득(시스템 콜).
2. **파일 오픈 및 생성:** 입력 파일 오픈(시스템 콜). 파일이 없으면 에러 메시지 출력 후 비정상 종료(시스템 콜). 출력 파일 생성 및 오픈(시스템 콜). 기존 파일이 존재하면 유저에게 덮어쓸지 확인(시스템 콜).
3. **복사 루프 작업:** 입력 파일로부터 버퍼로 읽기(시스템 콜), 버퍼에서 출력 파일로 쓰기(시스템 콜). 파일의 끝(EOF)을 만날 때까지 반복. 읽기/쓰기 오류 상태 확인.
4. **종료 작업:** 두 파일 닫기(시스템 콜), 완료 메시지 출력(시스템 콜), 정상 종료 처리(시스템 콜).

### 2.3.2 응용 프로그래밍 인터페이스 (Application Programming Interface, API)
실제 응용 프로그래머들은 개별 시스템 콜의 복잡한 세부 사항을 직접 다루기보다 **API**를 기반으로 개발합니다. API는 개발자가 사용할 수 있는 함수 집합과 매개변수, 반환값 명세를 정의해 둔 것입니다.

* **대표적인 3대 API:**
  * **Windows API:** Windows 시스템용 API
  * **POSIX API:** POSIX 기반 시스템(UNIX, Linux, macOS 등 거의 모든 유닉스 계열)용 API
  * **Java API:** 자바 가상 머신(JVM) 위에서 실행되는 프로그램을 위한 API
* **API를 사용하는 이유:**
  1. **프로그램 이식성 (Portability):** 동일한 API 표준을 준수하는 운영체제라면 소스 코드 변경 없이 컴파일하여 부드럽게 실행할 수 있습니다.
  2. **사용 용이성:** 커널 내부의 원시 시스템 콜은 직접 호출하기에 매우 까다롭고 복잡하지만, API 함수는 이를 추상화하여 단순화시켜 둡니다.

#### 런타임 환경 (Run-Time Environment, RTE)과 시스템 콜 인터페이스
* **RTE**는 프로그램 실행에 필요한 컴파일러, 인터프리터, 라이브러리, 로더 등을 포괄하는 소프트웨어 수트입니다.
* RTE는 **시스템 콜 인터페이스(System-call Interface)**를 포함하고 있으며, 이는 API 함수 호출을 가로채어 커널 내부의 실제 시스템 콜로 연결하는 다리 역할을 합니다.
* 운영체제 내부의 각 시스템 콜에는 고유한 **번호(Number)**가 부여되어 있습니다. 시스템 콜 인터페이스는 이 번호표를 인덱스로 하는 테이블을 관리하며, 해당 시스템 콜을 호출한 뒤 실행 상태 및 반환값을 사용자 앱으로 돌려줍니다.

#### 🛠️ 운영체제 매개변수 전달 방식 (Passing Parameters)
시스템 콜을 호출할 때 추가적인 정보(예: 읽을 파일, 데이터 저장 버퍼 주소, 데이터 길이 등)를 커널에 넘겨주어야 합니다. 대표적인 3가지 방식이 있습니다.

1. **레지스터(Register) 방식:** 가장 간단한 방식으로, 매개변수 값을 CPU 레지스터에 직접 넣어서 넘겨줍니다. 레지스터 개수가 부족하면 매개변수 개수에 제한을 받습니다.
2. **블록 / 테이블 (Block / Table) 방식:** 매개변수들을 메모리 안의 블록이나 테이블에 한데 모아 저장하고, 그 블록의 **시작 주소(Address)**를 레지스터에 담아 넘겨주는 방식입니다. 매개변수의 개수나 길이에 제한을 받지 않습니다. (Linux가 매개변수 5개 초과 시 사용하는 방식)
3. **스택 (Stack) 방식:** 프로그램이 필요한 매개변수들을 메모리상의 스택(Stack) 영역에 푸시(Push)해두면, 운영체제 커널이 이를 팝(Pop)하여 가져가는 방식입니다. 역시 개수 제한이 없습니다.

### 2.3.3 시스템 콜의 주요 유형과 대응 예시

운영체제가 제공하는 시스템 콜은 크게 6가지 카테고리로 분류할 수 있습니다.

| 분류 | 주요 기능 | Windows API 대치 예시 | UNIX/Linux (POSIX) 대치 예시 |
| :--- | :--- | :--- | :--- |
| **프로세스 제어**<br>*(Process Control)* | 종료(end), 비정상 종료(abort)<br>로드(load), 실행(execute)<br>프로세스 생성/종료<br>속성 가져오기/설정<br>이벤트 대기, 신호 알림<br>메모리 할당 및 해제 | `CreateProcess()` <br> `ExitProcess()` <br> `WaitForSingleObject()` | `fork()` <br> `exit()` <br> `wait()` |
| **파일 관리**<br>*(File Management)* | 파일 생성/삭제<br>열기(open), 닫기(close)<br>읽기(read), 쓰기(write)<br>위치 재지정(reposition)<br>파일 속성 가져오기/설정 | `CreateFile()` <br> `ReadFile()` <br> `WriteFile()` <br> `CloseHandle()` | `open()` <br> `read()` <br> `write()` <br> `close()` |
| **장치 관리**<br>*(Device Management)* | 장치 요청(request)/해제(release)<br>읽기, 쓰기, 위치 재지정<br>장치 속성 가져오기/설정<br>논리적 장치 부착/분리 | `SetConsoleMode()` <br> `ReadConsole()` <br> `WriteConsole()` | `ioctl()` <br> `read()` <br> `write()` |
| **정보 유지**<br>*(Information Maintenance)* | 시간/날짜 가져오기 및 설정<br>시스템 데이터 가져오기 및 설정<br>프로세스/파일/장치 속성 설정 | `GetCurrentProcessID()` <br> `SetTimer()` <br> `Sleep()` | `getpid()` <br> `alarm()` <br> `sleep()` |
| **통신**<br>*(Communications)* | 통신 연결 생성/삭제<br>메시지 송수신<br>상태 정보 전달<br>원격 장치 부착/분리 | `CreatePipe()` <br> `CreateFileMapping()` <br> `MapViewOfFile()` | `pipe()` <br> `shm_open()` <br> `mmap()` |
| **보호**<br>*(Protection)* | 파일/자원 권한 설정 및 획득<br>사용자 접근 허용/거부 조절 | `SetFileSecurity()` <br> `InitializeSecurityDescriptor()` | `chmod()` <br> `umask()` <br> `chown()` |

#### 💡 싱글태스킹과 멀티태스킹의 구체적 예시
* **Arduino (싱글태스킹 임베디드 시스템):** 운영체제가 없거나 매우 단순한 구조입니다. PC에서 컴파일한 프로그램(스케치, Sketch)을 USB를 통해 보드의 플래시 메모리에 업로드하면, **부트 로더(Boot Loader)**가 이를 특정 메모리 영역에 올립니다. 메모리에는 단 하나의 스케치만 상주할 수 있으며, 새 프로그램이 들어오면 기존 것을 완전히 대체합니다.
* **FreeBSD (멀티태스킹 유닉스 시스템):** 사용자가 로그인하면 선택한 쉘(인터프리터)이 실행되어 대기합니다. 사용자가 명령을 내리면 `fork()` 시스템 콜을 통해 프로세스를 복제하고, 복제된 자식 프로세스 위에 `exec()` 시스템 콜을 호출하여 새 프로그램을 덮어씌워 실행합니다. 이 동안 쉘은 프로세스가 끝나기를 기다리거나, 혹은 백그라운드(Background)로 돌려놓고 곧바로 다음 사용자 명령을 받을 수 있습니다. 프로그램이 끝나면 `exit()`를 호출하여 상태 코드(정상: 0, 에러: 0이 아닌 값)를 부모 프로세스(쉘)에 반환합니다.

#### 🔄 두 가지 interprocess communication(IPC) 모델 비교
1. **메시지 전달 (Message-passing) 모델:**
   * 프로세스들이 메시지 박스나 채널을 통해 패킷 형태로 정보를 주고받습니다.
   * 통신 전 `open_connection()` 혹은 daemons(시스템 대기 서비스)를 향한 `accept_connection()` 단계가 필요합니다.
   * **장점:** 충돌 위험이 없어 소량의 데이터 교환에 안전하며, 네트워크로 연결된 다른 컴퓨터 간 분산 통신 구현이 매우 쉽습니다.
2. **공유 메모리 (Shared-memory) 모델:**
   * 운영체제가 본래 강제하는 "프로세스 간 메모리 접근 금지" 제한을 `shared_memory_create()` 및 `shared_memory_attach()` 시스템 콜을 통해 명시적으로 해제하여 특정 영역을 함께 사용합니다.
   * **장점:** 통신이 메모리 버스 전송 속도로 처리되므로 속도가 극도로 빠릅니다.
   * **단점:** 여러 프로세스가 동일 공간을 동시에 쓰려고 할 때 발생하는 동기화(Synchronization) 및 보호 문제를 프로그래머가 직접 제어해야 하므로 복잡합니다.

## 2.4. 시스템 서비스 (System Services / Utilities)

시스템 서비스(System Services) 혹은 **시스템 유틸리티(System Utilities)**는 프로그램 개발과 실행을 위해 사용자에게 더 편리한 환경을 직접 제공하는 소프트웨어 계층입니다. 단순히 시스템 콜을 감싸고 있는 껍데기 인터페이스부터 매우 복잡한 독립 프로그램까지 다양합니다.

* **파일 관리 (File Management):** 파일 및 디렉터리를 생성, 삭제, 복사, 이름 변경, 인쇄, 나열 및 조작하는 프로그램.
* **상태 정보 (Status Information):** 날짜, 시간, 사용 가능한 메모리/디스크 공간, 사용자 수 등의 정보를 단순 포맷팅하여 출력하는 프로그램부터, 상세 성능 로깅 및 디버깅 정보를 수집하는 도구들. 시스템 구성 설정을 저장하고 복구하는 **레지스트리(Registry)** 관리 도구도 포함됩니다.
* **파일 수정 (File Modification):** 디스크에 저장된 파일 내용을 작성하고 수정하기 위한 텍스트 에디터(Text Editors) 및 텍스트 검색/변환용 특수 명령어 툴.
* **프로그래밍 언어 지원 (Programming-Language Support):** 주요 프로그래밍 언어(C, C++, Java, Python 등)를 위한 컴파일러, 어셈블러, 디버거, 인터프리터.
* **프로그램 로딩 및 실행 (Program Loading and Execution):** 컴파일이 완료된 프로그램을 실행하기 위해 메모리에 배치하는 절대 로더, 재배치 로더, 링키지 에디터(Linkage Editors), 중첩 로더 및 기계어/고급 언어용 디버깅 시스템.
* **통신 (Communications):** 프로세스, 사용자, 컴퓨터 간의 가상 연결을 생성하는 메커니즘 제공. 웹 서핑(Browsers), 이메일 전송, 원격 로그인(Remote Login), 파일 전송(FTP) 유틸리티 등.
* **백그라운드 서비스 (Background Services / Daemons):** 시스템이 부팅될 때 커널과 함께 구동되어 시스템이 꺼질 때까지 백그라운드에서 특정 감시/유지 임무를 수행하는 프로세스들입니다. 이를 **서비스(Services)**, **서브시스템(Subsystems)**, 혹은 **데몬(Daemons)이라고 부릅니다.
  * 예: 네트워크 연결 요청을 상시 대기하는 네트워크 데몬, 특정 일정에 맞추어 프로세스를 켜주는 스케줄러 데몬, 에러 모니터링 서비스, 프린트 서버 등.
