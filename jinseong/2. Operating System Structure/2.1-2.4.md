# Chapter 2. 운영체제 구조 — Part 1

## 2.1 Operating-System Services

운영체제는 하드웨어를 관리할 뿐 아니라, 사용자와 응용 프로그램이 컴퓨터를 편리하고 안전하게 사용할 수 있도록 여러 서비스를 제공한다. 이 서비스는 크게 **사용자와 프로그램의 작업을 돕는 기능**과 **시스템 자체를 효율적이고 안전하게 운영하는 기능**으로 나눌 수 있다.

### 사용자와 프로그램을 위한 서비스

**사용자 인터페이스**는 사용자가 운영체제와 상호작용하는 방법이다. 데스크톱에서는 GUI, 서버 환경에서는 CLI, 모바일 기기에서는 터치 인터페이스가 주로 사용된다. 인터페이스의 형태는 다르지만, 궁극적으로 사용자의 요청을 운영체제 기능과 연결한다.

**프로그램 실행**은 실행 파일을 메모리에 적재하고 CPU가 명령어를 실행할 수 있도록 준비하는 기능이다. 운영체제는 프로그램의 정상 종료뿐 아니라 오류로 인한 비정상 종료도 처리해야 한다.

**입출력 연산**은 파일, 키보드, 화면, 네트워크 장치 등을 사용하는 기능이다. 일반 프로그램이 하드웨어를 직접 제어하게 두면 시스템이 손상될 수 있으므로, 운영체제가 안전한 입출력 방법을 제공한다.

**파일 시스템 조작**은 파일과 디렉터리를 생성·삭제하고, 읽고 쓰며, 검색하고 권한을 관리하는 기능이다. 사용자는 파일이라는 논리적 단위를 다루지만, 실제 저장 장치의 물리적 구조는 운영체제가 처리한다.

**통신**은 프로세스들이 정보를 주고받는 기능이다. 같은 컴퓨터에서는 공유 메모리나 메시지 전달을 사용할 수 있고, 서로 다른 컴퓨터에서는 네트워크를 통해 통신할 수 있다.

**오류 탐지**는 CPU, 메모리, 저장 장치, 네트워크, 응용 프로그램에서 발생하는 오류를 감지하고 적절히 처리하는 기능이다. 운영체제는 오류 코드를 반환하거나 문제가 생긴 프로세스를 종료하고, 심각한 경우 시스템을 중단할 수도 있다.

### 시스템 운영을 위한 서비스

**자원 할당**은 여러 프로세스가 동시에 실행될 때 CPU 시간, 메모리, 파일 저장 공간, 입출력 장치를 적절히 나누어 주는 기능이다. 자원은 한정되어 있으므로 운영체제는 효율성과 공정성을 고려해야 한다.

**로깅**은 어떤 프로그램이 어떤 자원을 얼마나 사용했는지를 기록하는 기능이다. 이 기록은 성능 분석, 장애 조사, 보안 감사 등에 활용된다.

**보호와 보안**은 프로세스나 사용자가 허용되지 않은 자원에 접근하지 못하게 하는 기능이다. 보호는 시스템 내부의 접근 통제에 가깝고, 보안은 인증과 외부 공격 방어까지 포함하는 더 넓은 개념이다.

### 핵심 정리

운영체제 서비스는 사용자가 직접 사용하는 단일 프로그램을 뜻하는 것이 아니다. **운영체제가 전체적으로 제공하는 기능의 범주**를 의미한다. 프로그램 실행, 파일 관리, 통신, 자원 할당, 보호 등이 모두 운영체제 서비스에 속한다.

### 면접 포인트

**Q. 운영체제가 제공하는 대표적인 서비스는 무엇인가요?**

운영체제는 프로그램 실행, 입출력, 파일 시스템 조작, 프로세스 간 통신, 오류 탐지 등의 사용자 중심 기능을 제공한다. 또한 자원 할당, 로깅, 보호와 보안을 통해 시스템을 효율적이고 안전하게 운영한다.

## 2.2 User and Operating-System Interface

사용자나 프로그램이 운영체제를 사용하는 방식은 하나가 아니다. 일반 사용자는 GUI나 CLI를 이용하고, 응용 프로그램은 API와 시스템 콜을 통해 운영체제 기능에 접근한다.

### 명령어 인터페이스와 셸

CLI에서는 사용자가 텍스트 명령어를 입력한다. 이 명령을 읽고 해석하는 프로그램을 **명령 해석기 또는 셸**이라고 한다. Linux의 Bash, Windows의 PowerShell이 대표적인 예다.

사용자가 다음 명령을 입력했다고 하자.

```bash
rm report.txt
```

셸이 직접 파일을 삭제하는 것은 아니다. 셸은 `rm`이라는 프로그램을 찾아 실행하고, `rm` 프로그램이 운영체제의 파일 삭제 기능을 요청한다.

셸의 명령 처리 방식은 두 가지가 있다. 일부 명령은 셸 내부에 직접 구현되어 있고, 나머지는 별도의 실행 파일로 존재한다. 명령을 별도 프로그램으로 구성하면 새로운 명령을 추가하더라도 셸 자체를 수정할 필요가 적어진다.

### 그래픽 사용자 인터페이스

GUI는 창, 아이콘, 메뉴, 포인터 등을 통해 운영체제와 상호작용하게 한다. 사용자가 파일을 휴지통으로 이동하는 동작도 내부적으로는 파일 시스템 관련 요청으로 변환된다.

GUI와 CLI는 겉으로 보이는 사용 방식이 다를 뿐, 결국 운영체제가 제공하는 동일한 자원과 기능을 사용한다.

### 터치 인터페이스

모바일 환경에서는 작은 화면과 물리 키보드의 부재 때문에 터치 인터페이스가 사용된다. 탭, 스와이프, 길게 누르기 등의 동작이 프로그램 실행이나 파일 선택 등의 명령으로 해석된다.

### 핵심 정리

CLI, GUI, 터치 인터페이스는 모두 **사용자와 운영체제를 연결하는 사용자 인터페이스**다. 셸이나 GUI 프로그램은 커널 그 자체가 아니라, 운영체제 기능을 사용자가 쉽게 이용하도록 돕는 프로그램이다.

### 면접 포인트

**Q. 셸을 커널과 분리하는 이유는 무엇인가요?**

셸은 사용자 명령을 해석하는 인터페이스이고, 커널은 하드웨어와 자원을 관리한다. 둘을 분리하면 사용자가 원하는 셸로 교체할 수 있고, 명령 처리 방식을 변경해도 커널을 수정할 필요가 없어 유연성과 유지보수성이 높아진다.

## 2.3 System Calls

시스템 콜은 **실행 중인 프로그램이 운영체제 커널의 기능을 요청하는 공식 인터페이스**다.

일반 응용 프로그램은 사용자 모드에서 실행되므로 디스크, 메모리 관리 장치, 입출력 장치를 직접 제어할 수 없다. 파일을 읽거나 새로운 프로세스를 생성하려면 커널의 도움이 필요하며, 이때 시스템 콜을 사용한다.

### API와 시스템 콜의 관계

개발자가 항상 시스템 콜을 직접 작성하는 것은 아니다. 보통은 언어나 라이브러리가 제공하는 API를 호출하고, 그 내부에서 필요한 시스템 콜이 실행된다.

예를 들어 C 프로그램에서 다음 함수를 사용할 수 있다.

```c
FILE *file = fopen("data.txt", "r");
```

`fopen()`은 C 표준 라이브러리가 제공하는 함수다. 이 함수는 내부적으로 운영체제의 파일 열기 시스템 콜을 사용한다.

```text
응용 프로그램 → 라이브러리 API → 시스템 콜 인터페이스 → 커널
```

API와 시스템 콜은 항상 일대일 관계가 아니다. 하나의 API 함수가 여러 시스템 콜을 호출할 수 있고, 시스템 콜을 전혀 사용하지 않고 사용자 공간에서 처리를 끝낼 수도 있다.

### 시스템 콜의 실행 흐름

응용 프로그램이 시스템 콜을 요청하면 CPU는 사용자 모드에서 커널 모드로 전환한다. 커널은 요청 번호와 매개변수를 확인하고 작업을 수행한 뒤 결과를 반환한다. 이후 CPU는 다시 사용자 모드로 돌아와 응용 프로그램 실행을 계속한다.

시스템 콜은 일반 함수 호출보다 비용이 크다. 단순히 다른 함수로 이동하는 것이 아니라 권한 모드가 바뀌고, 커널이 요청의 유효성과 권한을 확인해야 하기 때문이다.

### 시스템 콜 매개변수 전달

시스템 콜이 작업을 수행하려면 파일 이름, 버퍼 주소, 데이터 크기와 같은 정보가 필요하다. 이러한 매개변수는 CPU 레지스터에 직접 넣거나, 메모리 블록에 저장한 뒤 주소를 전달하거나, 스택을 이용해 전달할 수 있다.

### 시스템 콜의 주요 유형

**프로세스 제어**에는 프로세스 생성, 종료, 프로그램 교체, 대기 등이 포함된다. UNIX 계열의 `fork()`, `exec()`, `wait()`, `exit()`가 대표적이다.

**파일 관리**에는 파일 생성, 열기, 읽기, 쓰기, 위치 변경, 닫기, 삭제 등이 포함된다. `open()`, `read()`, `write()`, `close()`, `unlink()` 등이 사용된다.

**장치 관리**는 장치를 요청하거나 해제하고 장치 속성을 조정하는 기능이다. 운영체제에 따라 파일 입출력과 유사한 방식으로 장치를 다루기도 한다.

**정보 유지**는 시간, 시스템 정보, 프로세스 정보, 파일 속성 등을 조회하거나 변경하는 기능이다.

**통신**은 프로세스 간 메시지 전달, 공유 메모리, 파이프, 소켓 등을 지원한다.

**보호**는 파일이나 자원에 대한 접근 권한을 조회하거나 변경하는 기능이다.

### `rm`은 시스템 콜인가?

`rm`은 시스템 콜이 아니라 **시스템 프로그램**이다. 사용자가 `rm file.txt`를 실행하면 `rm` 프로그램은 파일 정보를 확인하고, 실제 삭제를 위해 `unlink()`와 같은 시스템 콜을 호출한다.

파일 삭제라는 동일한 기능이 여러 절에서 등장하는 이유는 관점이 다르기 때문이다.

- 운영체제 서비스: 운영체제가 파일 삭제 기능을 제공한다는 기능적 관점
- 시스템 콜: 프로그램이 커널에 파일 삭제를 요청하는 저수준 인터페이스
- 시스템 프로그램: 사용자가 `rm` 명령으로 파일을 삭제하도록 만든 실행 프로그램

### 핵심 정리

시스템 콜은 사용자 프로그램과 커널 사이의 경계다. 응용 프로그램은 보통 API를 호출하고, 라이브러리가 시스템 콜 인터페이스를 통해 커널 기능을 요청한다. 시스템 콜이 실행될 때는 사용자 모드에서 커널 모드로 전환된다.

### 면접 포인트

**Q. 시스템 콜과 일반 함수 호출의 차이는 무엇인가요?**

일반 함수 호출은 같은 권한 수준과 주소 공간에서 실행되는 경우가 많다. 시스템 콜은 커널 기능을 요청하기 때문에 사용자 모드에서 커널 모드로 전환되고, 요청 검증과 권한 확인이 필요해 상대적으로 비용이 크다.

## 2.4 System Services

이 절에서 말하는 시스템 서비스는 문맥상 **시스템 프로그램 또는 시스템 유틸리티**에 가깝다. 이들은 커널 밖에서 실행되면서 사용자가 프로그램을 개발하고 실행하고 시스템을 관리할 수 있는 편리한 환경을 제공한다.

### 주요 시스템 프로그램

**파일 관리 프로그램**은 파일과 디렉터리를 생성, 삭제, 복사, 이동, 이름 변경, 출력한다. Linux의 `cp`, `mv`, `rm`, `ls`, `mkdir` 등이 해당한다.

**상태 정보 프로그램**은 날짜, 시간, 메모리 사용량, 디스크 사용량, 실행 중인 프로세스 등의 정보를 보여준다. `ps`, `top`, `df` 등이 대표적이다.

**파일 수정 프로그램**은 텍스트 편집기나 파일 내용을 검색하고 변환하는 도구를 포함한다.

**프로그래밍 언어 지원 프로그램**은 컴파일러, 어셈블러, 인터프리터, 디버거 등을 제공한다.

**프로그램 적재 및 실행 프로그램**은 실행 파일을 메모리에 적재하거나 디버깅 환경에서 실행하도록 돕는다.

**통신 프로그램**은 다른 사용자나 프로세스, 컴퓨터와 정보를 교환할 수 있도록 한다. 원격 로그인, 파일 전송, 메일, 웹 브라우저 등이 여기에 포함될 수 있다.

**백그라운드 서비스**는 부팅 과정에서 시작되어 계속 실행되는 프로그램이다. 네트워크 요청 처리, 작업 예약, 로깅 등의 기능을 담당하며 UNIX 계열에서는 흔히 데몬이라고 부른다.

### 시스템 콜과 시스템 프로그램 비교

시스템 콜과 시스템 프로그램에서 모두 파일 관리가 등장하지만, 같은 계층을 뜻하는 것은 아니다.

`unlink()`는 프로그램이 커널에 특정 파일을 삭제해 달라고 요청하는 시스템 콜이다. 반면 `rm`은 사용자가 명령어 형태로 편리하게 파일을 삭제할 수 있게 만든 시스템 프로그램이다.

```text
사용자 입력: rm report.txt
→ rm 프로그램 실행
→ unlink() 시스템 콜 요청
→ 커널이 파일 시스템을 수정
```

따라서 시스템 프로그램은 여러 시스템 콜을 조합하고, 사용자 입력 검증과 오류 메시지 같은 부가 기능을 제공한다.

### 시스템 프로그램과 응용 프로그램의 경계

시스템 프로그램과 일반 응용 프로그램의 경계는 명확하지 않을 수 있다. 웹 브라우저나 편집기가 운영체제에 기본 포함되면 시스템 프로그램처럼 느껴질 수 있지만, 커널의 필수 구성 요소는 아니다.

운영체제에서 핵심적인 구분은 다음과 같다.

- 커널: 항상 실행되며 하드웨어와 핵심 자원을 관리한다.
- 시스템 프로그램: 운영체제와 관련된 편의 기능을 제공하지만 반드시 커널의 일부는 아니다.
- 응용 프로그램: 사용자의 특정 문제를 해결한다.

### 핵심 정리

시스템 프로그램은 사용자가 운영체제 기능을 편리하게 활용하도록 만든 사용자 공간의 프로그램이다. 시스템 콜이 커널에 개별 기능을 요청하는 저수준 인터페이스라면, 시스템 프로그램은 여러 시스템 콜을 조합해 완성된 사용자 기능을 제공한다.

### 면접 포인트

**Q. 시스템 콜과 시스템 프로그램의 차이를 `rm`을 예로 설명해 보세요.**

`rm`은 사용자가 실행하는 시스템 프로그램이다. `rm`은 대상 파일과 옵션을 확인한 뒤 `unlink()`와 같은 시스템 콜을 통해 커널에 파일 삭제를 요청한다. 즉, 시스템 프로그램은 사용자에게 완성된 기능을 제공하고, 시스템 콜은 그 기능을 구현하기 위해 커널에 접근하는 인터페이스다.

# Part 1 핵심 요약

운영체제는 프로그램 실행, 입출력, 파일 시스템, 통신, 오류 처리, 자원 할당, 보호 등의 서비스를 제공한다. 사용자는 CLI·GUI·터치 인터페이스를 통해 운영체제와 상호작용한다. 응용 프로그램은 시스템 콜을 통해 커널 기능을 요청하며, 일반적으로 라이브러리 API가 그 과정을 감싼다. 시스템 프로그램은 여러 시스템 콜을 조합해 `cp`, `rm`, `ps`처럼 사용자가 직접 이용할 수 있는 기능을 제공한다.

```text
사용자
→ CLI·GUI 또는 시스템 프로그램
→ API
→ 시스템 콜
→ 커널
→ 하드웨어
```
