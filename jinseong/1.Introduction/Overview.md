# Chapter 1. Introduction

## 1.1 운영체제가 하는 일 (What Operating Systems Do)

- **컴퓨터 시스템의 4가지 구성 요소:**
  1. **하드웨어 (Hardware):** CPU, 메모리, I/O 장치 등 기본적인 계산 자원 제공.
  2. **운영체제 (Operating System):** 다양한 사용자 및 응용 프로그램 간의 하드웨어 사용을 제어하고 조율.
  3. **응용 프로그램 (Application Programs):** 사용자의 컴퓨팅 문제를 해결하기 위해 자원을 정의 및 활용 (웹 브라우저, 컴파일러, 데이터베이스 시스템, 게임 등).
  4. **사용자 (Users):** 사람, 기계, 다른 컴퓨터 등 시스템을 사용하는 주체.
- **사용자 관점 (User View):**
  - 일반 PC나 노트북 사용자는 편리함(Ease of use)과 고성능을 원하며, 자원 이용률(Resource utilization)에는 큰 관심을 두지 않음.
  - 서버나 메인프레임 환경에서는 다수의 사용자가 자원을 공유하므로, 자원을 극대화하고 공정하게 분배하는 것이 중요함.
  - 모바일 기기(스마트폰, 태블릿)는 편리함뿐만 아니라 배터리 수명(Battery life)의 최적화가 필수적임.
- **시스템 관점 (System View):**
  - **자원 할당자 (Resource Allocator):** CPU 시간, 메모리 공간, 파일 저장 공간, I/O 장치 등 대립하는 자원 요청 사이에서 효율적이고 공정하게 자원을 배분함.
  - **제어 프로그램 (Control Program):** 사용자 프로그램의 오류나 부적절한 컴퓨터 사용을 방지하기 위해 프로그램의 실행을 제어함.
- **운영체제의 정의:** 하드웨어 장치에 따라 완벽한 정의는 없지만, 일반적으로 컴퓨터가 켜져 있는 동안 항상 실행되는 프로그램인 **커널(Kernel)**을 의미함. 커널 외에는 시스템 프로그램(System program)과 응용 프로그램(Application program)으로 분류됨.

## 1.2 컴퓨터 시스템의 구성 (Computer-System Organization)

- **컴퓨터 시스템의 작동:** 하나 이상의 CPU와 여러 장치 컨트롤러(Device Controller)가 공통 버스(Common Bus)를 통해 연결되어 공유 메모리에 접근함. CPU와 자원들은 메모리 사이클을 확보하기 위해 동시 경쟁하며 실행됨.
- **부트스트랩 프로그램 (Bootstrap Program):** 컴퓨터 전원을 켜거나 재부팅할 때 실행되는 첫 프로그램으로, 주로 ROM이나 EEPROM에 저장됨(펌웨어). 시스템을 초기화하고 운영체제 커널을 메모리에 로드하여 실행을 위임함. 대표적인 예시로 IBM 호환 PC 환경의 BIOS와 UEFI가 있음.
- **인터럽트 (Interrupt):**
  - 하드웨어는 시스템 버스를 통해 CPU에 신호를 보내 인터럽트를 발생시키고, 소프트웨어는 **시스템 콜(System Call / Trap)**을 호출하여 인터럽트를 발생시킴.
  - 인터럽트가 발생하면 CPU는 하던 일을 멈추고, 인터럽트 벡터(Interrupt Vector)를 참조하여 해당 **인터럽트 서비스 루틴(ISR)**의 주소로 점프해 코드를 실행함. 처리가 끝나면 원래 중단되었던 명령어로 복귀함.

## 1.3 컴퓨터 시스템 구조 (Computer-System Architecture)

- **단일 처리기 시스템 (Single-Processor Systems):** 사용자 수준의 명령을 실행할 수 있는 주 CPU가 단 1개 존재하는 시스템.
- **다중 처리기 시스템 (Multiprocessor Systems):** 2개 이상의 밀접하게 결합된(Closely coupled) CPU를 가짐.
  - **장점:** 처리량 증가(Throughput), 규모의 경제(비용 절감), 신뢰성 증가(Fault tolerance).
  - **대칭형 다중 처리 (SMP):** 모든 프로세서가 대등한 관계에서 하나의 운영체제를 공유하여 실행함.
  - **비대칭형 다중 처리 (Asymmetric Multiprocessing):** 주 처리기(Master)가 시스템을 제어하고 다른 처리기(Slave)에 특정 작업을 할당함.
  - **멀티코어(Multicore) 설계:** 단일 칩 내에 여러 개의 실행 코어(Core)를 포함하여 칩 내부 통신 속도를 극대화하고 전력 소모를 줄임.
  - **불균형 메모리 접근 (NUMA, Non-Uniform Memory Access):** 여러 개의 CPU를 가진 대규모 시스템에서 시스템 버스 병목을 해결하기 위해 메모리를 '노드(Node)' 단위로 쪼개어 배치하는 아키텍처. 로컬 메모리 접근은 빠르나 인터커넥트를 거치는 원격 메모리 접근은 지연 시간(Latency)이 발생하므로 OS의 NUMA-Aware 스케줄링이 필수적임.
  - **블레이드 서버 (Blade Server):** CPU와 메모리가 독립적으로 탑재된 얇은 보드(Blade)들을 하나의 거대한 통합 섀시(Chassis)에 서랍처럼 꽂아서 사용하는 고밀도 서버 하드웨어.
- **클러스터 시스템 (Clustered Systems):** 여러 개의 독립된 개별 컴퓨터(Node)들을 네트워크로 결합한 고가용성(High Availability) 구조.
  - **저장장치 공유와 스토리지 영역 네트워크 (SAN):** 클러스터 노드들은 데이터 동기화를 위해 고속 네트워크로 연결된 거대한 공유 저장장치인 SAN을 바라봄.
  - **분산 잠금 관리자 (DLM, Distributed Lock Manager):** 여러 독립된 컴퓨터가 하나의 공유 저장장치(SAN)에 동시에 접근하여 데이터를 수정할 때, 데이터가 오염되거나 충돌하는 것을 막기 위해 파일이나 자원에 잠금(Lock)을 걸어 상호 배제를 보장하는 기술.
  - **비대칭형 클러스터링 (Asymmetric Clustering):** 한 노드는 실제 서비스를 실행하는 활성(Active) 상태이고, 다른 노드는 감시만 하며 대기하는 상태(Hot Standby).
  - **대칭형 클러스터링 (Symmetric Clustering):** 모든 노드가 각자 서로 다른 애플리케이션을 동시에 가동(Active-Active)하며 서로를 감시하는 효율적인 구조.
  - **병렬화 (Parallelization):** 대규모 작업을 분할하여 복수의 처리 장치에서 동시에 수행시켜 처리 성능을 높이는 기법. 클러스터 시스템 환경에서 안정적인 장애 조치(Failover)와 통신 프로토콜 호환성을 확보하기 위해 각 호스트는 완벽하게 동일한 소프트웨어 버전을 사용해야 함.

## 1.4 운영체제의 동작 (Operating-System Operations)

- **인터럽트 구동식 (Interrupt-driven):** 운영체제는 평소에 대기 상태에 있다가 인터럽트나 트랩(Trap)이 발생할 때만 동작함. 트랩은 오류(0으로 나누기 등)나 사용자 프로그램의 운영체제 서비스 요청(System call)으로 인해 발생하는 소프트웨어 인터럽트임.
- **멀티프로그래밍 (Multiprogramming):** CPU가 항상 무언가를 실행할 수 있도록 여러 프로그램(Job)을 메모리에 유지하는 방식. 한 프로그램이 I/O 작업을 기다릴 때 CPU는 다른 프로그램을 실행하여 자원 효율성을 극대화함.
- **멀티태스킹 / 시분할 (Multitasking / Time-sharing):** CPU가 여러 프로세스를 매우 빈번하게 번갈아 가며 실행하여(Time slice), 사용자가 각 프로그램과 실시간으로 상호작용할 수 있게 만드는 방식.
- **이중 모드 동작 (Dual-Mode Operation):** 운영체제와 사용자 프로그램을 보호하기 위해 하드웨어적으로 모드를 분리함.
  - **사용자 모드 (User Mode):** 모드 비트 `1`. 일반적인 사용자 응용 프로그램이 실행됨. 하드웨어 직접 접근이 차단되는 메모리 공간을 유저 영역(User Space)이라고 함.
  - **커널 모드 (Kernel Mode):** 모드 비 `0`. 시스템의 모든 제어 권한을 가지며, 특권 명령어(Privileged Instructions)는 오직 커널 모드(Kernel Space)에서만 실행 가능함.
  - 사용자 프로그램이 하드웨어 자원을 쓰려면 시스템 콜을 호출하여 커널 모드로 전환을 요청해야 함.
- **타이머 (Timer):** 특정 프로그램이 CPU를 독점하는 것을 방지하기 위해 하드웨어 타이머를 두고, 지정된 시간이 지나면 인터럽트를 발생시켜 제어권을 다시 운영체제 커널로 회수함.

## 1.5 자원 관리 (Resource Management)

- **프로세스 관리 (Process Management):** 프로세스는 실행 중인 프로그램이며, CPU 자원을 할당받는 주체임. OS는 프로세스의 생성·삭제, 일시 중지·재개, 프로세스 동기화 및 통신, 데드락(Deadlock) 처리 메커니즘을 제공함.
- **메모리 관리 (Memory Management):** 메인 메모리는 CPU가 직접 주소를 지정해 접근할 수 있는 거대한 바이트 배열임. OS는 메모리의 어느 부분이 사용되고 있는지 추적하고, 어떤 프로세스를 메모리에 로드할지 결정하며, 공간을 할당 및 회수함.
- **파일 시스템 관리 (File-System Management):** 물리적 저장 매체의 세부 특성을 추상화하여 '파일(File)'이라는 논리적 저장 단위로 관리함. 디렉터리 구조 관리, 파일 생성 및 삭제, 보조 저장장치로의 매핑, 백업 등을 담당함.
- **대용량 저장장치 관리 (Mass-Storage Management):** 메인 메모리는 휘발성이며 용량이 작기 때문에 비휘발성인 보조 저장장치(HDD, SSD)를 관리함. 디스크 비어있는 공간 관리, 저장 공간 할당, 디스크 스케줄링이 포함됨.
- **캐싱 (Caching):** 특정 정보가 사용될 때 더 빠른 저장장치(캐시)에 복사해 두어 성능을 높이는 기법. 데이터 정합성(Cache Coherency) 문제가 발생할 수 있음.
- **I/O 시스템 관리 (I/O System Management):** 하드웨어 장치마다 다른 특성을 사용자에게 숨기는 목적을 가짐. 메모리 관리 구성 요소(버퍼링, 캐싱, 스풀링), 공통 장치 드라이버 인터페이스, 특정 하드웨어용 장치 드라이버로 구성됨.

## 1.7 보안 및 보호 (Security and Protection)

- **보호 (Protection):** 컴퓨터 시스템이 정의한 자원에 대해 프로세스나 사용자의 접근을 제어하고 권한을 제한하는 메커니즘. 내부적인 오류나 잘못된 접근 차단이 주 목적임.
- **보안 (Security):** 외부 또는 내부의 고의적인 공격(바이러스, 웜, 해킹, 서비스 거부 공격 등)으로부터 시스템의 방어 체계를 유지하는 것.
- 시스템은 사용자를 구분하기 위해 사용자 ID(User ID)와 사용자가 속한 그룹 ID(Group ID)를 할당하여 권한을 판별함.
- **권한 에스컬레이션 (Privilege Escalation):** 사용자가 더 높은 권한을 얻기 위해 시스템의 취약점을 공격하는 행위로, 보호 시스템이 이를 반드시 모니터링해야 함.

## 1.8 가상화 (Virtualization)

- **정의:** 단일 컴퓨터의 하드웨어를 여러 개의 독립적인 실행 환경으로 추상화하는 기술. 이를 통해 하나의 물리적 컴퓨터 위에서 여러 개의 가상 운영체제(Guest OS)를 동시에 실행할 수 있음.
- **VMM (Virtual Machine Monitor / Hypervisor):** 가상화 환경을 제공하고 관리하는 핵심 소프트웨어 계층. CPU, 메모리, 저장장치 자원을 가상 머신에 동적으로 격리하여 분배함.
- **에뮬레이션 (Emulation)과의 차이:** 에뮬레이션은 소스 CPU 유형과 다른 대상 CPU 환경을 소프트웨어로 번갈아 번역하며 실행하는 것이라 속도가 느림. 가상화는 본래 하드웨어 아키텍처 위에서 직접 실행되므로 네이티브에 가까운 효율을 냄.

## 1.9 분산 시스템 (Distributed Systems)

- **정의:** 물리적으로 분리되어 있고 네트워크로 연결된 여러 컴퓨터(노드)들의 모음. 사용자는 분산 시스템 내의 단일 자원에 접근하듯 투명하게 사용할 수 있음.
- 분산 시스템을 매끄럽게 연결하기 위해 네트워크 통신 프로토콜(TCP/IP) 및 분산 파일 시스템 등 고도의 소프트웨어 인프라가 수반됨.

## 1.10 커널 데이터 구조 (Kernel Data Structures)

운영체제 커널 내에서 데이터를 효율적으로 관리하기 위해 표준 데이터 구조들이 대거 활용됨.

- **리스트 (Lists):** 데이터 항목들이 순차적으로 연결된 구조 (싱글 링크드 리스트, 더블 링크드 리스트 등).
- **스택 (Stacks):** 후입선출(LIFO) 방식의 구조로, 함수 호출 시 복귀 주소 및 로컬 변수 파라미터 관리에 쓰임.
- **큐 (Queues):** 선입선출(FIFO) 방식의 구조로, CPU 대기열이나 I/O 요청 대기열에 쓰임.
- **트리 (Trees):** 계층적 데이터 구조로, 효율적인 탐색을 위해 밸런스드 이진 탐색 트리(예: Red-Black Tree)가 리눅스의 CPU 스케줄링(CFS) 등에 다수 활용됨.
- **해시 함수 및 테이블 (Hash Functions & Tables):** 키 값을 해시 함수를 통해 인덱스로 변환하여 O(1)의 속도로 데이터를 조회하는 구조.
- **비트맵 (Bitmaps):** N개의 자원의 사용 유무(0과 1)를 하나의 비트 스트링으로 표현하는 고도로 압축된 자원 관리 방식. 디스크 블록 할당 상태 표시에 주로 사용됨.

## 1.11 컴퓨팅 환경 (Computing Environments)

- **전통적 컴퓨팅 (Traditional Computing):** 포털 오피스 환경이나 개인 PC 환경. 최근에는 웹 포털 및 원격 접근 환경과 결합됨.
- **모바일 컴퓨팅 (Mobile Computing):** 스마트폰 및 태블릿 환경. 물리적 크기가 작아 배터리 관리, 무선 네트워크 연결, 터치스크린 사용자 인터페이스 등이 강제됨. iOS와 Android가 대표적임.
- **클라이언트-서버 컴퓨팅 (Client-Server Computing):** 클라이언트의 요청을 받아 서버가 자원이나 서비스를 제공하는 구조 (컴퓨트 서버, 파일 서버 등).
- **피어 투 피어 컴퓨팅 (Peer-to-Peer Computing):** 중앙 서버 없이 참여하는 모든 노드(Peer)가 클라이언트이자 서버 역할을 동시에 수행하는 분산 구조. Discovery Service를 통해 서로를 찾음.
- **클라우드 컴퓨팅 (Cloud Computing):** 가상화를 기반으로 컴퓨팅, 저장장치, 네트워크 자원을 인터넷을 통해 서비스 형태로 제공하는 환경 (SaaS, PaaS, IaaS로 분류).
- **실시간 임베디드 시스템 (Real-Time Embedded Systems):** 가전제품, 자동차, 로봇 등에 내장되는 전용 시스템. 정해진 시간 제한(Deadlines) 내에 반드시 연산을 완료해야 하는 엄격한 제약 조건을 가짐.

## 1.12 오픈소스 운영체제 (Open-Source Operating Systems)

- **정의:** 소스코드가 대중에게 공개되어 누구나 자유롭게 수정, 배포, 연구할 수 있는 운영체제. 대표적으로 리눅스(Linux)가 있음.
- **대조 개념:** 소스코드가 비공개되어 영리 기업만 수정할 수 있는 독점 소스(Proprietary / Closed Source) 운영체제 (예: Microsoft Windows).
- **GNU/Linux:** 리처드 스톨만의 GNU 프로젝트 툴들과 리누스 토르발스의 리눅스 커널이 결합하여 현대 오픈소스 운영체제의 기반을 닦음. 대다수 클라우드 인프라와 모바일(Android 커널)의 모태가 됨.
