# Chapter 4. Threads & Concurrency

# 4.1 Overview

스레드(Thread)는 **CPU 사용의 기본 단위**다.

하나의 스레드는 독립적인 실행 흐름을 유지하기 위해 다음 정보를 가진다.

- Thread ID
- Program Counter
- Register Set
- Stack

반면 같은 프로세스에 속한 스레드들은 다음 자원을 공유한다.

- Code Section
- Data Section
- 운영체제 자원
  - 열린 파일
  - Signal
  - 기타 프로세스 자원

```text
하나의 멀티스레드 프로세스

┌─────────────────────────────────┐
│ Code Section                    │
│ Data Section                    │
│ Heap                            │
│ Open Files / Signals            │
│                                 │
│ Thread 1        Thread 2        │
│ ├─ Thread ID    ├─ Thread ID    │
│ ├─ PC           ├─ PC           │
│ ├─ Registers    ├─ Registers    │
│ └─ Stack        └─ Stack        │
└─────────────────────────────────┘
```

전통적인 프로세스는 하나의 실행 흐름만 가진다. 이를 **단일 스레드 프로세스**라고 한다.

```text
단일 스레드 프로세스

Process
└─ Thread 1
```

반면 멀티스레드 프로세스는 하나의 프로세스 안에 여러 실행 흐름을 가진다.

```text
멀티스레드 프로세스

Process
├─ Thread 1
├─ Thread 2
└─ Thread 3
```

따라서 하나의 프로세스가 여러 작업을 동시에 진행할 수 있다.

---

## 스레드마다 독립적으로 가지는 정보

### Program Counter

Program Counter는 다음에 실행할 명령어의 위치를 저장한다.

각 스레드는 서로 다른 코드를 실행할 수 있으므로 Program Counter를 공유할 수 없다.

```text
Thread A → 네트워크 처리 코드 실행
Thread B → 화면 렌더링 코드 실행
Thread C → 사용자 입력 처리 코드 실행
```

각 스레드가 현재 실행 중인 위치가 다르므로 각자 PC가 필요하다.

---

### Register Set

레지스터에는 현재 계산 중인 값, 함수 인자, 중간 결과 등이 저장된다.

스레드가 CPU에서 내려갔다가 다시 실행될 때 이전 연산 상태를 복원하려면 스레드별 레지스터 값이 필요하다.

```text
Thread A 실행
Register: x = 10

Context Switch

Thread B 실행
Register: x = 50

다시 Thread A 실행
Register: x = 10으로 복원
```

---

### Stack

스택에는 다음 정보가 저장된다.

- 함수 호출 기록
- 지역 변수
- 함수 인자
- 반환 주소

각 스레드는 서로 다른 함수를 실행하므로 별도의 스택이 필요하다.

```text
Thread A
main()
└─ download()
   └─ receiveData()

Thread B
main()
└─ render()
   └─ drawImage()
```

스택을 공유하면 서로 다른 함수 호출 기록과 지역 변수가 섞이게 된다.

---

## 스레드들이 공유하는 정보

같은 프로세스의 스레드들은 Code, Data, Heap 등을 공유한다.

```text
Thread A
→ Heap에 객체 생성

Thread B
→ 같은 Heap 객체 사용
```

이 때문에 스레드 간 데이터 공유는 프로세스 간 통신보다 간단하다.

프로세스끼리는 독립된 주소 공간을 사용하므로 데이터를 주고받으려면 다음과 같은 IPC가 필요하다.

- Shared Memory
- Message Passing
- Pipe
- Socket

하지만 같은 프로세스의 스레드들은 이미 주소 공간을 공유한다.

다만 여러 스레드가 같은 데이터를 동시에 수정하면 경쟁 조건이 발생할 수 있다.

```text
공유 변수 count = 0

Thread A: count++
Thread B: count++

예상 결과: 2
실제 결과: 1이 될 수도 있음
```

이러한 동기화 문제는 Chapter 6에서 자세히 다룬다.

# 4.1.1 Motivation

현대의 컴퓨터와 모바일 장치에서 실행되는 대부분의 응용 프로그램은 멀티스레드 방식으로 설계된다.

하나의 응용 프로그램은 일반적으로 하나의 프로세스로 실행되지만, 그 안에는 여러 실행 흐름이 존재한다.

교재는 대표적인 예로 사진 처리 프로그램, 웹 브라우저, 워드 프로세서를 든다.

---

## 사진 썸네일 생성 프로그램

여러 이미지에서 썸네일을 만들어야 한다고 하자.

단일 스레드라면 이미지를 하나씩 처리한다.

```text
이미지 1 처리
    ↓
이미지 2 처리
    ↓
이미지 3 처리
    ↓
이미지 4 처리
```

멀티스레드라면 각 이미지의 썸네일 생성을 별도 스레드가 맡을 수 있다.

```text
Thread 1 → 이미지 1 썸네일 생성
Thread 2 → 이미지 2 썸네일 생성
Thread 3 → 이미지 3 썸네일 생성
Thread 4 → 이미지 4 썸네일 생성
```

이미지 간 처리가 독립적이라면 멀티코어에서 실제 병렬 실행도 가능하다.

---

## 웹 브라우저

웹 브라우저는 동시에 여러 종류의 작업을 처리한다.

```text
Thread 1 → 화면에 이미지와 텍스트 표시
Thread 2 → 네트워크에서 데이터 수신
Thread 3 → 사용자 입력 처리
Thread 4 → JavaScript 실행
```

네트워크 응답을 기다리는 동안에도 화면이나 사용자 입력을 처리할 수 있기 때문에 응답성이 높아진다.

---

## 워드 프로세서

워드 프로세서는 다음 작업을 동시에 수행할 수 있다.

```text
Thread 1 → 화면에 글자와 그래픽 표시
Thread 2 → 키보드 입력 처리
Thread 3 → 맞춤법 및 문법 검사
```

맞춤법 검사가 오래 걸리더라도 사용자는 계속 문서를 작성할 수 있다.

---

## 멀티스레드 웹 서버

웹 서버는 여러 클라이언트의 요청을 처리해야 한다.

단일 스레드 서버라면 한 클라이언트 요청을 처리하는 동안 다른 요청은 기다려야 한다.

```text
Client A 요청
    ↓
A 요청 처리 완료
    ↓
Client B 요청 처리
```

초기 서버 구현에서는 요청마다 새 프로세스를 생성하기도 했다.

```text
서버 프로세스
    ↓ 요청 수신
새 프로세스 생성
    ↓
클라이언트 요청 처리
```

하지만 프로세스 생성은 주소 공간과 여러 운영체제 자원을 새로 구성해야 하므로 비용이 크다.

새 요청이 기존 서버와 같은 작업을 수행한다면 새 프로세스를 만드는 것보다 새 스레드를 만드는 편이 효율적이다.

```text
Server Main Thread
    │
    ├─ Client A 요청 → Worker Thread A
    ├─ Client B 요청 → Worker Thread B
    └─ Client C 요청 → Worker Thread C
```

교재의 Figure 4.2는 다음 흐름을 보여준다.

```text
1. 클라이언트가 요청을 전송한다.
2. 서버 스레드가 요청 처리용 새 스레드를 생성한다.
3. 서버 스레드는 다시 다음 요청을 기다린다.
```

즉, 요청 처리와 새로운 요청 수신을 동시에 진행할 수 있다.

---

## 운영체제 커널의 멀티스레딩

응용 프로그램뿐 아니라 운영체제 커널도 일반적으로 멀티스레드 방식으로 동작한다.

Linux는 부팅 과정에서 여러 커널 스레드를 생성한다.

각 커널 스레드는 특정 작업을 담당한다.

```text
Kernel Thread A → 장치 관리
Kernel Thread B → 메모리 관리
Kernel Thread C → 인터럽트 처리
Kernel Thread D → 기타 백그라운드 작업
```

Linux에서 `ps -ef` 명령을 사용하면 커널 스레드를 확인할 수 있다.

그중 `kthreadd`는 PID 2를 가지며 다른 커널 스레드들의 부모 역할을 한다.

여기서 커널 스레드는 단순히 “커널 메모리에 존재하는 스레드”라는 의미가 아니다.

핵심은 운영체제가 직접 인식하고 스케줄링할 수 있는 실행 단위라는 점이다.

---

## CPU 중심 응용 프로그램

정렬, 트리, 그래프 알고리즘과 같은 작업도 여러 스레드를 활용할 수 있다.

특히 다음과 같은 계산 집약적 분야는 멀티코어를 활용한 병렬 실행의 효과가 크다.

- 데이터 마이닝
- 그래픽 처리
- 인공지능
- 대규모 수치 계산

단, 프로그램을 스레드로 나누었다고 자동으로 성능이 증가하는 것은 아니다.

작업의 독립성, 데이터 의존성, 동기화 비용 등을 함께 고려해야 한다.

---

# 4.1.2 Benefits

교재는 멀티스레드 프로그래밍의 장점을 네 가지로 구분한다.

---

## 1. Responsiveness — 응답성

### 개념

프로그램의 일부가 Block되거나 긴 작업을 수행하더라도 다른 스레드가 계속 실행될 수 있다.

### 이유

단일 스레드 프로그램에서는 긴 작업 하나가 전체 실행 흐름을 차지한다.

```text
사용자가 버튼 클릭
    ↓
10초짜리 계산 실행
    ↓
계산이 끝날 때까지 UI 입력 처리 불가
```

멀티스레드 프로그램에서는 긴 작업을 비동기 스레드에 맡길 수 있다.

```text
UI Thread
├─ 사용자 입력 처리
├─ 화면 갱신
└─ 이벤트 처리

Worker Thread
└─ 10초짜리 계산 수행
```

### 동작

1. UI 스레드가 사용자 요청을 받는다.
2. 시간이 오래 걸리는 작업을 Worker Thread에 맡긴다.
3. UI 스레드는 계속 화면과 입력을 처리한다.
4. Worker Thread가 끝나면 결과를 UI에 전달한다.

### 예시

- 웹 브라우저 파일 다운로드
- 이미지 편집 프로그램의 필터 처리
- 모바일 앱의 네트워크 요청
- IDE의 코드 분석

---

## 2. Resource Sharing — 자원 공유

### 개념

같은 프로세스의 스레드들은 메모리와 자원을 기본적으로 공유한다.

### 이유

프로세스 간 자원 공유는 프로그래머가 IPC를 명시적으로 구성해야 한다.

반면 스레드는 같은 주소 공간에 속하기 때문에 Code, Data, Heap 등을 기본적으로 공유한다.

### 동작

```text
Thread A
→ Heap에 작업 데이터 저장

Thread B
→ 같은 데이터를 읽음

Thread C
→ 결과를 수정
```

### 예시

웹 서버의 Worker Thread들이 다음 자원을 공유할 수 있다.

- 메모리 캐시
- 데이터베이스 연결 풀
- 설정 정보
- 로그 객체
- 열린 파일

공유는 편리하지만, 동시에 수정할 때는 동기화가 필요하다.

---

## 3. Economy — 경제성

### 개념

프로세스를 생성하고 전환하는 것보다 스레드를 생성하고 전환하는 것이 일반적으로 비용이 적다.

### 이유

새 프로세스를 생성할 때는 독립적인 실행 환경을 구성해야 한다.

```text
새 프로세스 생성
├─ 주소 공간 생성
├─ 페이지 테이블 구성
├─ PCB 생성
├─ 메모리 할당
├─ 파일 정보 구성
└─ 기타 자원 할당
```

반면 새 스레드는 기존 프로세스의 주소 공간과 자원을 공유한다.

```text
새 스레드 생성
├─ Thread ID
├─ Program Counter
├─ Register Context
└─ Stack
```

따라서 생성해야 할 정보가 상대적으로 적다.

### Context Switch

프로세스 전환 시에는 실행 상태뿐 아니라 주소 공간과 관련된 정보도 바뀔 수 있다.

```text
Process A 주소 공간
    ↓
Process B 주소 공간
```

같은 프로세스의 스레드 전환에서는 주소 공간이 그대로 유지된다.

```text
같은 Code / Data / Heap

Thread A → Thread B
```

따라서 일반적으로 스레드 생성은 프로세스 생성보다 적은 시간과 메모리를 사용하며, 스레드 간 문맥 교환도 더 빠르다.

다만 실제 비용은 운영체제와 스레드 구현 방식에 따라 달라질 수 있다.

---

## 4. Scalability — 확장성

### 개념

멀티스레드 프로그램은 멀티프로세서 또는 멀티코어 환경에서 여러 스레드를 서로 다른 코어에 배치할 수 있다.

### 이유

단일 스레드 프로세스는 코어가 여러 개여도 자신에게 속한 실행 흐름이 하나뿐이다.

```text
4 Core CPU

Core 1 → Single Thread 실행
Core 2 → 해당 프로세스의 실행 흐름 없음
Core 3 → 해당 프로세스의 실행 흐름 없음
Core 4 → 해당 프로세스의 실행 흐름 없음
```

멀티스레드 프로세스는 여러 실행 흐름을 제공한다.

```text
Core 1 → Thread 1
Core 2 → Thread 2
Core 3 → Thread 3
Core 4 → Thread 4
```

따라서 여러 코어에서 병렬로 실행될 가능성이 생긴다.

### 주의

멀티스레드라고 반드시 병렬 실행되는 것은 아니다.

- 싱글 코어에서는 스레드들이 번갈아 실행된다.
- 멀티코어에서도 스레드 간 의존성이 크면 병렬성이 제한된다.
- Lock이나 동기화가 많으면 스레드들이 서로 기다릴 수 있다.
- 스레드 수가 코어 수보다 많으면 일부 스레드는 대기해야 한다.

# 4.2 Multicore Programming

과거에는 성능 향상을 위해 여러 CPU를 사용하는 다중 CPU 시스템이 등장했다.

이후 하나의 프로세서 칩 안에 여러 개의 계산 코어를 배치하는 멀티코어 구조가 일반화되었다.

```text
Processor Chip
├─ Core 1
├─ Core 2
├─ Core 3
└─ Core 4
```

각 코어는 운영체제에 별도의 CPU처럼 보일 수 있다.

멀티스레드 프로그래밍은 여러 코어를 효율적으로 사용하고 동시성을 높이는 방법을 제공한다.

---

## 싱글 코어에서의 실행

하나의 응용 프로그램에 네 개의 스레드가 있어도 코어가 하나라면 한 순간에 하나의 스레드만 실행된다.

```text
시간 ─────────────────────────────→

Single Core
T1 | T2 | T3 | T4 | T1 | T2 | ...
```

운영체제가 스레드를 빠르게 전환하기 때문에 여러 작업이 함께 진행되는 것처럼 보인다.

교재의 Figure 4.3은 이러한 **인터리빙된 동시 실행**을 보여준다.

## 멀티코어에서의 실행

여러 코어가 있으면 일부 스레드를 서로 다른 코어에 동시에 배치할 수 있다.

```text
같은 시간

Core 1 → Thread 1
Core 2 → Thread 2
Core 3 → Thread 3
Core 4 → Thread 4
```

교재의 Figure 4.4는 여러 스레드가 각 코어에서 실제로 동시에 실행되는 병렬 실행을 보여준다.

---

## Concurrency와 Parallelism

### Concurrency — 동시성

여러 작업이 일정 시간 동안 모두 진행되는 상태다.

한 순간에 하나의 작업만 실행되더라도 작업들을 번갈아 실행하여 모두 진전시키면 동시성이다.

```text
Single Core

T1 → T2 → T3 → T1 → T2
```

### Parallelism — 병렬성

둘 이상의 작업이 실제 같은 순간에 실행되는 상태다.

```text
Core 1 → T1
Core 2 → T2
```

### 차이

| 구분      | Concurrency             | Parallelism                  |
| --------- | ----------------------- | ---------------------------- |
| 의미      | 여러 작업이 함께 진전됨 | 여러 작업이 같은 순간 실행됨 |
| 싱글 코어 | 가능                    | 불가능                       |
| 멀티코어  | 가능                    | 가능                         |
| 핵심      | 작업을 다루는 구조      | 물리적인 동시 실행           |

따라서 **동시성은 있지만 병렬성은 없는 상태가 가능하다.**

예를 들어 싱글 코어가 여러 스레드를 빠르게 번갈아 실행하는 경우다.

---

# 4.2.1 Programming Challenges

멀티코어 시스템이 보편화되면서 운영체제 설계자와 응용 프로그램 개발자 모두 여러 코어를 효율적으로 활용해야 한다.

운영체제 설계자는 여러 코어에서 스레드를 실행할 수 있도록 스케줄링 알고리즘을 만들어야 한다.

응용 프로그램 개발자는 기존 프로그램을 멀티스레드 방식으로 변경하거나 처음부터 병렬 실행을 고려해 설계해야 한다.

교재는 멀티코어 프로그래밍의 주요 과제를 다섯 가지로 구분한다.

---

## 1. Identifying Tasks — 작업 식별

### 개념

프로그램에서 서로 분리하여 동시에 실행할 수 있는 작업을 찾아야 한다.

### 이유

모든 코드를 단순히 여러 조각으로 나눈다고 병렬 실행할 수 있는 것은 아니다.

각 작업이 가능하면 서로 독립적이어야 한다.

```text
독립적인 작업

Task A ─────────→
Task B ─────────→
Task C ─────────→
```

반대로 다음처럼 의존성이 있으면 병렬화하기 어렵다.

```text
Task A 결과
    ↓
Task B 실행
    ↓
Task C 실행
```

### 예시

이미지의 각 영역에 같은 필터를 적용하는 작업은 영역별로 나눌 수 있다.

```text
전체 이미지
├─ 왼쪽 위 영역
├─ 오른쪽 위 영역
├─ 왼쪽 아래 영역
└─ 오른쪽 아래 영역
```

각 영역이 서로 독립적이라면 별도의 코어에서 처리할 수 있다.

---

## 2. Balance — 작업 균형

### 개념

각 코어가 비슷한 양과 비슷한 가치의 작업을 수행하도록 분배해야 한다.

### 이유

작업량이 한 코어에 몰리면 다른 코어가 먼저 작업을 마치고 놀게 된다.

```text
Core 1 → 작업량 80%
Core 2 → 작업량 10%
Core 3 → 작업량 5%
Core 4 → 작업량 5%
```

전체 작업은 Core 1이 끝날 때까지 완료되지 않는다.

### 예시

100만 개의 데이터를 네 스레드가 처리한다면 단순하게는 다음처럼 나눌 수 있다.

```text
Thread 1 → 25만 개
Thread 2 → 25만 개
Thread 3 → 25만 개
Thread 4 → 25만 개
```

하지만 데이터마다 처리 비용이 다르면 개수만 같게 나눠도 작업량은 같지 않을 수 있다.

또한 어떤 작업이 전체 결과에 거의 기여하지 않는다면, 그 작업을 위해 별도의 코어를 사용하는 비용이 더 클 수도 있다.

---

## 암달의 법칙

암달의 법칙은 직렬 부분과 병렬 부분을 모두 가진 프로그램에서 코어를 추가했을 때 얻을 수 있는 최대 성능 향상을 설명한다.

교재에서는 4.2.1의 작업 균형 설명 다음에 별도 박스 형태로 제시한다.

### 공식

프로그램의 직렬 실행 비율을 `S`, 코어 수를 `N`이라고 하면 다음과 같다.

```text
Speedup ≤ 1 / (S + (1 - S) / N)
```

- `S`: 직렬 실행 부분
- `1 - S`: 병렬화 가능한 부분
- `N`: 처리 코어 수

### 공식의 의미

전체 실행 시간을 1이라고 가정한다.

직렬 부분은 코어를 늘려도 줄어들지 않는다.

```text
직렬 실행 시간 = S
```

병렬 부분은 N개 코어에 분배할 수 있다.

```text
병렬 실행 시간 = (1 - S) / N
```

따라서 새로운 실행 시간은 다음과 같다.

```text
S + (1 - S) / N
```

기존 시간 1을 새로운 실행 시간으로 나누면 Speedup이 된다.

---

### 교재 예시

프로그램이 다음과 같이 구성되어 있다고 하자.

```text
병렬 부분 = 75%
직렬 부분 = 25%
S = 0.25
```

#### 2코어

```text
Speedup
= 1 / (0.25 + 0.75 / 2)
= 1 / 0.625
= 1.6
```

2코어를 사용해도 정확히 2배가 아니라 1.6배 정도 빨라진다.

#### 4코어

```text
Speedup
= 1 / (0.25 + 0.75 / 4)
= 1 / 0.4375
≈ 2.28
```

4코어를 사용해도 약 2.28배만 빨라진다.

---

### 코어를 무한히 늘리는 경우

`N`이 무한히 커지면 병렬 부분의 실행 시간은 0에 가까워진다.

```text
(1 - S) / N → 0
```

따라서 최대 Speedup은 다음과 같다.

```text
Maximum Speedup = 1 / S
```

직렬 부분이 25%라면 다음과 같다.

```text
1 / 0.25 = 4
```

코어를 무한히 늘려도 최대 4배 이상 빨라질 수 없다.

직렬 부분이 50%라면 최대 성능 향상은 2배다.

```text
1 / 0.5 = 2
```

### 핵심

> 프로그램의 작은 직렬 부분이 전체 성능 향상을 크게 제한할 수 있다.

또한 실제 프로그램에는 다음 오버헤드도 있으므로 실제 성능 향상은 공식보다 낮아질 수 있다.

- 스레드 생성
- 작업 분배
- 동기화
- Lock 획득
- 캐시 일관성 유지
- 결과 병합
- Context Switch

## 3. Data Splitting — 데이터 분할

### 개념

작업을 나누는 것과 함께, 각 작업이 처리할 데이터도 나누어야 한다.

### 이유

여러 스레드가 같은 큰 데이터 집합을 처리한다면 각 스레드가 맡을 범위를 명확히 정해야 한다.

### 예시

```text
Array[0 ... 999]

Thread 1 → 0 ~ 249
Thread 2 → 250 ~ 499
Thread 3 → 500 ~ 749
Thread 4 → 750 ~ 999
```

이미지라면 행이나 영역 단위로 나눌 수 있다.

```text
Thread 1 → 1~250행
Thread 2 → 251~500행
Thread 3 → 501~750행
Thread 4 → 751~1000행
```

### 주의점

- 데이터가 누락되지 않아야 한다.
- 중복 처리되지 않아야 한다.
- 경계 영역을 정확히 처리해야 한다.
- 여러 스레드가 같은 데이터를 동시에 수정하지 않도록 해야 한다.
- 데이터 배치가 캐시 효율에 영향을 줄 수 있다.

---

## 4. Data Dependency — 데이터 의존성

### 개념

한 작업이 다른 작업의 결과를 사용한다면 실행 순서를 보장해야 한다.

### 이유

여러 스레드의 실행 순서는 고정되어 있지 않다.

```text
Thread A: x 계산
Thread B: y = x + 5 계산
```

Thread B가 먼저 실행되면 x가 아직 준비되지 않았을 수 있다.

### 동작

```text
Thread A
└─ x 계산 완료
       ↓ 완료 신호

Thread B
└─ x를 사용해 y 계산
```

이 경우 다음과 같은 동기화 기법이 필요하다.

- Join
- Mutex
- Semaphore
- Condition Variable
- Barrier

동기화를 지나치게 많이 사용하면 스레드들이 서로 기다리기 때문에 병렬성이 감소할 수 있다.

---

## 5. Testing and Debugging — 테스트와 디버깅

### 개념

병렬 프로그램은 단일 스레드 프로그램보다 실행 가능한 경로가 많기 때문에 테스트와 디버깅이 어렵다.

### 이유

스레드 실행 순서가 매번 달라질 수 있다.

```text
실행 1
A → B → C

실행 2
B → A → C

실행 3
C → B → A
```

같은 입력에서도 오류가 항상 같은 방식으로 발생하지 않을 수 있다.

### 대표 문제

- Race Condition
- Deadlock
- Starvation
- Livelock
- 데이터 가시성 문제
- 실행 순서에 따른 비결정적 오류

### 예시

```text
count = 0

Thread A: count++
Thread B: count++
```

어떤 실행에서는 2가 나오고, 어떤 실행에서는 1이 나올 수 있다.

따라서 멀티코어 시스템의 등장으로 소프트웨어 설계와 교육 방식 모두 병렬 프로그래밍을 더 중요하게 다뤄야 한다.

---

# 4.2.2 Types of Parallelism

교재는 병렬성을 두 종류로 구분한다.

- Data Parallelism
- Task Parallelism

Figure 4.5는 데이터를 코어별로 분할하는 방식과 작업을 코어별로 분할하는 방식을 비교한다.

---

## Data Parallelism — 데이터 병렬성

### 개념

같은 데이터를 여러 부분으로 나누어 각 코어에서 동일한 연산을 수행한다.

```text
같은 연산
├─ Core 1 → Data Part 1
├─ Core 2 → Data Part 2
├─ Core 3 → Data Part 3
└─ Core 4 → Data Part 4
```

### 교재 예시: 배열 합계

크기가 N인 배열의 합을 구한다고 하자.

싱글 코어에서는 하나의 스레드가 전체 배열을 더한다.

```text
Thread 1
→ Array[0] ~ Array[N - 1] 합산
```

듀얼 코어에서는 배열을 절반으로 나눌 수 있다.

```text
Thread A on Core 0
→ Array[0] ~ Array[N/2 - 1] 합산

Thread B on Core 1
→ Array[N/2] ~ Array[N - 1] 합산
```

두 스레드가 부분합을 계산한 뒤 마지막에 결과를 합친다.

```text
Total = Partial Sum A + Partial Sum B
```

### 다른 예시

- 이미지 영역별 필터 적용
- 행렬의 행 단위 연산
- 배열 원소 변환
- 대규모 데이터 분석
- 머신러닝 학습 데이터 처리

---

## Task Parallelism — 작업 병렬성

### 개념

데이터가 아니라 서로 다른 작업을 여러 코어에 분배한다.

각 스레드는 서로 다른 연산을 수행한다.

```text
Core 1 → Task A
Core 2 → Task B
Core 3 → Task C
Core 4 → Task D
```

각 스레드는 같은 데이터를 사용할 수도 있고 서로 다른 데이터를 사용할 수도 있다.

### 교재 예시

하나의 배열에 대해 서로 다른 통계 연산을 수행한다고 하자.

```text
Thread A → 배열 평균 계산
Thread B → 배열 최댓값 계산
```

두 스레드는 같은 배열을 사용하지만 서로 다른 연산을 수행한다.

### 다른 예시

웹 브라우저:

```text
Thread 1 → 화면 렌더링
Thread 2 → 네트워크 통신
Thread 3 → JavaScript 실행
Thread 4 → 사용자 입력 처리
```

---

## Data Parallelism과 Task Parallelism 비교

| 구분               | Data Parallelism        | Task Parallelism          |
| ------------------ | ----------------------- | ------------------------- |
| 분할 대상          | 데이터                  | 작업                      |
| 각 스레드의 연산   | 동일                    | 서로 다름                 |
| 각 스레드의 데이터 | 서로 다른 데이터 부분   | 같거나 다를 수 있음       |
| 대표 예시          | 배열을 나누어 각각 합산 | 평균과 최댓값을 각각 계산 |

두 방식은 함께 사용할 수도 있다.

```text
Task Parallelism
├─ 이미지 불러오기
├─ 이미지 필터 적용
└─ 이미지 저장

이미지 필터 적용 내부
└─ Data Parallelism으로 영역별 분할
```

현대 응용 프로그램은 여러 작업을 동시에 처리하기 위해 멀티스레드를 사용한다.

## 4.2 Multicore Programming

```text
싱글 코어 + 여러 스레드
→ 번갈아 실행
→ Concurrency

멀티코어 + 여러 스레드
→ 서로 다른 코어에서 동시 실행 가능
→ Parallelism
```

동시성은 여러 작업이 모두 진행되는 것이고, 병렬성은 여러 작업이 실제 같은 순간에 실행되는 것이다.

---

## 4.2.1 Programming Challenges

멀티코어 프로그래밍의 다섯 가지 과제는 다음과 같다.

1. Identifying Tasks
2. Balance
3. Data Splitting
4. Data Dependency
5. Testing and Debugging

암달의 법칙은 직렬 부분이 전체 성능 향상의 상한을 결정한다는 것을 보여준다.

```text
Speedup ≤ 1 / (S + (1 - S) / N)
```

코어 수가 무한히 증가할 때 최대 성능 향상은 다음과 같다.

```text
Maximum Speedup = 1 / S
```

---

## 4.2.2 Types of Parallelism

```text
Data Parallelism
→ 같은 작업을 서로 다른 데이터 부분에 수행

Task Parallelism
→ 서로 다른 작업을 여러 코어에서 수행
```

---

# 면접 포인트

### Q1. 스레드는 어떤 자원을 독립적으로 가지는가?

스레드는 Thread ID, Program Counter, Register Set, Stack을 독립적으로 가진다. 같은 프로세스의 스레드끼리는 Code, Data, Heap과 열린 파일 등의 프로세스 자원을 공유한다.

### Q2. 프로세스 대신 스레드를 사용하는 이유는 무엇인가?

스레드는 프로세스의 주소 공간과 자원을 공유하므로 생성과 문맥 교환 비용이 일반적으로 더 작다. 또한 데이터 공유가 쉽고, 응답성을 높이며, 멀티코어에서 병렬 실행할 수 있다.

### Q3. 동시성과 병렬성의 차이는 무엇인가?

동시성은 여러 작업이 같은 시간 구간에 모두 진전되는 것이고, 병렬성은 여러 작업이 서로 다른 코어에서 실제 같은 순간에 실행되는 것이다. 싱글 코어에서는 동시성은 가능하지만 병렬성은 불가능하다.

### Q4. 코어를 늘리면 성능이 코어 수만큼 증가하는가?

그렇지 않다. 직렬 실행 부분과 동기화 및 통신 오버헤드 때문에 성능 향상은 제한된다. 암달의 법칙은 이러한 최대 성능 향상을 계산한다.

### Q5. 데이터 병렬성과 작업 병렬성의 차이는 무엇인가?

데이터 병렬성은 같은 연산을 서로 다른 데이터 부분에 수행하는 방식이고, 작업 병렬성은 서로 다른 연산을 여러 코어에 분배하는 방식이다.

# 4.3 Multithreading Models

## 사용자 스레드와 커널 스레드

스레드를 이해할 때는 먼저 **사용자 스레드(User Thread)** 와 **커널 스레드(Kernel Thread)** 를 구분해야 한다.

### 사용자 스레드

사용자 스레드는 사용자 영역에서 제공되는 스레드 라이브러리에 의해 생성되고 관리된다.

```text
User Space

Application
├─ User Thread 1
├─ User Thread 2
└─ User Thread 3
```

사용자 스레드를 관리하는 주체는 운영체제 커널이 아니라 다음과 같은 스레드 라이브러리일 수 있다.

- POSIX Pthreads
- Windows Thread API
- Java Thread API

다만 라이브러리가 사용자 스레드를 만들었다고 해서 그 스레드가 항상 커널과 무관한 것은 아니다. 현대 시스템에서는 사용자 스레드가 커널 스레드에 연결되어 실행되는 경우가 일반적이다.

---

### 커널 스레드

커널 스레드는 운영체제가 직접 지원하고 관리하는 실행 단위다.

```text
Kernel Space

Kernel
├─ Kernel Thread 1
├─ Kernel Thread 2
└─ Kernel Thread 3
```

Windows, Linux, macOS를 포함한 현대 운영체제들은 커널 스레드를 지원한다.

CPU 스케줄러가 실제 실행 대상으로 보는 것은 일반적으로 **커널 스레드**다.

```text
User Thread
    ↓ 매핑
Kernel Thread
    ↓ 스케줄링
CPU Core
```

따라서 사용자 프로그램이 만든 스레드를 실제 CPU에서 실행하려면 사용자 스레드와 커널 스레드 사이에 어떤 연결 관계가 필요하다.

이 연결 방식을 **Multithreading Model**이라고 한다.

---

## 왜 여러 가지 매핑 모델이 필요한가

사용자 스레드와 커널 스레드를 어떻게 연결하느냐에 따라 다음 특성이 달라진다.

- 스레드 생성 비용
- 문맥 교환 비용
- Blocking 시스템 콜의 영향
- 멀티코어 활용 가능 여부
- 커널이 관리해야 하는 스레드 수
- 응용 프로그램이 만들 수 있는 스레드 수

교재는 다음 세 가지 주요 모델을 설명한다.

```text
1. Many-to-One
2. One-to-One
3. Many-to-Many
```

Many-to-Many의 변형으로 **Two-Level Model**도 설명한다.

---

# 4.3.1 Many-to-One Model

## 개념

여러 사용자 스레드를 하나의 커널 스레드에 연결하는 방식이다.

```text
User Space

UT1 ─┐
UT2 ─┼──→ KT1
UT3 ─┘

Kernel Space
```

- 사용자 스레드: 여러 개
- 커널 스레드: 한 개

사용자 영역의 스레드 라이브러리가 스레드 관리와 스케줄링을 수행한다.

커널은 사용자 스레드 각각을 알지 못하고, 하나의 커널 스레드만 인식한다.

---

## 필요한 이유

사용자 영역에서 스레드를 관리하면 커널 호출 없이 다음 작업을 처리할 수 있다.

- 스레드 생성
- 스레드 종료
- 사용자 스레드 간 문맥 교환
- 사용자 스레드 스케줄링

따라서 스레드 관리 비용이 작다.

```text
UT1 → UT2 전환

커널 진입 없이
사용자 스레드 라이브러리가 처리
```

---

## 동작

사용자 스레드 라이브러리가 여러 사용자 스레드 중 하나를 선택한다.

```text
UT1 실행
  ↓
UT2 실행
  ↓
UT3 실행
```

하지만 커널 관점에서는 항상 하나의 커널 스레드가 실행 중이다.

```text
Kernel View

KT1 하나만 존재
```

---

## 장점

### 스레드 관리 비용이 작다

사용자 스레드 생성과 전환이 사용자 공간에서 이루어지므로 커널 모드로 진입할 필요가 없다.

### 많은 사용자 스레드를 만들 수 있다

운영체제가 모든 사용자 스레드를 직접 관리하지 않으므로 비교적 많은 스레드를 생성할 수 있다.

---

## 단점 1: Blocking 시스템 콜 문제

하나의 사용자 스레드가 Blocking 시스템 콜을 호출하면 연결된 커널 스레드가 Block된다.

커널 스레드가 하나뿐이므로 프로세스의 모든 사용자 스레드가 실행할 수 없게 된다.

```text
UT1 → read() 호출
        ↓
KT1 Block

UT2 실행 불가
UT3 실행 불가
```

예를 들어 UT1이 디스크 입력을 기다린다고 하자.

UT2와 UT3는 별개의 작업을 수행할 수 있어도 커널에는 실행 가능한 커널 스레드가 없으므로 함께 멈춘다.

---

## 단점 2: 멀티코어 병렬 실행 불가능

사용자 스레드가 여러 개여도 커널 스레드는 하나뿐이다.

```text
Core 1 → KT1
Core 2 → 실행시킬 KT 없음
Core 3 → 실행시킬 KT 없음
Core 4 → 실행시킬 KT 없음
```

따라서 멀티코어 시스템에서도 한 시점에 하나의 사용자 스레드만 실행할 수 있다.

동시성은 구현할 수 있지만 병렬성은 얻을 수 없다.

---

## 예시

교재는 과거에 사용된 예로 다음을 언급한다.

- Solaris Green Threads
- GNU Portable Threads

다만 현대의 범용 운영체제에서는 이 모델이 널리 사용되지 않는다.

---

# 4.3.2 One-to-One Model

## 개념

각 사용자 스레드를 하나의 커널 스레드에 연결하는 방식이다.

```text
User Space          Kernel Space

UT1 ─────────────→ KT1
UT2 ─────────────→ KT2
UT3 ─────────────→ KT3
```

사용자 스레드 하나를 생성하면 대응되는 커널 스레드도 생성된다.

---

## 필요한 이유

Many-to-One에서는 하나의 스레드가 Blocking되면 전체 프로세스가 멈추고 멀티코어도 사용할 수 없다.

One-to-One은 사용자 스레드마다 독립적인 커널 실행 단위를 제공하여 이 문제를 해결한다.

---

## 동작

각 사용자 스레드는 대응되는 커널 스레드를 통해 실행된다.

```text
UT1 → KT1 → Core 1
UT2 → KT2 → Core 2
UT3 → KT3 → Core 3
```

운영체제 스케줄러는 KT1, KT2, KT3를 각각 독립적으로 스케줄링할 수 있다.

---

## 장점 1: Blocking의 영향이 제한된다

UT1이 Blocking 시스템 콜을 실행하면 KT1만 Block된다.

```text
UT1 → KT1 → Block

UT2 → KT2 → 계속 실행
UT3 → KT3 → 계속 실행
```

따라서 다른 스레드들은 계속 실행할 수 있다.

---

## 장점 2: 멀티코어 병렬 실행 가능

각 사용자 스레드가 별도의 커널 스레드에 연결되므로 서로 다른 코어에서 실행될 수 있다.

```text
Core 1 → KT1
Core 2 → KT2
Core 3 → KT3
```

단, One-to-One이라는 이유만으로 항상 병렬 실행되는 것은 아니다.

실제 병렬 실행을 위해서는 다음 조건이 필요하다.

- 두 개 이상의 CPU 코어
- 동시에 실행 가능한 여러 스레드
- 스레드 간 의존성과 대기가 적을 것
- 운영체제가 서로 다른 코어에 배치할 것

싱글 코어에서도 One-to-One 매핑은 가능하지만 이때 스레드들은 번갈아 실행된다.

```text
Single Core

KT1 → KT2 → KT3 → KT1
```

---

## 단점: 스레드 생성 비용과 개수 제한

사용자 스레드를 생성할 때마다 커널 스레드도 만들어야 한다.

커널 스레드는 운영체제가 관리해야 하므로 생성과 관리에 비용이 발생한다.

```text
사용자 스레드 10,000개
↓
커널 스레드도 10,000개 필요
↓
커널 메모리와 스케줄링 비용 증가
```

따라서 운영체제는 하나의 응용 프로그램이 생성할 수 있는 스레드 수를 제한할 수 있다.

---

## 사용 사례

교재는 다음 시스템들이 One-to-One 모델을 구현한다고 설명한다.

- Windows
- Linux
- macOS

현대의 범용 운영체제에서 가장 일반적인 모델이다.

---

# 4.3.3 Many-to-Many Model

## 개념

여러 사용자 스레드를 여러 커널 스레드에 다중화하는 방식이다.

사용자 스레드의 수와 커널 스레드의 수가 반드시 같지 않다.

```text
User Space

UT1 ─┐
UT2 ─┼────┐
UT3 ─┤    │
UT4 ─┘    │
          ↓
Kernel Space

KT1
KT2
KT3
```

예를 들어 사용자 스레드가 100개 있어도 커널 스레드는 8개만 사용할 수 있다.

---

## 필요한 이유

Many-to-One과 One-to-One의 장점을 결합하려는 모델이다.

### Many-to-One의 장점

- 사용자 스레드를 많이 만들 수 있음
- 사용자 영역에서 스레드를 유연하게 관리 가능

### One-to-One의 장점

- Blocking되어도 다른 스레드 실행 가능
- 여러 커널 스레드를 사용해 멀티코어 병렬 실행 가능

Many-to-Many는 다수의 사용자 스레드를 제한된 수의 커널 스레드에 연결한다.

---

## 동작

사용자 스레드 라이브러리는 실행할 사용자 스레드를 선택해 사용 가능한 커널 스레드에 연결한다.

```text
시점 1

UT1 → KT1
UT2 → KT2
UT3 → KT3
UT4 → 대기
```

이후 UT1이 Block되거나 실행을 마치면 다른 사용자 스레드가 KT1을 사용할 수 있다.

```text
시점 2

UT1 → Block
UT4 → KT1
UT2 → KT2
UT3 → KT3
```

즉, 사용자 스레드가 커널 스레드보다 많더라도 실행 가능한 사용자 스레드를 커널 스레드에 번갈아 연결한다.

---

## 장점 1: 사용자 스레드 수에 유연하다

개발자는 필요한 만큼 사용자 스레드를 만들 수 있고, 커널 스레드는 시스템이 처리 가능한 수준으로 유지할 수 있다.

---

## 장점 2: Blocking 문제 완화

한 사용자 스레드가 Blocking 시스템 콜을 실행해 특정 커널 스레드가 Block되더라도 다른 커널 스레드에서 다른 사용자 스레드를 실행할 수 있다.

```text
UT1 → KT1 → Block

UT2 → KT2 → 실행
UT3 → KT3 → 실행
```

---

## 장점 3: 멀티코어 활용 가능

커널 스레드가 여러 개이므로 서로 다른 코어에서 동시에 실행할 수 있다.

```text
Core 1 → KT1
Core 2 → KT2
Core 3 → KT3
```

---

## 단점

사용자 스레드와 커널 스레드 사이의 매핑을 동적으로 관리해야 하므로 구현이 복잡하다.

운영체제와 스레드 라이브러리가 서로 협력해야 한다.

```text
사용자 스레드 스케줄링
+
커널 스레드 스케줄링
+
두 계층의 매핑 관리
```

One-to-One 모델이 일반화되면서 현대 시스템에서 Many-to-Many의 중요성은 상대적으로 감소했다.

교재는 처리 코어 수가 증가해도 커널이 생성할 수 있는 커널 스레드 수가 크게 늘었기 때문에 One-to-One 모델의 스레드 수 제한 문제가 과거보다 덜 중요해졌다고 설명한다.

---

## Two-Level Model

Two-Level Model은 Many-to-Many의 변형이다.

기본적으로 여러 사용자 스레드를 여러 커널 스레드에 다중화하지만, 특정 사용자 스레드를 특정 커널 스레드에 고정할 수도 있다.

```text
일반 매핑

UT1 ─┐
UT2 ─┼──→ KT1, KT2에 동적 매핑
UT3 ─┘

고정 매핑

UT4 ─────→ KT3
```

특정 사용자 스레드와 커널 스레드를 고정하는 것을 **Binding**이라고 볼 수 있다.

---

## 필요한 이유

일반적인 사용자 스레드는 커널 스레드를 공유해 효율성을 얻고, 중요한 스레드는 전용 커널 스레드를 확보할 수 있다.

예를 들어 실시간 처리가 필요한 스레드나 응답성이 중요한 스레드를 특정 커널 스레드에 고정할 수 있다.

---

## 모델 비교

| 구분             | Many-to-One   | One-to-One              | Many-to-Many     |
| ---------------- | ------------- | ----------------------- | ---------------- |
| 사용자 스레드    | 여러 개       | 여러 개                 | 여러 개          |
| 커널 스레드      | 1개           | 사용자 스레드와 같은 수 | 여러 개          |
| Blocking 영향    | 전체 프로세스 | 해당 스레드             | 일부 커널 스레드 |
| 멀티코어 병렬성  | 불가능        | 가능                    | 가능             |
| 스레드 생성 비용 | 낮음          | 상대적으로 높음         | 중간             |
| 구현 복잡도      | 낮음          | 비교적 단순             | 높음             |
| 스레드 수 유연성 | 높음          | 커널 제한 가능          | 높음             |
| 현대 범용 OS     | 드묾          | 일반적                  | 제한적으로 사용  |

---

# 4.4 Thread Libraries

## 스레드 라이브러리란

Thread Library는 프로그래머가 스레드를 생성하고 관리할 수 있도록 API를 제공한다.

주요 기능은 다음과 같다.

```text
Thread Library
├─ 스레드 생성
├─ 스레드 종료
├─ 스레드 대기
├─ 속성 설정
├─ 스레드 식별
└─ 동기화 기능
```

교재는 세 가지 주요 스레드 라이브러리를 설명한다.

- POSIX Pthreads
- Windows Thread API
- Java Thread API

---

## 스레드 라이브러리의 구현 방식

교재는 스레드 라이브러리를 구현하는 두 가지 기본 방법을 설명한다.

### 사용자 공간 라이브러리

라이브러리의 코드와 자료구조가 사용자 공간에 존재한다.

```text
User Space
├─ Thread Library
├─ Thread Table
└─ User Threads
```

라이브러리 함수 호출은 일반 함수 호출처럼 처리되며 커널 시스템 콜이 필요하지 않을 수 있다.

장점은 빠른 스레드 생성과 관리다.

하지만 Many-to-One 모델이라면 Blocking 시스템 콜과 멀티코어 활용 문제가 발생한다.

---

### 커널 수준 라이브러리

운영체제가 직접 커널 수준의 스레드 라이브러리를 제공한다.

```text
User Program
    ↓ API 호출
Kernel
├─ Kernel Thread 생성
├─ Kernel Thread 관리
└─ Kernel Thread 스케줄링
```

라이브러리 함수 호출이 시스템 콜로 이어질 수 있으며, 커널이 스레드 관련 자료구조를 관리한다.

One-to-One 모델에서 일반적으로 볼 수 있는 방식이다.

---

## 비동기 스레딩과 동기 스레딩

교재는 스레드를 생성한 뒤 부모 스레드와 자식 스레드가 어떤 관계로 실행되는지도 구분한다.

---

### Asynchronous Threading — 비동기 스레딩

부모 스레드가 자식 스레드를 생성한 뒤 자식의 종료를 기다리지 않고 계속 실행한다.

```text
Parent Thread
    ├─ Child Thread 생성
    └─ 즉시 다음 작업 계속

Child Thread
    └─ 독립적으로 실행
```

부모와 자식은 서로 독립적으로 실행되며 일반적으로 데이터 공유가 적다.

#### 예시

- 백그라운드 로그 기록
- 파일 다운로드
- 사용자 인터페이스와 독립된 작업
- 서버 요청 처리

---

### Synchronous Threading — 동기 스레딩

부모 스레드가 하나 이상의 자식 스레드를 생성하고, 자식들이 모두 종료할 때까지 기다린다.

```text
Parent
├─ Child 1 생성
├─ Child 2 생성
├─ Child 3 생성
└─ join으로 대기
       ↓
모든 자식 종료
       ↓
Parent 실행 재개
```

부모가 자식의 결과를 이용해야 할 때 사용한다.

#### 예시

배열을 여러 구간으로 나누어 부분합을 계산한다고 하자.

```text
Child 1 → 첫 번째 구간 합계
Child 2 → 두 번째 구간 합계
Child 3 → 세 번째 구간 합계
```

부모 스레드는 세 부분합이 모두 준비된 뒤 최종 합계를 계산해야 한다.

---

# 4.4.1 Pthreads

## 개념

Pthreads는 POSIX 표준이 정의한 스레드 생성과 동기화 API다.

중요한 점은 Pthreads가 특정 구현 자체가 아니라 **스레드 동작에 관한 명세**라는 것이다.

운영체제는 이 명세를 각자의 방식으로 구현한다.

Pthreads는 일반적으로 UNIX 계열 시스템에서 사용된다.

- Linux
- macOS
- 기타 POSIX 호환 시스템

---

## 기본 자료형

Pthreads를 사용할 때는 다음 헤더를 포함한다.

```c
#include <pthread.h>
```

스레드 식별자는 `pthread_t` 타입으로 표현한다.

```c
pthread_t tid;
```

스레드 속성은 `pthread_attr_t` 타입으로 표현한다.

```c
pthread_attr_t attr;
```

---

## `pthread_create()`

새 스레드는 `pthread_create()` 함수로 생성한다.

```c
pthread_create(
    &tid,
    &attr,
    runner,
    &param
);
```

각 인자의 의미는 다음과 같다.

| 인자     | 의미                           |
| -------- | ------------------------------ |
| `&tid`   | 생성된 스레드 ID를 저장할 위치 |
| `&attr`  | 스레드 속성                    |
| `runner` | 새 스레드가 실행할 함수        |
| `&param` | 실행 함수에 전달할 인자        |

실행 함수는 일반적으로 다음 형태다.

```c
void *runner(void *param)
{
    /* 스레드가 수행할 작업 */
    pthread_exit(0);
}
```

`void *`를 사용하기 때문에 다양한 자료형의 주소를 인자로 전달할 수 있다.

---

## `pthread_attr_init()`

스레드 속성 객체를 기본값으로 초기화한다.

```c
pthread_attr_init(&attr);
```

속성에는 다음과 같은 설정이 포함될 수 있다.

- 스택 크기
- 스케줄링 정보
- 분리 상태
- 기타 스레드 특성

교재 예제에서는 기본 속성을 사용한다.

---

## `pthread_join()`

부모 스레드는 `pthread_join()`을 호출하여 자식 스레드가 종료할 때까지 기다릴 수 있다.

```c
pthread_join(tid, NULL);
```

동작은 다음과 같다.

```text
Parent Thread
    ↓ pthread_create()
Child Thread 실행

Parent Thread
    ↓ pthread_join()
대기

Child Thread 종료
    ↓
Parent Thread 재개
```

따라서 `pthread_join()`은 동기 스레딩을 구현하는 대표적인 함수다.

---

## 교재 예제: 1부터 N까지의 합

교재는 별도의 스레드가 1부터 사용자가 전달한 숫자까지의 합을 계산하는 예제를 제시한다.

```text
입력: 10

Child Thread
→ 1 + 2 + ... + 10 계산
→ 공유 변수 sum에 저장

Parent Thread
→ pthread_join()으로 대기
→ sum 출력
```

공유 변수는 전역 변수로 선언되므로 부모와 자식 스레드가 같은 값을 공유한다.

```c
int sum;
```

대략적인 흐름은 다음과 같다.

```c
pthread_t tid;
pthread_attr_t attr;

pthread_attr_init(&attr);
pthread_create(&tid, &attr, runner, argv[1]);
pthread_join(tid, NULL);

printf("sum = %d\n", sum);
```

---

## 여러 스레드를 생성하는 경우

N개의 스레드를 생성하려면 `pthread_t` 배열을 사용할 수 있다.

```c
pthread_t workers[N];
```

각 스레드를 반복문으로 생성한다.

```c
for (int i = 0; i < N; i++) {
    pthread_create(&workers[i], NULL, runner, ...);
}
```

그다음 모든 스레드의 종료를 기다린다.

```c
for (int i = 0; i < N; i++) {
    pthread_join(workers[i], NULL);
}
```

여기서 중요한 점은 생성 루프와 `join` 루프를 분리하는 것이다.

다음처럼 생성 직후 바로 `join`하면 병렬성이 사라질 수 있다.

```c
for (int i = 0; i < N; i++) {
    pthread_create(&workers[i], NULL, runner, ...);
    pthread_join(workers[i], NULL);
}
```

이 경우 한 스레드가 끝난 뒤 다음 스레드를 생성하므로 사실상 순차 실행이 된다.

---

# 4.4.2 Windows Threads

Windows Thread API는 Windows 운영체제에서 스레드를 생성하고 관리하는 기능을 제공한다.

교재는 Pthreads와 동일하게 1부터 N까지의 합을 구하는 예제를 Windows API로 구현한다.

---

## 기본 헤더와 자료형

```c
#include <windows.h>
```

교재 예제에서 사용되는 주요 자료형은 다음과 같다.

| 자료형         | 의미                          |
| -------------- | ----------------------------- |
| `DWORD`        | 부호 없는 32비트 정수         |
| `HANDLE`       | 커널 객체를 참조하는 핸들     |
| `LPVOID`       | `void *`에 해당하는 포인터    |
| `DWORD WINAPI` | Windows 스레드 실행 함수 형식 |

---

## 스레드 함수

Windows의 스레드 실행 함수는 다음 형태로 작성할 수 있다.

```c
DWORD WINAPI Summation(LPVOID Param)
{
    DWORD Upper = *(DWORD *)Param;

    for (DWORD i = 1; i <= Upper; i++) {
        Sum += i;
    }

    return 0;
}
```

`Param`은 `LPVOID` 타입으로 전달되므로 실제 사용 전에 적절한 자료형으로 변환해야 한다.

---

## `CreateThread()`

Windows에서는 `CreateThread()`로 새 스레드를 생성한다.

```c
ThreadHandle = CreateThread(
    NULL,
    0,
    Summation,
    &Param,
    0,
    &ThreadId
);
```

매개변수의 의미는 다음과 같다.

| 순서 | 매개변수    | 의미                      |
| ---: | ----------- | ------------------------- |
|    1 | `NULL`      | 기본 보안 속성            |
|    2 | `0`         | 기본 스택 크기            |
|    3 | `Summation` | 실행할 스레드 함수        |
|    4 | `&Param`    | 스레드 함수에 전달할 인자 |
|    5 | `0`         | 기본 생성 플래그          |
|    6 | `&ThreadId` | 생성된 스레드 ID 저장     |

기본 생성 플래그를 사용하면 스레드는 생성 후 바로 CPU 스케줄링 대상이 된다.

특정 플래그를 사용하면 스레드를 일시 중지된 상태로 만들 수도 있다.

---

## HANDLE과 Thread ID의 차이

`ThreadId`는 스레드를 식별하는 숫자다.

`ThreadHandle`은 운영체제의 스레드 객체를 조작하기 위한 참조다.

```text
ThreadId
→ 스레드를 구분하는 식별자

ThreadHandle
→ 대기, 상태 확인, 닫기 등에 사용하는 커널 객체 참조
```

---

## `WaitForSingleObject()`

부모 스레드가 하나의 자식 스레드 종료를 기다릴 때 사용한다.

```c
WaitForSingleObject(ThreadHandle, INFINITE);
```

- 첫 번째 인자: 기다릴 객체의 핸들
- 두 번째 인자: 대기 시간
- `INFINITE`: 객체가 신호 상태가 될 때까지 무한 대기

스레드 객체는 해당 스레드가 종료되면 신호 상태가 된다.

```text
Child Thread 실행 중
→ Thread Object: non-signaled

Child Thread 종료
→ Thread Object: signaled

Parent 대기 해제
```

Pthreads의 `pthread_join()`과 비슷한 역할을 한다.

---

## `CloseHandle()`

스레드 사용이 끝난 뒤 핸들을 닫는다.

```c
CloseHandle(ThreadHandle);
```

스레드가 종료됐다고 해서 핸들이 자동으로 해제되는 것은 아니다.

핸들을 닫지 않으면 커널 객체에 대한 참조가 남아 자원 누수가 발생할 수 있다.

---

## 여러 스레드를 기다리는 경우

여러 스레드의 종료를 기다릴 때는 `WaitForMultipleObjects()`를 사용한다.

```c
WaitForMultipleObjects(
    N,
    THandles,
    TRUE,
    INFINITE
);
```

교재에서 설명하는 네 매개변수는 다음과 같다.

1. 기다릴 객체 수
2. 객체 핸들 배열
3. 모든 객체를 기다릴지 여부
4. 타임아웃 시간

```text
TRUE
→ 모든 스레드가 끝날 때까지 대기

FALSE
→ 하나라도 끝나면 대기 해제
```

---

# 4.4.3 Java Threads

## Java에서 스레드의 위치

스레드는 Java 프로그램 실행의 기본 모델이다.

단순히 `main()` 메서드만 가진 Java 프로그램도 JVM 내부에서 최소 하나의 스레드로 실행된다.

Java 스레드는 JVM이 존재하는 여러 운영체제에서 사용할 수 있다.

- Windows
- Linux
- macOS
- Android

교재는 Java에서 명시적으로 스레드를 만드는 두 가지 방법을 설명한다.

---

## 방법 1: Thread 클래스 상속

`Thread` 클래스를 상속하고 `run()` 메서드를 재정의한다.

```java
class Worker extends Thread {
    @Override
    public void run() {
        System.out.println("I am a thread.");
    }
}
```

생성과 실행은 다음과 같다.

```java
Worker worker = new Worker();
worker.start();
```

---

## 방법 2: Runnable 인터페이스 구현

교재는 `Runnable`을 구현하는 방식을 더 일반적인 방법으로 설명한다.

```java
class Task implements Runnable {
    @Override
    public void run() {
        System.out.println("I am a thread.");
    }
}
```

`Runnable`은 다음 단일 추상 메서드를 정의한다.

```java
public void run();
```

`run()` 안의 코드가 별도 스레드에서 실행할 작업이다.

스레드를 생성할 때 `Runnable` 객체를 `Thread` 생성자에 전달한다.

```java
Thread worker = new Thread(new Task());
worker.start();
```

---

## Runnable을 사용하는 이유

Java는 클래스 다중 상속을 지원하지 않는다.

`Thread` 클래스를 상속하면 다른 클래스를 상속할 수 없게 된다.

```java
class Task extends SomeClass implements Runnable {
    // 다른 클래스 상속 가능
}
```

또한 `Runnable`은 **작업**과 **실행 스레드**를 분리한다.

```text
Runnable
→ 무엇을 실행할 것인가

Thread
→ 어떤 실행 흐름에서 실행할 것인가
```

같은 `Runnable` 작업을 여러 스레드에 전달할 수도 있다.

---

## `start()`와 `run()`의 차이

새로운 스레드를 실행하려면 반드시 `start()`를 호출해야 한다.

```java
worker.start();
```

`start()`는 다음 두 가지 작업을 수행한다.

1. JVM에서 새 스레드를 위한 메모리와 실행 상태를 초기화한다.
2. 새 스레드를 실행 가능 상태로 만들고, 해당 스레드에서 `run()`을 호출한다.

```text
start()
    ↓
새 스레드 생성
    ↓
JVM 스케줄링 대상
    ↓
새 스레드에서 run() 실행
```

반면 다음처럼 `run()`을 직접 호출하면 새 스레드가 만들어지지 않는다.

```java
worker.run();
```

이 경우 현재 스레드가 일반 메서드처럼 `run()`을 실행한다.

```text
main thread
    ↓
worker.run()
    ↓
main thread에서 그대로 실행
```

따라서 다음 두 코드는 완전히 다르다.

```java
worker.start(); // 새 스레드
worker.run();   // 현재 스레드에서 일반 함수 호출
```

---

## Java Lambda Expression

Java 8부터 Lambda Expression을 사용해 `Runnable` 작업을 간단하게 표현할 수 있다.

```java
Runnable task = () -> {
    System.out.println("I am a thread.");
};

Thread worker = new Thread(task);
worker.start();
```

별도의 `Task` 클래스를 만들지 않아도 되므로 간결하다.

더 줄이면 다음처럼 작성할 수도 있다.

```java
Thread worker = new Thread(() -> {
    System.out.println("I am a thread.");
});

worker.start();
```

## `join()`

부모 스레드가 자식 스레드 종료를 기다릴 때 `join()`을 사용한다.

```java
try {
    worker.join();
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
}
```

동작은 다음과 같다.

```text
main thread
    ↓ worker.start()

worker thread 실행

main thread
    ↓ worker.join()
대기

worker thread 종료
    ↓
main thread 재개
```

Pthreads의 `pthread_join()` 및 Windows의 `WaitForSingleObject()`와 같은 목적이다.

---

## InterruptedException

`join()`으로 대기 중인 스레드는 다른 스레드에 의해 interrupt될 수 있다.

따라서 Java에서는 `InterruptedException`을 처리해야 한다.

```java
try {
    worker.join();
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();
}
```

교재 예제는 단순화를 위해 예외를 무시하지만, 실제 코드에서는 interrupt 상태를 복구하거나 적절한 종료 처리를 하는 것이 좋다.

> **추가 설명:** `Thread.currentThread().interrupt()`는 catch 과정에서 제거된 interrupt 상태를 다시 설정하는 일반적인 처리 방식이다.

## 여러 스레드를 기다리는 경우

Pthreads와 마찬가지로 Thread 배열을 만들고 반복문에서 `join()`할 수 있다.

```java
Thread[] workers = new Thread[N];

for (int i = 0; i < N; i++) {
    workers[i] = new Thread(new Task());
    workers[i].start();
}

for (int i = 0; i < N; i++) {
    try {
        workers[i].join();
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}
```

모든 스레드를 먼저 시작한 뒤 별도의 반복문에서 기다려야 여러 스레드가 함께 실행될 수 있다.

# 4.3~4.4 핵심 요약

## 사용자 스레드와 커널 스레드

```text
사용자 스레드
→ 응용 프로그램과 스레드 라이브러리가 다루는 실행 흐름

커널 스레드
→ 운영체제가 직접 스케줄링하는 실행 단위
```

사용자 스레드는 커널 스레드와 매핑되어 CPU에서 실행된다.

---

## 멀티스레딩 모델

### Many-to-One

```text
여러 User Thread → 하나의 Kernel Thread
```

생성과 전환은 빠르지만 하나의 Blocking 호출이 전체를 막고 멀티코어 병렬 실행이 불가능하다.

### One-to-One

```text
하나의 User Thread → 하나의 Kernel Thread
```

Blocking의 영향이 해당 스레드로 제한되고 멀티코어 병렬 실행이 가능하지만 커널 스레드 관리 비용이 발생한다.

### Many-to-Many

```text
여러 User Thread → 여러 Kernel Thread
```

사용자 스레드 수를 유연하게 유지하면서 Blocking과 멀티코어 문제를 해결하지만 구현이 복잡하다.

### Two-Level

Many-to-Many를 기반으로 특정 사용자 스레드를 특정 커널 스레드에 고정할 수 있다.

# 면접 포인트

### Q1. 사용자 스레드와 커널 스레드의 차이는 무엇인가?

사용자 스레드는 사용자 영역의 스레드 라이브러리가 생성하고 관리하는 논리적 실행 흐름이고, 커널 스레드는 운영체제가 직접 인식하고 CPU에 스케줄링하는 실행 단위다. 사용자 스레드가 실행되려면 일반적으로 커널 스레드와의 매핑이 필요하다.

### Q2. Many-to-One 모델에서 한 스레드의 Blocking 호출이 왜 전체 프로세스를 막는가?

모든 사용자 스레드가 하나의 커널 스레드를 공유하기 때문이다. 시스템 콜로 해당 커널 스레드가 Block되면 다른 사용자 스레드를 실행할 커널 스레드가 남지 않는다.

### Q3. One-to-One이면 무조건 병렬 실행되는가?

아니다. One-to-One은 각 사용자 스레드를 독립적으로 스케줄링할 수 있게 할 뿐이다. 실제 병렬 실행을 위해서는 여러 코어와 동시에 실행 가능한 여러 스레드가 필요하다. 싱글 코어에서는 커널 스레드들이 번갈아 실행된다.

### Q4. 현대 운영체제가 One-to-One 모델을 주로 사용하는 이유는 무엇인가?

구조가 비교적 단순하면서 하나의 스레드가 Block되어도 다른 스레드가 실행될 수 있고, 멀티코어 병렬성도 활용할 수 있기 때문이다. 현대 시스템에서는 커널 스레드 생성과 관리 능력이 향상되어 과거의 스레드 수 제한 문제도 완화되었다.

### Q5. `start()`와 `run()`의 차이는 무엇인가?

Java에서 `start()`는 새로운 스레드를 생성하고 그 스레드에서 `run()`을 실행한다. `run()`을 직접 호출하면 새로운 스레드가 생성되지 않고 현재 스레드에서 일반 메서드처럼 실행된다.

### Q6. `join()`은 어떤 역할을 하는가?

호출한 스레드가 대상 스레드의 종료를 기다리게 한다. 자식 스레드의 계산 결과가 필요하거나 여러 병렬 작업이 모두 완료된 뒤 다음 단계로 진행해야 할 때 사용한다.

### Q7. Windows에서 Thread ID와 HANDLE은 어떻게 다른가?

Thread ID는 스레드를 구분하는 숫자 식별자다. HANDLE은 운영체제의 스레드 객체를 조작하고 대기하거나 자원을 해제하는 데 사용하는 참조다. 사용이 끝난 HANDLE은 `CloseHandle()`로 닫아야 한다.
