# Chapter 4. Threads & Concurrency

# 4.1 Overview

## 프로세스만으로는 부족한 이유

3장에서 프로세스(Process)를 배웠다.

프로세스는 실행 중인 프로그램이며

- 코드(Code)
- 데이터(Data)
- Heap
- Stack
- 열린 파일
- PCB

등을 가진다.

하지만 현실의 프로그램은 하나의 작업만 수행하지 않는다.

예를 들어 웹 브라우저는

- 화면 출력
- 사용자 입력
- 네트워크 통신
- 파일 다운로드

를 동시에 수행한다.

만약 이것을 프로세스로만 만든다면

```
브라우저
 ├── 프로세스1 (UI)
 ├── 프로세스2 (다운로드)
 ├── 프로세스3 (렌더링)
```

각 프로세스마다

- 메모리
- PCB
- 열린 파일

등을 전부 따로 가져야 한다.

→ 메모리 낭비
→ Context Switching 비용 증가

그래서 등장한 것이 **Thread**이다. fileciteturn1file3

---

## Thread란?

> 프로세스 내부에서 실행되는 실행 흐름(Execution Flow)

하나의 프로세스 안에 여러 개 존재할 수 있다.

예시

```
Chrome Process

 ├── Thread 1 (UI)
 ├── Thread 2 (Rendering)
 ├── Thread 3 (Download)
 └── Thread 4 (JavaScript)
```

---

## Thread가 공유하는 것

같은 프로세스이므로

공유한다.

- Code
- Data
- Heap
- 열린 파일
- Signal

---

## Thread마다 따로 가지는 것

각 Thread는 독립적으로 실행되므로

각자 가진다.

- Program Counter
- Register
- Stack

```
Process

 Code
 Data
 Heap
 Files
  │
  ├── Thread1
  │      PC
  │      Register
  │      Stack
  │
  ├── Thread2
  │      PC
  │      Register
  │      Stack
```

Stack을 따로 가지는 이유는

각 함수 호출(Call Stack)이 달라야 하기 때문이다.

---

## Thread를 사용하는 장점

### 1. 응답성(Response)

예)

Word

Spell Check 수행 중에도

사용자는 계속 입력 가능

---

### 2. 자원 공유(Resource Sharing)

프로세스처럼

메모리를 복사할 필요가 없다.

이미 같은 주소 공간을 사용한다.

---

### 3. 경제성(Economy)

Process 생성

↓

PCB 생성

↓

메모리 생성

↓

페이지 테이블 생성

↓

Context Switch

비용이 크다.

Thread 생성은

Stack만 하나 만들면 되는 수준이다.

훨씬 가볍다.

---

### 4. Scalability

멀티코어에서

여러 Thread를

동시에 실행 가능하다.

# 4.2 Multicore Programming

## 왜 Multicore가 등장했는가?

예전에는 CPU 성능을 높이는 방법이

Clock Speed 증가였다.

```
1GHz
↓

2GHz
↓

3GHz
```

하지만

- 발열
- 전력 소비

문제로 더 이상 증가시키기 어려워졌다.

그래서

```
Core 1
Core 2
Core 3
Core 4
```

처럼 여러 개의 CPU Core를 하나의 CPU 안에 넣기 시작했다.

---

## 단순히 Core만 늘리면 빨라질까?

아니다.

프로그램이

```
Thread 하나
```

뿐이라면

```
Core1 사용

Core2 놀고 있음

Core3 놀고 있음
```

이 된다.

따라서

프로그램도

여러 작업으로 나누어야 한다.

---

## 병렬 실행(Parallelism)

여러 Core에서

동시에 실행

```
Core1
Thread A

Core2
Thread B
```

실제로 같은 시간에 수행된다.

---

## 동시성(Concurrency)

동시에 실행되는 것처럼 보이는 것

```
A

↓

B

↓

A

↓

B
```

CPU가 빠르게 번갈아 수행한다.

---

### 차이

Concurrency

```
1 Core

A
B
A
B
```

Parallelism

```
Core1 A

Core2 B
```

---

## Parallelism의 종류

### Data Parallelism

같은 작업

다른 데이터

예)

배열 합

```
Thread1

1~500

Thread2

501~1000
```

---

### Task Parallelism

작업 자체가 다르다.

```

Download

Thread2

Render

Thread3

```

## Mapping 방식

---

### ① Many-to-One

```
User Thread

A

B

C

↓

Kernel Thread 하나
```

장점

- 구현 쉬움
- 생성 빠름

단점

모두 멈춘다.

---

### ② One-to-One

```
User A → Kernel A

User B → Kernel B

User C → Kernel C
```

장점

- 진짜 병렬 수행
- Blocking 영향 없음

단점

Kernel Thread 생성 비용 증가

현재

Windows

Linux

macOS

대부분 사용한다.

---

### ③ Many-to-Many

```
User

A

B

C

D

↓

Kernel

1

2
```

필요한 만큼만 Kernel Thread 사용

장점

- 병렬성
- 비용 절감

단점

구현이 매우 복잡

---

### Two-Level Model

Many-to-Many의 확장

필요하면

특정 User Thread를

특정 Kernel Thread에

고정(Bound)할 수 있다.

# 4.4 Thread Libraries

## Thread Library란?

Thread 생성과 관리를 위한 API이다.

프로그래머는

운영체제 내부를 직접 다루지 않고

라이브러리를 사용한다.

---

## 대표적인 Thread Library

### 1. POSIX Threads (Pthreads)

Linux

UNIX

가장 표준적인 API

예)

```c
pthread_create();
pthread_join();
pthread_exit();
```

---

### 2. Windows Threads

Windows API 제공

```cpp
CreateThread()
```

---

### 3. Java Threads

Java Virtual Machine이 관리

```java
Thread t = new Thread();
t.start();
```

또는

```java
ExecutorService
```

사용을 권장한다.

---

## Thread 생성 방식

### User Level

```
Application

↓

Thread Library

↓

User Thread
```

커널 호출이 거의 없어 빠르다.

---

### Kernel Level

```
Application

↓

System Call

↓

```

운영체제가 직접 관리한다.

---

## Thread 종료

Thread 종료 시

- Register 제거
- Program Counter 제거

공유 중인

Code

Heap

Data

는 다른 Thread가 사용 중이라면 제거되지 않는다.

# 핵심 요약

- Thread는 프로세스 내부의 실행 단위이다.
- Thread는 Code, Data, Heap을 공유한다.
- Stack, Register, PC는 Thread마다 독립적이다.
- 멀티코어를 활용하려면 프로그램도 여러 Thread로 작성되어야 한다.
- Parallelism은 실제 동시 실행, Concurrency는 번갈아 실행하여 동시에 실행되는 것처럼 보이는 것이다.
- Thread 매핑 방식에는 Many-to-One, One-to-One, Many-to-Many가 있다.
- 현대 운영체제는 대부분 **One-to-One 모델**을 사용한다.
- Thread Library는 Thread 생성과 관리를 위한 API(Pthreads, Windows API, Java Threads)를 제공한다.

# 면접 포인트

### Q1. Process와 Thread의 가장 큰 차이는?

- Process는 독립적인 주소 공간을 가진다.
- Thread는 같은 Process 내부에서 Code, Data, Heap을 공유하는 실행 단위이다.

---

### Q2. Thread마다 Stack이 필요한 이유는?

함수 호출 정보(Call Stack), 지역 변수, 반환 주소는 각 Thread마다 달라야 하기 때문이다.

---

### Q3. Concurrency와 Parallelism의 차이는?

- **Concurrency**: 여러 작업을 번갈아 실행하여 동시에 실행되는 것처럼 보이게 하는 개념.
- **Parallelism**: 여러 코어에서 여러 작업을 실제로 동시에 실행하는 개념.

---

### Q4. 현대 운영체제는 어떤 Thread 모델을 사용하는가?

대부분 **One-to-One 모델**을 사용한다. 각 사용자 스레드가 하나의 커널 스레드와 연결되어 멀티코어를 효율적으로 활용할 수 있기 때문이다.
